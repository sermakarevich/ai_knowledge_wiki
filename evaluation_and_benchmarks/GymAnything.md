# Gym-Anything: Turn any Software into an Agent Environment

**Paper:** [Gym-Anything: Turn any Software into an Agent Environment (Aggarwal, Neubig, Welleck, 2025)](https://arxiv.org/abs/2604.06126)

## Human Readable TL;DR

Imagine you wanted to teach a robot assistant to use every piece of software on your computer -- spreadsheets, medical imaging tools, accounting apps, design programs. Right now, researchers have to manually set up each program one by one, which takes weeks per app. This paper builds a system that automatically installs, configures, and creates practice exercises for 200 different software applications, producing over 10,000 training tasks. It is like building an automated driving school that can instantly create courses for any vehicle, rather than hand-building each track. Even the best AI agents today can only pass about 23% of the resulting tests, showing how far we still have to go.

## TL;DR

Gym-Anything is a framework that automates the creation of interactive computer-use agent (CUA) environments by using a multi-agent creation-audit pipeline. It produces CUA-World -- 10,000+ long-horizon tasks across 200 GDP-grounded software applications spanning all 22 U.S. occupation groups. Frontier models achieve ~50% average score but only ~23% pass rate, and a propose-and-amplify strategy enables scalable task generation with checklist-based VLM verification.

---

## Problem & Motivation

Computer-use agents (CUAs) that interact with GUIs are tested on short-horizon tasks within a handful of consumer apps -- changing wallpapers, filling web forms. This does not reflect professional workflows that involve hundreds of steps across specialized software. The bottleneck is environment creation: installing, configuring with realistic data, designing tasks, and building verifiers takes weeks of expert effort per application. This manual cost limits benchmark diversity, produces unfaithful evaluation, and starves training pipelines of long-horizon supervision signal. Gym-Anything targets this scalability gap, grounding software selection in U.S. GDP data to ensure economic relevance.

---

## Main Original Ideas

1. **GDP-Grounded Software Selection** -- Uses O*NET occupation data crossed with BLS/BEA economic statistics to estimate per-software GDP contribution, then selects 200 applications across five tiers balancing economic importance, domain coverage, and diversity across all 22 Standard Occupational Classification groups.

2. **Multi-Agent Creation-Audit Loop** -- Frames environment construction as a multi-agent task: a Creation Agent (Claude Opus) installs and configures software with real-world data, while an independent Audit Agent adversarially verifies the setup against a quality checklist, reducing self-confirmation bias. A shared memory system accumulates cross-environment learnings.

3. **Propose-and-Amplify Task Generation** -- An expensive agentic model creates high-quality seed tasks by actively running the software; a cheaper non-agentic model amplifies these into thousands of additional tasks with semantic diversity filtering. This achieves 88.9% setup success rate vs. 55.2% without seeds.

4. **Checklist-Based VLM Verification with Integrity Checks** -- Automatically extracts privileged ground-truth from setup scripts, generates weighted subtask checklists for granular partial-credit scoring, and applies integrity checks to catch workflow bypasses (e.g., editing config files instead of using the GUI).

5. **Test-Time Auditing (TTA)** -- An independent VLM reviews completed agent trajectories and provides feedback on uncompleted subtasks, prompting the agent to continue rather than prematurely stop -- improving pass rates on long-horizon tasks.

6. **CUA-World-Long Benchmark** -- 200 extremely long-horizon tasks (one per software, often 500+ steps) generated by analyzing agent failure patterns, exceeding existing benchmarks in complexity and providing a stress test for frontier models.

## Key Findings

| **Gemini 3 Flash** | CUA-World-Test | **50.1** | **22.6%** | Best overall on test split |
| Kimi-K 2.5 | CUA-World-Test | 37.1 | 12.8% | |
| Qwen3-VL-2B | CUA-World-Test | 5.8 | 1.6% | Baseline small model |
| Qwen3-VL-2B (distilled) | CUA-World-Test | 13.3 | 4.4% | Beats 4B model (3.9%) |
| **Gemini 3 Flash** | CUA-World-Long ($5 cap) | 36.2 | 7.5% | 500-step limit |
| Gemini 3 Flash | CUA-World-Long (uncapped) | -- | 11.5% | 2000-step limit |
| Gemini 3 Flash + TTA | CUA-World-Long (uncapped) | -- | **14.0%** | +2.5pp from auditing |
| GPT-5.4 | CUA-World-Long (uncapped) | -- | **27.5%** | Best on long-horizon |

- Distillation shows log-linear scaling: ~3.5-point average score gain per doubling of training data.
- In-distribution gains from distillation recover 65--87% of potential improvement; out-of-distribution recovers only 22--27%, highlighting the need for diverse software coverage.
- Failed trajectories exhibit 78% retry loops vs. 39% in successful ones; verification checks correlate with success (91% of passes vs. 70% of failures).
- The checklist VLM verifier achieves 93.3% human agreement, outperforming direct VLM (81.7%) and programmatic verifiers (43.3%).
- Cross-model auditing catches an average of 2.1 additional issues per environment vs. self-auditing.

## Suggestions & Future Directions

1. **Broader software coverage** -- The current 200 applications cover only a fraction of the ~3,400 sandboxable candidates identified; scaling to thousands would further improve agent generalization.
2. **Closing the OOD generalization gap** -- Out-of-distribution transfer remains weak (22--27% recovery), suggesting the need for training strategies that improve cross-software generalization beyond simple trajectory distillation.
3. **Long-horizon reasoning** -- Even with 2,000 steps and uncapped budgets, frontier models achieve only ~28% pass rate on CUA-World-Long, pointing to fundamental limitations in long-term planning and execution.
4. **Richer verification** -- While the checklist-based VLM verifier outperforms alternatives, the 6.7% disagreement with humans leaves room for more precise automated verification, especially for nuanced professional workflows.
5. **Test-time scaling** -- TTA provides modest gains (+2.5pp); more sophisticated test-time compute strategies (e.g., search-based planning, multi-round auditing) could yield larger improvements.
6. **Economic impact measurement** -- The GDP-grounded framework opens the door to directly measuring how agent improvements translate to economic value across occupations.
