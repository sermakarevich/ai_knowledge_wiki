# Orchestrator Core: Town, Rig, Crew, Polecat, Mayor

**In one sentence:** A Town (workspace directory identified by `mayor/town.json`) contains Rigs (one managed repository each, provisioned by `rig.Manager.AddRig`), and each rig hosts a persistent Mayor-adjacent identity layer, user-managed Crew clones, and Witness-managed Polecats whose persistent beads identity is kept separate from their ephemeral tmux sessions and per-assignment git worktrees.

## Key points
- A Town is a workspace root (`~/gt/`) detected by walking up to the outermost `mayor/town.json` marker in `workspace.Find` (`internal/workspace/find.go:33`), with town identity in `TownConfig` (`internal/config/types.go:17`) and behavior in `TownSettings` (`internal/config/types.go:42`).
- A Rig is one managed git repository plus its agents, represented by the `Rig` struct (`internal/rig/types.go:9`) and created by `Manager.AddRig` (`internal/rig/manager.go:318`), which clones a shared bare repo (`.repo.git`), a mayor clone (`mayor/rig`), a refinery worktree (`refinery/rig`), and scaffolds `crew/`, `witness/`, `polecats/` directories.
- A Polecat is a Witness-managed worker with persistent identity but an ephemeral session: the `Polecat` struct (`internal/polecat/types.go:87`) carries seven lifecycle states (`internal/polecat/types.go:31`), while the live tmux session is retired on clean completion and the branch/MR evidence is left for refinery/cleanup (`docs/concepts/polecat-lifecycle.md:51`).
- Polecat identity is stored in the beads database (agent bead ID `<prefix>-<rig>-polecat-<name>` from `agentBeadID`, `internal/polecat/manager.go:403`, plus assignee `rig/polecats/name`, `internal/polecat/manager.go:394`); there is no per-polecat `state.json` — `loadFromBeads` derives state at query time from hooked/assigned beads cross-checked against tmux liveness (`internal/polecat/manager.go:2731`).
- Polecat spawn is `AllocateAndAdd` (`internal/polecat/manager.go:662`), which holds the pool flock across name allocation plus directory creation to close the GH#2215 TOCTOU race, then builds a git worktree on a generated branch `polecat/<name>/<issue>+<suffix>` (`internal/polecat/branch_name.go:22`).
- A Crew worker is a persistent, user-managed clone defined by `CrewWorker` (`internal/crew/types.go:8`) and created by `crew.Manager.Add` via full `git clone` (`internal/crew/manager.go:182`), with its own `state.json` persisted by atomic write (`internal/crew/manager.go:521`).
- The Mayor is a singleton persistent coordinator (one per machine, tmux session `hq-mayor` from `MayorSessionName`, `internal/session/names.go:16`) managed by `mayor.Manager` (`internal/mayor/manager.go:48`), with tmux and ACP modes combined in `CombinedStatus` (`internal/mayor/manager.go:53`).
- Concurrency between agents is file locking, not in-process mutexes: per-polecat `polecat-<name>.lock` and pool-wide `polecat-pool.lock` under `<rig>/.runtime/locks/` (`internal/polecat/manager.go:218`), per-crew `crew-<name>.lock` (`internal/crew/manager.go:168`), Boot's flock on `.boot-running` (`internal/boot/boot.go:89`), and Dolt optimistic-lock retry with backoff (`internal/polecat/manager.go:55`).

## Town: workspace root and identity

A Town is the workspace directory (for example `~/gt/`) holding infrastructure directories (`mayor/`, `deacon/`) plus one subdirectory per rig (`docs/overview.md:158`). Detection is marker-based: `PrimaryMarker = "mayor/town.json"` (`internal/workspace/find.go:20`), with `Find` walking from the start directory up to the filesystem root and keeping the outermost primary match so nested rig worktrees still resolve to the real town root (`internal/workspace/find.go:33`). `FindFromCwdOrError` adds a `GT_TOWN_ROOT`/`GT_ROOT` environment fallback (`internal/workspace/find.go:90`), and `FindFromCwdWithFallback` survives even a deleted cwd (for example a polecat worktree nuked by the Witness) via the same env fallback (`internal/workspace/find.go:119`).

Town identity and behavior are split across three structs. `TownConfig` (the `mayor/town.json` identity: type, version, name, owner, public name) is at `internal/config/types.go:17`. `MayorConfig` (town-level behavioral config in `mayor/config.json`, including theme, daemon, deacon blocks) is at `internal/config/types.go:28`. `TownSettings` (`settings/config.json`: default agent, custom agents, per-role agent map, crew-agent map, scheduler, polecat target-clean policy, operational thresholds, disabled patrols) is at `internal/config/types.go:42`, constructed with defaults by `NewTownSettings` (`internal/config/types.go:130`). The rig registry is `RigsConfig` (`mayor/rigs.json`: version plus a map of `RigEntry`) at `internal/config/types.go:614`, where each `RigEntry` holds git URLs, local-repo reference, added timestamp, and beads prefix config (`internal/config/types.go:620`).

```
town-root detection (internal/workspace/find.go:33)
│
▼
cwd ──► walk parents ──► outermost dir containing mayor/town.json ──► town root
                              │ (fallback: $GT_TOWN_ROOT / $GT_ROOT)
                              ▼
                    mayor/town.json (TownConfig) + mayor/rigs.json (RigsConfig)
```

## Rig: definition, discovery, provisioning

A Rig is a project container: it wraps one git repository and manages that repo's agents (`README.md:56`). The runtime view is the `Rig` struct — name, absolute path, fetch/push URLs, optional local reference repo, rig-level beads config, polecat/crew name lists, and witness/refinery/mayor presence flags (`internal/rig/types.go:9`). The standard agent directories inside a rig are `polecats`, `crew`, `refinery/rig`, `witness`, `mayor/rig` (`internal/rig/types.go:48`). Per-rig identity lives in `rig/config.json` as `RigConfig` (type, version, name, URLs, creation time, beads prefix) at `internal/config/types.go:650`; per-rig behavior lives in `settings/config.json` as `RigSettings` (merge queue, theme, namepool, crew startup, agent/role-agent overrides) at `internal/config/types.go:670`.

Discovery is registry-driven. `rig.Manager` holds the town root, the loaded `RigsConfig`, and a git helper (`internal/rig/manager.go:125`). `DiscoverRigs` iterates the registry and calls `loadRig` per entry, logging failures to stderr and returning partial results sorted by name (`internal/rig/manager.go:142`). `GetRig`/`RigExists` are single-entry lookup and membership test (`internal/rig/manager.go:162`, `internal/rig/manager.go:172`). `loadRig` stats the rig directory, copies URLs from the registry entry, then scans the `polecats/` directory for live polecat names, skipping dotfiles (`internal/rig/manager.go:195`, scan at `internal/rig/manager.go:217`).

Provisioning has two paths: `AddRig` (fresh rig from a remote URL, `internal/rig/manager.go:318`) and `RegisterRig` (adopt an existing on-disk directory, `internal/rig/manager.go:1632`). `AddRig` proceeds in this order:

1. Validate: reject registered names (`internal/rig/manager.go:319`); reject names containing `-`, `.`, space, or path separators because agent IDs use hyphens as delimiters (`internal/rig/manager.go:325`); reject reserved infrastructure names such as `hq` (`internal/rig/manager.go:334`); fail fast if the Dolt server is not running (`internal/rig/manager.go:342`).
2. Derive the beads prefix (explicit `--prefix` or `deriveBeadsPrefix` from the rig name) and check prefix availability town-wide before any expensive clone (`internal/rig/manager.go:362`, `internal/rig/manager.go:367`).
3. Create the rig directory and stamp ownership so a failed-rollback path cannot delete a later successful re-add (`internal/rig/manager.go:377`, stamp at `internal/rig/manager.go:383`); a deferred `removeRigPathIfOwned` cleanup runs only if the same invocation still owns the path (`internal/rig/manager.go:394`).
4. Write `rig/config.json` (`internal/rig/manager.go:403` via `saveRigConfig` at `internal/rig/manager.go:1033`), then clone the shared bare repo `.repo.git` (partial-clone and `--reference` variants supported) which is the source of truth polecats and refinery share (`internal/rig/manager.go:424`, clone selector at `internal/rig/manager.go:428`).
5. Detect or accept the default branch and re-save config (`internal/rig/manager.go:499`), then create the mayor clone at `mayor/rig` with `--reference` against the bare repo so objects are borrowed, not re-downloaded (`internal/rig/manager.go:533`, clone at `internal/rig/manager.go:545`).
6. Create the refinery worktree at `refinery/rig` from the bare repo on the default branch so refinery sees polecat branches (`internal/rig/manager.go:750`); set up its beads redirect (`internal/rig/manager.go:763`) and copy overlay files (`internal/rig/manager.go:768` via `CopyOverlay` at `internal/rig/overlay.go:43`).
7. Scaffold `crew/` with a README (`internal/rig/manager.go:778`), `witness/` with no clone (`internal/rig/manager.go:805`), and `polecats/` with agent settings scaffold (`internal/rig/manager.go:816`).
8. Append the prefix route to town `routes.jsonl` before creating agent beads, because `initAgentBeads` resolves routing targets through the route table (`internal/rig/manager.go:847`); create `settings/` (`internal/rig/manager.go:863`); create witness/refinery agent beads (`internal/rig/manager.go:876` via `initAgentBeads` at `internal/rig/manager.go:1270`); seed patrol molecules (`internal/rig/manager.go:882`); create plugin directories (`internal/rig/manager.go:888`).

`Rig.BeadsPath()` always returns the rig root: `rig/.beads/` is either a local beads database or a redirect file pointing at `mayor/rig/.beads`, so callers never write into the user's mayor clone (`internal/rig/types.go:86`). `DefaultBranch()` reads `rig/config.json` and falls back to `"main"` (`internal/rig/types.go:92`).

## Polecat: spawn, track, retire

A Polecat is a worker agent with persistent identity but an ephemeral session, spawned for a task and retired (session killed) on clean completion while identity and work history persist (`README.md:64`, `docs/concepts/polecat-lifecycle.md:8`). The `Polecat` struct carries name, rig, lifecycle `State`, clone path, branch, assigned issue, and timestamps (`internal/polecat/types.go:87`). The seven states are `working`, `idle`, `done`, `review-needed`, `stuck`, `stalled`, `zombie` (`internal/polecat/types.go:31`): `working` means session active on assigned work, `idle` means available capacity with no hook/session/cleanup state, `done` means `gt done` ran and the session should already have exited (a lingering `done` is a zombie), `stalled`/`zombie` are externally detected conditions from cross-checking tmux liveness against beads state (`internal/polecat/types.go:6`). Cleanup safety is a separate axis, `CleanupStatus` (`clean`, `has_uncommitted`, `has_stash`, `has_unpushed`, `unknown`) at `internal/polecat/types.go:131`, with `IsSafe`, `RequiresRecovery`, and `CanForceRemove` predicates (`internal/polecat/types.go:152`, `internal/polecat/types.go:160`, `internal/polecat/types.go:171`).

Identity is persistent and lives in beads, not on disk per-polecat. The beads assignee string is `<rig>/polecats/<name>` (`internal/polecat/manager.go:394` via `assigneeID`), and the agent bead ID is `<prefix>-<rig>-polecat-<name>` with the prefix resolved from town `routes.jsonl` (`internal/polecat/manager.go:403` via `agentBeadID`). The on-disk sandbox is `polecats/<name>/` as the home directory (`internal/polecat/manager.go:485`) containing the git worktree at `polecats/<name>/<rigname>/` for new polecats, with backward-compatible fallback to the old flat `polecats/<name>/` worktree (`internal/polecat/manager.go:500`). The code comment at the spawn entry point is explicit: polecat state is derived from the beads assignee field, not from `state.json` (`internal/polecat/manager.go:649`).

Spawning is `AllocateAndAdd` (`internal/polecat/manager.go:662`): hold the pool flock, reconcile the pool, `NamePool.Allocate` a name, save pool state, acquire the per-polecat flock while still holding the pool flock, create `polecats/<name>/`, kill any lingering tmux session for that name, release the pool lock (the new directory now blocks re-allocation during reconcile), then run `addWithOptionsLocked` under the polecat lock only (`internal/polecat/manager.go:684`). That inner function checks disk space, computes the branch via `buildBranchName` (`internal/polecat/manager.go:560`), fetches origin, attaches the worktree with `WorktreeAddExistingForce` for `--resume` or `WorktreeAddFromRef` for a fresh branch, installs the agent bead with retry, and rolls back (reset agent bead, remove worktree, remove directory, release name) on error (`internal/polecat/manager.go:725`). Branch names are canonical: `polecat/<name>/<issue>+<suffix>` for generated branches, `polecat/<name>-<suffix>` without an issue, with the legacy `@` separator still parsed (`internal/polecat/branch_name.go:22`, parser at `internal/polecat/branch_name.go:30`). Session startup is `SessionManager.Start` (`internal/polecat/session_manager.go:320`); the tmux session name is `<beads-prefix>-<polecat-name>`, for example `gt-toast` (`internal/session/names.go:46`), where the prefix comes from `PrefixFor(rigName)` (`internal/session/registry.go:196`).

Tracking is query-time derivation in `loadFromBeads` (`internal/polecat/manager.go:2731`): check tmux session liveness once (`internal/polecat/manager.go:2754` via `polecatSessionState` at `internal/polecat/manager.go:2859`); if a `status=hooked` bead is assigned to this polecat's assignee, report `working` (or `stalled` when the session is dead, `internal/polecat/manager.go:2759`); else fall back to the legacy agent-bead `hook_bead` only when it still resolves to a currently hooked bead (`internal/polecat/manager.go:2782`); else query the assigned issue (`internal/polecat/manager.go:2804`); a live session with no work and unsafe cleanup status becomes `review-needed` instead of a false `working` (`internal/polecat/manager.go:2845`). The agent's own liveness signal is the heartbeat file `<town>/.runtime/heartbeats/<session>.json` carrying timestamp plus v2 agent-reported state/context/bead (`internal/polecat/heartbeat.go:33`, paths at `internal/polecat/heartbeat.go:58`), written best-effort by `TouchSessionHeartbeatWithState` (`internal/polecat/heartbeat.go:78`) and considered stale after 3 minutes (`internal/polecat/heartbeat.go:13`, check at `internal/polecat/heartbeat.go:121`).

Retirement is the happy-path terminal: `gt done` pushes the branch, submits the merge-request bead to the refinery queue, clears the hook, sets agent state to `done` (via `SetAgentState`/`SetAgentStateWithRetry`, `internal/polecat/manager.go:2566`/`internal/polecat/manager.go:371`), and kills its own session — the next sling allocates fresh capacity rather than reusing the completed session (`docs/concepts/polecat-lifecycle.md:51`). Reuse is gated by pure policy: `DecideWorkstate` classifies a polecat into `WORKING`, `SAFE_TO_NUKE`, `PENDING_MR`, `NEEDS_RECOVERY`, or `NEEDS_MQ_SUBMIT` from lifecycle plus git plus merge-queue facts (`internal/polecat/workstate.go:59`, input at `internal/polecat/workstate.go:15`, verdicts at `internal/polecat/workstate.go:5`), and `DecideSlotReuse` is the same classifier projected to a reusable/not decision (`internal/polecat/reuse.go:43`). `ReuseIdlePolecat` reuses only genuinely idle slots (`internal/polecat/manager.go:1757`); `ReclaimBrokenIdlePolecat` repairs idle-looking polecats whose preserved work blocks reuse (`internal/polecat/manager.go:1346`); `RemoveWithOptions` is the destructive path with cleanup-status gating, active-MR blocking (`internal/polecat/manager.go:1310`), and force/nuclear/self-nuke modes (`internal/polecat/manager.go:1126`).

```
polecat lifecycle (docs/concepts/polecat-lifecycle.md:24, states internal/polecat/types.go:31)
│
▼
gt sling ──► AllocateAndAdd (pool+polecat locks, manager.go:662)
  │              │ worktree polecats/<name>/<rig> on polecat/<name>/<issue>+<ts>
  │              ▼
  │           tmux <prefix>-<name> ──► WORKING (hooked bead + live session)
  │              │  session cycles via handoff; sandbox persists
  │              ▼
  │           gt done ──► push branch, submit MR, agent_state=done, kill session ──► DONE (retired)
  │              │                                              │
  │              ▼                                              ▼
  │        Refinery merges MQ ──► cleanup owns branch/worktree  Witness: stalled/zombie detect + nuke
  │
  └─► only idle + SAFE_TO_NUKE slots are reused (workstate.go:59, reuse.go:43)
```

## Crew: persistent user-managed workers

Crew members are the operator's personal persistent workspaces inside a rig (`README.md:60`); unlike polecats they are never auto-garbage-collected and they push to main directly instead of going through the refinery merge queue (`docs/overview.md:74`, rig README scaffold at `internal/rig/manager.go:784`). `CrewWorker` holds name, rig, clone path, branch, and timestamps (`internal/crew/types.go:8`). `crew.Manager` holds the rig and git helper (`internal/crew/manager.go:130`); the worker lives at `<rig>/crew/<name>` (`internal/crew/manager.go:144`) with `state.json` beside the clone (`internal/crew/manager.go:149`). `Add` validates the name, takes the per-crew flock, and delegates to `addLocked` (`internal/crew/manager.go:182`); `addLocked` full-clones the rig repo on the rig's default branch (with `--reference` and fallback variants), syncs remotes from the mayor clone so fork push URLs are preserved, and persists state (`internal/crew/manager.go:195`, clone at `internal/crew/manager.go:212`). State is persisted with an atomic JSON write (`internal/crew/manager.go:521`) and loaded with directory-name-wins reconciliation so a renamed or copied directory self-heals (`internal/crew/manager.go:531`). `Rename` locks both names in alphabetical order to avoid deadlock (`internal/crew/manager.go:566`). The crew tmux session is `<prefix>-crew-<name>` (`internal/session/names.go:40`).

## Mayor, Boot, and the watchdog chain

The Mayor is the primary AI coordinator with full workspace context (`README.md:48`); infrastructure-wide it is a singleton persistent process, one per machine (`docs/overview.md:28`, session comment at `internal/session/names.go:14`). `mayor.Manager` is constructed with just the town root (`internal/mayor/manager.go:91`); its working directory is `<town>/mayor` (`internal/mayor/manager.go:109`) and its tmux session is `hq-mayor` (`internal/mayor/manager.go:99` via `internal/session/names.go:16`). `CombinedStatus` merges tmux liveness and ACP-process liveness into one `MayorStatus` with modes `tmux`/`acp`/`both`/`none` (`internal/mayor/manager.go:53`, modes at `internal/mayor/manager.go:29`); `IsActive` projects that to a boolean (`internal/mayor/manager.go:85`). Startup has `Start` (refuses when already active, `internal/mayor/manager.go:116`), `StartTMUX` (`internal/mayor/manager.go:131`), and `StartACP` (`internal/mayor/manager.go:192`). ACP presence is a PID file at `<town>/mayor/mayor-acp.pid` (`internal/mayor/cleanup.go:23`); `IsACPActive` checks process liveness without side effects, deliberately never auto-removing stale PID files because removal would trip the proxy's PID monitoring (`internal/mayor/cleanup.go:102`). `CleanupVetoChecker` vetoes destructive cleanup while an ACP mayor session is active, on the theory the mayor may be reviewing worker diffs (`internal/mayor/cleanup.go:144`).

Boot is the Deacon's triage watchdog: a dog that runs fresh on each daemon tick and decides whether to wake, nudge, or interrupt the Deacon (`internal/boot/boot.go:1`). The `Boot` struct binds the town root, `<town>/deacon/dogs/boot/` work dir, deacon dir, tmux handle, and degraded flag (`internal/boot/boot.go:38`). Mutual exclusion is a flock on `.boot-running` (`internal/boot/boot.go:89`), released plus marker-removed on completion (`internal/boot/boot.go:108`); execution status (`started_at`, `last_action`, target, error) is kept in `.boot-status.json` (`internal/boot/boot.go:29`). `Spawn` is explicitly ephemeral — no `IsRunning` guard, any stale `hq-boot` tmux session is killed before starting fresh (`internal/boot/boot.go:157`, kill at `internal/boot/boot.go:172`); degraded (tmux-less) mode runs `gt boot triage --degraded` as a detached subprocess instead (`internal/boot/boot.go:200`).

## Namepool: bounded slot allocation

Polecat names come from a themed `NamePool` holding rig name, theme, optional custom names, a transient in-use set, an overflow counter, and max size (`internal/polecat/namepool.go:92`). Defaults are 50 themed slots (`internal/polecat/namepool.go:23`) with the `mad-max` theme (`internal/polecat/namepool.go:26`); built-in themes are `mad-max`, `minerals`, and `wasteland` (`internal/polecat/namepool.go:45`), and names reserved for infrastructure (`witness`, `mayor`, `deacon`, `refinery`, `crew`, `polecats`) can never be allocated (`internal/polecat/namepool.go:35`). `Allocate` picks the first free themed name and falls back to numeric overflow past the max size (`internal/polecat/namepool.go:270`); `Release` frees a slot only on explicit nuke (`internal/polecat/namepool.go:295`); `Reconcile` rebuilds the transient in-use set from existing polecat directories on disk, never from persisted state (`internal/polecat/namepool.go:354`, in-use marked transient at `internal/polecat/namepool.go:104`). The pool persists theme/overflow state via `Save` (`internal/polecat/namepool.go:248`) and reloads with `Load` (`internal/polecat/namepool.go:201`); per-rig theme selection avoids collisions across rigs through `ThemeForRig` and `ThemeForRigAvoiding` (`internal/polecat/namepool.go:436`, `internal/polecat/namepool.go:452`), with the rig manager reporting already-used themes via `UsedNamepoolThemes` (`internal/rig/manager.go:180`). A name slot determines the sandbox path (`polecats/<name>/`), the tmux session, and the attribution string, and it persists until explicit nuke (`docs/concepts/polecat-lifecycle.md:173`).

## Sessions: tmux names and startup

Every agent role maps to a deterministic tmux session name built from the town `hq-` prefix or the rig's beads prefix: `hq-mayor` (`internal/session/names.go:16`), `hq-deacon` (`internal/session/names.go:21`), `<prefix>-witness` (`internal/session/names.go:28`), `<prefix>-refinery` (`internal/session/names.go:34`), `<prefix>-crew-<name>` (`internal/session/names.go:40`), `<prefix>-<name>` for polecats (`internal/session/names.go:46`), `hq-boot` (`internal/session/names.go:59`), and `hq-dog-<name>` (`internal/session/names.go:66`). Both mail addresses and session names parse into the same `AgentIdentity` (role, rig, name, prefix) struct (`internal/session/identity.go:24`): `ParseAddress` handles `mayor`, `deacon`, `<rig>/witness`, `<rig>/refinery`, `<rig>/crew/<name>`, `<rig>/polecats/<name>` (`internal/session/identity.go:32`), and `ParseSessionName` inverts the tmux format back to identity (`internal/session/identity.go:100`).

Polecat session startup (`SessionManager.Start`, `internal/polecat/session_manager.go:320`) validates the session name (`internal/polecat/session_manager.go:127`), resolves the slot index (`internal/polecat/session_manager.go:300`), ensures a canonical session branch (`internal/polecat/session_manager.go:246`), hooks the work bead to the agent (`internal/polecat/session_manager.go:958` via `hookIssue`), and verifies the startup nudge was delivered (`internal/polecat/session_manager.go:901`). Session teardown is `Stop` with a force flag (`internal/polecat/session_manager.go:631`); liveness probes are `IsRunning`/`Status`/`List` (`internal/polecat/session_manager.go:660`, `internal/polecat/session_manager.go:667`, `internal/polecat/session_manager.go:723`), and `StopAll` kills every polecat session in the rig (`internal/polecat/session_manager.go:833`). Crew startup takes `StartOptions` (agent override, session resume ID, startup prompt, detached mode) at `internal/crew/manager.go:39`, runs through `Start` (`internal/crew/manager.go:682`), and stops via `Stop` (`internal/crew/manager.go:909`) with `IsRunning` for probes (`internal/crew/manager.go:944`). Crew session IDs are validated (`internal/crew/manager.go:71`) and resume args built (`internal/crew/manager.go:87`) so a crew tmux session can reattach to a prior agent session.

## Rig teardown and adoption

`RemoveRig` deletes a rig's directory and registry entry (`internal/rig/manager.go:1600`), including dropping orphaned Dolt databases for the rig prefix (`internal/rig/manager.go:1093` via `dropRigOrphanDBs`). `RegisterRig` adopts an existing on-disk directory instead of cloning: it detects git URLs and push URL from the directory's own remotes (`internal/rig/manager.go:1801` via `detectPushURL`, `internal/rig/manager.go:1843` via `detectGitURL`), verifies rig identity to avoid adopting a foreign directory (`internal/rig/manager.go:992` via `verifyRigIdentity`), and then runs the same beads-init, agent-beads, molecule-seed, and plugin-directory steps as `AddRig` (`internal/rig/manager.go:1632`). Local-repo references (borrow objects from a nearby clone instead of the network) resolve through `resolveLocalRepo` (`internal/rig/manager.go:276`), and HTTPS remote URLs normalize to SSH via `convertToSSH` (`internal/rig/manager.go:65`) with clone failures wrapped with remediation hints by `wrapCloneError` (`internal/rig/manager.go:43`).

## Global state: machine-level enable toggle

Outside any town, `internal/state` keeps a machine-level on/off switch. `State` holds enabled flag, version, machine ID, install/update timestamps, shell-integration marker, and last doctor run (`internal/state/state.go:17`). Paths are XDG-compliant: state in `~/.local/state/gastown/` (`internal/state/state.go:29`), config in `~/.config/gastown/` (`internal/state/state.go:41`), cache in `~/.cache/gastown/` (`internal/state/state.go:51`), with the JSON file itself at `state.json` (`internal/state/state.go:59`). `IsEnabled` resolves env override (`GASTOWN_DISABLED`/`GASTOWN_ENABLED`) over the state file, defaulting to disabled when unreadable (`internal/state/state.go:65`); `Save` writes atomically with `0600` permissions (`internal/state/state.go:100`), and `Enable`/`Disable` flip the flag, creating fresh state with a generated machine ID when none exists (`internal/state/state.go:112`, `internal/state/state.go:128`).
`GetMachineID` returns the stored machine ID or a fresh ephemeral one when state is missing (`internal/state/state.go:150`).
`SetShellIntegration` records the installed shell hook and `RecordDoctorRun` timestamps the last health check (`internal/state/state.go:159`, `internal/state/state.go:172`).

## Concurrency and locking between agents

All cross-process coordination is flock files plus beads state, because every `gt` invocation is a separate process. Polecat paths use two lock granularities under `<rig>/.runtime/locks/`: `lockPolecat(name)` on `polecat-<name>.lock` serializes Add/Remove/Repair per polecat, and `lockPool()` on `polecat-pool.lock` serializes name allocation and pool reconciliation (`internal/polecat/manager.go:218`, `internal/polecat/manager.go:234`). The critical section design is documented inline: `AllocateAndAdd` holds the pool lock across allocation and directory creation (closing the GH#2215 race where two processes could allocate the same name between pool save and `mkdir`), acquires the per-polecat lock while still holding the pool lock, then releases the pool lock once the directory exists because reconcile will now see it (`internal/polecat/manager.go:658`). A `polecats/<name>.pending` reservation marker covers the residual window between pool save and directory creation (`internal/polecat/manager.go:489`, written at `internal/polecat/manager.go:1500`, reconciled at `internal/polecat/manager.go:2002`). Crew uses the same pattern with `crew-<name>.lock` (`internal/crew/manager.go:168`), with `Rename` taking both endpoint locks in alphabetical order to prevent deadlock (`internal/crew/manager.go:571`). Boot serializes triage with a flock on `.boot-running` rather than a session-existence check, because triage runs inside the Boot session itself so an existence check would always fail (`internal/boot/boot.go:85`). Beads-level races against the Dolt backend use bounded retry with exponential backoff that distinguishes optimistic-lock conflicts (retryable) from config errors (fail fast) (`internal/polecat/manager.go:55`, `internal/polecat/manager.go:75`, `internal/polecat/manager.go:92`), gated before spawn by `CheckDoltHealth` (`internal/polecat/manager.go:252`). Stale-state detection elsewhere is read-side cross-checking (tmux versus beads in `loadFromBeads`, heartbeat freshness in the Witness) rather than locking, so monitors never block workers.
