# Overstory — Critical Analysis

## Claims vs. evidence
(README/docs claims vs. what the source actually shows)

- Multi-harness (multiple AI coding tools) claim is overstated. The registry lists 8 adapters (`src/runtimes/registry.ts:16`), but only 2 are marked `stable` — Claude (`src/runtimes/claude.ts:35`) and Sapling (`src/runtimes/sapling.ts:349`) — and the rest are `experimental`. OpenCode is an acknowledged stub: `detectReady` always returns `loading` and `parseTranscript` always returns null (`src/runtimes/opencode.ts:138`, `src/runtimes/opencode.ts:155`). Cursor reports zero tokens because its stream format exposes no usage (`src/runtimes/cursor.ts:156`). In practice this is a Claude-first system with one headless alternative, not 8 equal backends.
- Guard (tool-call blocking) claim holds only on 3 harnesses. Five adapters — Codex, Copilot, Cursor, Gemini, OpenCode — deploy no guards at all, so role limits there are prompt text only. Claude writes hooks (`src/runtimes/claude.ts:129`), Pi writes a guard extension (`src/runtimes/pi-guards.ts:128`), Sapling writes JSON guards (`src/runtimes/sapling.ts:98`). A read-only reviewer on Gemini or OpenCode is therefore a request, not an enforcement.
- Durability (survives restarts) claim is half true. Checkpoints, handoffs, and SQLite (a small file-based database) state do survive crashes, but mail delivery is destructive-read: `check()` fetches unread rows then marks them read in a loop (`src/mail/client.ts:156`), so a crash between SELECT and UPDATE redelivers, and broadcast fan-out inserts N rows in a loop (`src/commands/mail.ts:327`), so a mid-loop failure delivers to only a prefix of recipients. Event recording is deliberately fire-and-forget and swallows database failures (`src/commands/mail.ts:442`, `src/events/tailer.ts:162`), so observability loss is silent. Durable work state, lossy coordination signals.
- Supervision claim is weaker than the diagram suggests. T1 triage (Tier 1, one-shot AI classifier) reads only the last 50 log lines and asks for a one-word answer (`src/watchdog/triage.ts:29`), defaulting to `extend` (leave running) when logs or model are missing (`src/watchdog/triage.ts:44`). A dead agent with no logs therefore gets extended, not killed. Session resume is documented in design docs but no adapter implements it — the wiki confirms zero `resume` references in any runtime file.
- Merge safety claim improved only after a data-loss bug. CHANGELOG 0.8.7 fixes "silent content loss in merge auto-resolve Tier 2", and the current code refuses to discard non-empty canonical sides (`src/merge/resolver.ts:273`). The Tier 2 regex keeps the incoming side by default (`src/merge/resolver.ts:142`), and the prose filter (`looksLikeProse()` at `src/merge/resolver.ts:314`) is a string-pattern heuristic against model chatter. These are sensible patches, but they show the 4-tier ladder shipped with a correctness hole.
- Docs lag code. The daemon header still describes an old tier numbering where Tier 2 is "not yet implemented" (`src/watchdog/daemon.ts:13`), while `ov monitor` plus `agents/monitor.md` implement it. Supervisor is deprecated (`agents/supervisor.md:1`) yet still appears in manifests, commands, and guard lists. Trust the command source, not the header comments.

## Architecture tradeoffs
(What the design makes hard, not just what it enables)

- Single-machine lock-in. Everything assumes local `git`, `tmux` (a terminal multiplexer that keeps shell sessions alive in the background), and SQLite files under `.overstory/`. There is no network API (application programming interface), so distributing workers across machines or running cleanly in containers and CI (continuous integration, automated test servers) is hard — each new host needs Bun (a JavaScript runtime), tmux, tracker CLIs (command-line tools `sd`/`bd`), and harness CLIs installed.
- Readiness by screen-scraping is brittle. Claude readiness matches prompt markers plus bypass-permissions dialogs (`src/runtimes/claude.ts:153`), Pi matches a header plus token-counter regex (`src/runtimes/pi.ts:174`). Any harness UI (user interface) text change breaks spawn detection, as the 0.8.7 Shift+Tab false-positive fix already demonstrated.
- Depth ceiling of 2 limits recursion. Coordinator (depth 0) spawns leads (depth 1) which spawn leaves (depth 2) (`src/commands/sling.ts:568`, default `maxDepth` 2 in `src/config.ts:59`). Deep task trees must be flattened into groups, and the coordinator becomes a bottleneck: only a typed `merge_ready` mail authorizes a merge (`agents/coordinator.md:224`), and issue close must follow merge (`agents/coordinator.md:291`).
- Serial merge queue limits throughput. One SQLite FIFO (first-in-first-out) queue processes one branch at a time (`src/merge/queue.ts:135`), so a slow AI-resolve or reimagine tier blocks every branch behind it (head-of-line blocking). Good for correctness, bad for 25 concurrent agents (the configured `maxConcurrent` in `src/config.ts:57`).
- File sprawl and cleanup debt. Each agent produces a worktree directory, tmux session, mailbox rows, 5 SQLite databases, specs, checkpoints, handoffs, logs, and nudge markers. Cleanup defaults to completed and zombie sessions only and refuses unmerged branches without `--force` (`src/commands/worktree.ts:109`, `src/commands/worktree.ts:117`), so interrupted runs accumulate orphans. Lead branches are never merged and only their `.seeds/` diff is preserved (`src/worktree/manager.ts:249`) — lead-authored work outside issue files is thrown away by design.
- Reinvented parsers. The config loader has a hand-rolled YAML (a human-readable config format) parser that skips flow syntax, multiline strings, and anchors (`src/config.ts:121`), and identity files use a custom tab-indented serializer plus custom parser (`src/agents/identity.ts:18`, `src/agents/identity.ts:90`). Standard YAML libraries would remove two bespoke failure surfaces.
- Priority is display-only. Mail priority never reorders storage, only adds a tag and a nudge file (`src/mail/client.ts:104`). An urgent message behind 50 normal ones is still read in creation order.

## Maturity and risk signals
(Test coverage, release cadence, bus factor, issue hygiene — check CHANGELOG.md and version 0.8.7 in /tmp/overstory, plus test-file density observed in wiki pages)

- Test count is high but did not prevent severe bugs. CHANGELOG 0.8.7 reports 3364 tests across 100 files (7924 assertions), and wiki pages show colocated `*.test.ts` files with real temp-directory I/O (input/output against temporary folders) for runtimes, mail, merge, and watchdog. Yet the same changelog fixes a tmux kill blast radius (empty session name matching everything, fixed via `killAgent()` routing in `src/watchdog/daemon.ts:368`), silent merge content loss, a dashboard crash on SQLite lock contention, and coordinator premature issue closure. The suite looks unit-heavy and integration-light around concurrency and failure paths.
- Release cadence is pre-1.0 churn. Version 0.8.7 is dated 2026-03-10 in `/tmp/overstory`; the changelog shows 0.8.1 through 0.8.4 all landing on 2026-03-04, then 0.8.5 on 03-05, 0.8.6 on 03-06, 0.8.7 on 03-10. Four releases in one day plus daily follow-ups means fast fixes but unstable interfaces — pinning to this API (the command and config surface) carries migration cost.
- Bus factor (number of people who must disappear to stall the project) is 1. `CODEOWNERS` contains only `@jayminwest`, `package.json` names author Jaymin West, and the repository URL there (`github.com/jayminwest/overstory`) disagrees with the knowledge-base source URL (`github.com/Marmalade118/overstory`) — a fork-or-move confusion no maintainer clarified in-repo. Outside names in 0.8.7 (@XavierChevalier for Cursor, @mustafamagdy for dashboard, @Ilanbux, @arosstale) each contributed one fix, not ongoing ownership.
- Issue hygiene signals are mixed. The doctor command validates the merge queue (stale entries older than 24 hours, duplicate branches with auto-fix to `MAX(id)` in `src/doctor/merge-queue.ts:88`), which is good. But shipping an OpenCode stub adapter, a zero-token Cursor parser, a stale daemon header, and duplicated file-modifying bash lists (not exported from `guard-rules.ts`, duplicated at `src/runtimes/pi-guards.ts:38`) shows tolerance for landing incomplete work and paying down later.

## Dependency risk
(Small dep surface: commander, chalk, @os-eco/mulch-cli, bun runtime — judge it)

- The npm (JavaScript package registry) surface is genuinely small and that is a strength: `commander` (CLI argument parser), `chalk` (terminal colors), and `@os-eco/mulch-cli` (expertise and pattern store) per `package.json:46`, plus dev-only formatter and type tools. No LLM (large language model) SDK (software development kit) dependency means no vendor lock-in at the package layer — model access goes through harness CLIs behind the `AgentRuntime` interface.
- The hidden surface is large. Real requirements are Bun >= 1.0, `git`, `tmux`, one harness CLI, and one tracker CLI (`sd` or `bd`) — none version-pinned by npm. Past breakage proves the cost: fish-shell spawn failure (fixed by wrapping in `/bin/bash -c` in `src/worktree/tmux.ts:114`), WSL2 (Windows Subsystem for Linux) tmux timing races, root-execution refusal because Claude rejects permission bypass as UID 0 (user id zero, i.e. root) (`src/commands/sling.ts:498`), and transcript discovery depending on `HOME` (`src/runtimes/claude.ts:248`). `chalk` v5 and `commander` v14 are ESM-only (ECMAScript Modules, the modern JavaScript import style), cementing the Bun-only path.
- `@os-eco/mulch-cli` at `^0.6.2` is the risky pin. It backs overlays (`ml prime`), learning loops (`ml record`), and merge-pattern search (`src/merge/resolver.ts:549`), so Overstory degrades with its sibling ecosystem (mulch, seeds, canopy) rather than standing alone. A single-vendor internal tool as the only stateful npm dependency concentrates supply risk: if `mulch-cli` breaks or changes output shape, expertise injection, cost-adjacent learning, and guard-adjacent flows fail together.

## What it changes / applicability to fleet
(Which ideas transfer to the fleet orchestrator and which do not)

- Transfer the SQLite mail pragmatics: WAL (write-ahead logging, a mode allowing concurrent readers) mode plus 5-second busy timeout, CHECK-constrained (database-level value restriction) schema, inbox and thread indexes (`src/mail/store.ts:177`, `src/mail/store.ts:46`), typed and threaded messages with unread tracking. Skip the destructive-read plus file-nudge plus tmux-poke delivery chain — fleet should use lease-based claims or explicit acknowledgments instead of SELECT-then-UPDATE plus 3-second-delayed `sendKeys` (`src/commands/mail.ts:479`).
- Transfer guards-as-data: central blocklists (10 native team tools, 3 interactive tools, 3 write tools, ~37 bash patterns) checked after a safe-prefix allowlist (`src/agents/guard-rules.ts:13`, `src/agents/guard-rules.ts:85`). Fleet can enforce role-shaped CLIs the same way without trusting prompts. Do not copy the three-way split (Claude hooks vs Pi extension vs Sapling JSON) or the duplicated bash list — export one source list.
- Transfer checkpoint plus handoff plus identity trio (`src/agents/checkpoint.ts:14`, `src/agents/lifecycle.ts:72`, `src/agents/identity.ts:253`): file snapshots decoupled from conversation context, pending-handoff records with null replacement sessions, and per-agent work-history CVs (curriculum vitae, here a work-history record) capped at 20 tasks. These survive compaction (automatic context compression) and crashes with no harness cooperation.
- Transfer progressive supervision: warn, nudge, AI triage, terminate with a ceiling (`src/watchdog/daemon.ts:703`), recovery reset (`src/watchdog/daemon.ts:603`), once-per-run completion nudge guarded by a marker file (`src/watchdog/daemon.ts:190`), and observable-state-wins health checks (tmux and PID liveness outrank recorded state in `src/watchdog/health.ts:4`). Do not copy 50-line-log one-word triage or 2-minute monitor patrols verbatim — fleet needs richer evidence and configurable cadence.
- Transfer merge-tier safety checks, not the queue: the canonical-content guard that refuses to discard real canonical hunks (`src/merge/resolver.ts:273`), prose-output rejection (`src/merge/resolver.ts:314`), and stash plus auto-commit pre-steps (`src/merge/resolver.ts:709`) port directly. The single FIFO queue, keep-incoming default, regex marker parsing, and full-reimplement Tier 4 do not scale to fleet branch volumes.
- Do not transfer tmux screen-scraping spawn, the 8-adapter registry with stubs, the depth-2 ceiling, tracker-CLI subprocess coupling, or the custom YAML parsers. Fleet already owns beads-based tracking; Overstory's value is its coordination patterns, not its process layer.

## Verdict
(Commit to ONE of: adopt / trial / watch / skip, with 2-3 sentences of justification. No both-sides filler.)

**Verdict: trial.** Pilot the portable patterns — SQLite typed mail, guards-as-data, checkpoint/handoff resume, and progressive watchdog escalation — inside one fleet workstream, because each maps to a concrete source file with proven mechanics. Reject wholesale adoption: single maintainer, pre-1.0 daily churn, Claude-centric guards, and tmux-bound single-machine design make the full system a support liability fleet should not inherit.
