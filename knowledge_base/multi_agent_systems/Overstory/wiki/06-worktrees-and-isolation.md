# Git-Worktree Isolation and Process Management
**In one sentence:** Overstory gives each worker agent its own filesystem directory plus git branch, runs the agent inside a named tmux (terminal multiplexer, a tool that keeps terminal processes alive in background sessions) session or a direct headless subprocess, and exposes `worktree`, `stop`, and `run` CLI (command-line interface, the text commands used to control the tool) commands to inspect and tear that isolation down safely.

## Key points
- One agent maps to one directory (`{baseDir}/{agentName}`) and one branch (`overstory/{agentName}/{taskId}`), created atomically by `git worktree add -b <branch> <path> <baseBranch>` (`src/worktree/manager.ts:55`, `src/worktree/manager.ts:56`, `src/worktree/manager.ts:58`).
- All git plumbing goes through a shared `runGit()` wrapper over `Bun.spawn(["git", ...])` that throws a structured `WorktreeError` with worktree path and branch context on nonzero exit (`src/worktree/manager.ts:8`, `src/worktree/manager.ts:25`).
- Failed spawns roll back both artifacts (forced worktree removal plus `git branch -D`) on a best-effort, error-swallowing path so the original spawn error is preserved (`src/worktree/manager.ts:72`, `src/worktree/manager.ts:78`, `src/worktree/manager.ts:90`).
- TUI (terminal user interface, an interactive full-terminal program such as Claude Code) agents run in detached tmux sessions named `overstory-{projectName}-{agentName}`, started with `tmux new-session -d -s <name> -c <cwd>`, with PID (process identifier, the operating-system number for a running process) discovery via `list-panes -F #{pane_pid}` and up to 3 retries for pane-registration races (`src/worktree/tmux.ts:5`, `src/worktree/tmux.ts:85`, `src/worktree/tmux.ts:126`, `src/worktree/tmux.ts:140`).
- Headless agents bypass tmux entirely via `spawnHeadlessAgent()`: direct `Bun.spawn()` with explicit `cwd`/`env` and optional `stdoutFile`/`stderrFile` redirects that eliminate ~64 KB pipe backpressure (`src/worktree/process.ts:84`, `src/worktree/process.ts:95`, `src/worktree/process.ts:98`).
- Termination is two-layered: deepest-first `SIGTERM`, a 2000 ms grace period, then `SIGKILL` on survivors, using `pgrep -P` tree walks and `process.kill(pid, 0)` liveness checks, before `tmux kill-session -t` (`src/worktree/tmux.ts:212`, `src/worktree/tmux.ts:255`, `src/worktree/tmux.ts:290`, `src/worktree/tmux.ts:317`, `src/worktree/tmux.ts:376`).
- Cleanup is merge-gated: `ov worktree clean` defaults to completed/zombie sessions only, skips unmerged branches per `git merge-base --is-ancestor` unless `--force`, kills live tmux sessions first, then force-removes the worktree and force-deletes the branch (`src/commands/worktree.ts:109`, `src/commands/worktree.ts:117`, `src/worktree/manager.ts:173`, `src/commands/worktree.ts:183`).
- `ov stop <agent>` distinguishes TUI versus headless (`tmuxSession === "" && pid !== null` means headless), refuses to re-stop completed agents without `--clean-worktree`, and `ov run` only manages coordinator run groupings, not processes (`src/commands/stop.ts:118`, `src/commands/stop.ts:110`, `src/commands/run.ts:1`).

## 1. Worktree creation and on-disk layout
Each worker gets a physically separate checkout. `createWorktree()` in `src/worktree/manager.ts:46` takes `repoRoot`, `baseDir`, `agentName`, `baseBranch`, and `taskId`, then derives:

```ts
const worktreePath = join(baseDir, agentName); // src/worktree/manager.ts:55
const branchName = `overstory/${agentName}/${taskId}`; // src/worktree/manager.ts:56
```

It then executes a single git operation (`src/worktree/manager.ts:58`):

```ts
await runGit(repoRoot, ["worktree", "add", "-b", branchName, worktreePath, baseBranch], {
  worktreePath,
  branchName,
});
```

Consequences: the branch is created (`-b`) already checked out at the new path and parented on `baseBranch`, so all workers share a common ancestor but diverge immediately. The return value is `{ path, branch }` (`src/worktree/manager.ts:63`). Because git forbids checking out the same branch in two worktrees at once, the `overstory/{agent}/{task}` naming simultaneously namespaces ownership and makes accidental double-checkout structurally impossible.

All git invocations funnel through `runGit()` (`src/worktree/manager.ts:8`), which spawns `git` with piped stdout/stderr (`src/worktree/manager.ts:13`), awaits stdout, stderr, and exit code together (`src/worktree/manager.ts:19`), and throws `WorktreeError` carrying `worktreePath` and `branchName` on nonzero exit (`src/worktree/manager.ts:25`). This is why every worktree failure carries enough context to identify which agent directory and branch broke.

## 2. Rollback on failed spawn
`rollbackWorktree()` (`src/worktree/manager.ts:72`) exists to undo a half-created worktree when agent spawning fails after the git step. It runs `git worktree remove --force <path>` (`src/worktree/manager.ts:78`) and then `git branch -D <branch>` (`src/worktree/manager.ts:90`), each wrapped in its own try/catch that swallows errors (`src/worktree/manager.ts:84`, `src/worktree/manager.ts:96`). The branch delete is skipped for empty branch names (`src/worktree/manager.ts:88`). The function is documented as best-effort and intended to be called inside a catch block so the caller's original error dominates (`src/worktree/manager.ts:66`).

## 3. Listing, parsing, and merge detection
`listWorktrees()` (`src/worktree/manager.ts:162`) runs `git worktree list --porcelain` (`src/worktree/manager.ts:165`) and parses it in `parseWorktreeOutput()` (`src/worktree/manager.ts:125`). Porcelain blocks are split on blank lines (`src/worktree/manager.ts:127`), `worktree`/`HEAD`/`branch` lines are extracted (`src/worktree/manager.ts:138`, `src/worktree/manager.ts:140`, `src/worktree/manager.ts:142`), and the `refs/heads/` prefix is stripped to yield short branch names (`src/worktree/manager.ts:145`). Entries with a path are kept (`src/worktree/manager.ts:149`); the result type is `{ path, branch, head }` (`src/worktree/manager.ts:105`).

`isBranchMerged()` (`src/worktree/manager.ts:173`) shells `git merge-base --is-ancestor <branch> <targetBranch>` (`src/worktree/manager.ts:178`): exit 0 returns `true`, exit 1 returns `false` (`src/worktree/manager.ts:186`, `src/worktree/manager.ts:187`), and any other exit throws `WorktreeError` (`src/worktree/manager.ts:189`). Callers treat unresolvable merge status as unmerged, a fail-closed default (`src/commands/worktree.ts:119`).

`removeWorktree()` (`src/worktree/manager.ts:203`) first re-lists worktrees to resolve the branch for the given path (`src/worktree/manager.ts:209`), then runs `git worktree remove <path>` with optional `--force` (`src/worktree/manager.ts:214`). After removal it deletes the branch with `-D` when `forceBranch` is set and `-d` (safe, merged-only) otherwise (`src/worktree/manager.ts:227`); branch-deletion failure is caught and ignored because the worktree itself is already gone (`src/worktree/manager.ts:230`).

## 4. Lead-agent `.seeds/` preservation
Lead branches are never merged through the normal pipeline, so their `.seeds/` issue files would be lost on cleanup. `preserveSeedsChanges()` (`src/worktree/manager.ts:249`) extracts only the `.seeds/` diff with a three-dot range `git diff <canonical>...<branch> -- .seeds/` (`src/worktree/manager.ts:259`), returns `{ preserved: false }` when the diff is empty (`src/worktree/manager.ts:265`), verifies the repo root is on the canonical branch via `rev-parse --abbrev-ref HEAD` (`src/worktree/manager.ts:273`), requires `.seeds/` to be clean per `git status --porcelain -- .seeds/` (`src/worktree/manager.ts:289`), writes the diff to a temp file under `.overstory/` (`src/worktree/manager.ts:303`), applies it with `git apply --index` (`src/worktree/manager.ts:309`), commits as `chore: preserve .seeds/ changes from lead <agent>` (`src/worktree/manager.ts:324`), reverts `.seeds/` on apply or commit failure (`src/worktree/manager.ts:314`, `src/worktree/manager.ts:333`), and always unlinks the temp file (`src/worktree/manager.ts:345`).

## 5. tmux session lifecycle
tmux is a terminal multiplexer that keeps processes alive in background sessions after the launching shell exits. Overstory names every session `overstory-{projectName}-{agentName}` so sessions do not collide across projects and can be cleaned per project (`src/worktree/tmux.ts:5`).

`createSession(name, cwd, command, env?, maxRetries = 3)` (`src/worktree/tmux.ts:85`) builds a bash startup script: it prepends the overstory binary directory to `PATH` (detected via `which ov` then `which overstory` in `src/worktree/tmux.ts:24`, used at `src/worktree/tmux.ts:97`), unsets the `CLAUDECODE` nesting guard (`src/worktree/tmux.ts:105`), and exports caller-provided variables (`src/worktree/tmux.ts:108`). The script is wrapped in `/bin/bash -c '...'` with single-quote escaping so it works regardless of the user's login shell (`src/worktree/tmux.ts:114`, `src/worktree/tmux.ts:121`). Creation is `tmux new-session -d -s <name> -c <cwd> <wrappedCommand>` (`src/worktree/tmux.ts:125`); nonzero exit throws `AgentError` (`src/worktree/tmux.ts:130`). The pane PID (process identifier) is then read with `tmux list-panes -t <name> -F #{pane_pid}` with retry and `250 * (attempt + 1)` ms backoff for pane-registration races (`src/worktree/tmux.ts:140`, `src/worktree/tmux.ts:143`); an unparseable PID throws (`src/worktree/tmux.ts:161`).

Supporting operations, all via direct tmux CLI (command-line interface) calls through a `runCommand()` helper that captures stdout, stderr, and exit code (`src/worktree/tmux.ts:60`): `listSessions()` parses `tmux list-sessions -F #{session_name}:#{pid}` and maps "no server running" to an empty list rather than an error (`src/worktree/tmux.ts:172`, `src/worktree/tmux.ts:181`); `getPanePid()` uses `tmux display-message -p -t <name> #{pane_pid}` and returns null on failure (`src/worktree/tmux.ts:221`); `isSessionAlive()` wraps `tmux has-session -t` (`src/worktree/tmux.ts:429`); `checkSessionState()` distinguishes `alive` / `dead` / `no_server` by inspecting stderr (`src/worktree/tmux.ts:441`, `src/worktree/tmux.ts:458`); `capturePaneContent()` runs `tmux capture-pane -p -S -<lines>` with a default of 50 lines (`src/worktree/tmux.ts:474`); `waitForTuiReady()` polls pane content against a runtime-supplied `detectReady` callback with default 30 s timeout and 500 ms interval, retrying typed dialog actions (`src/worktree/tmux.ts:510`, `src/worktree/tmux.ts:527`); `ensureTmuxAvailable()` probes `tmux -V` (`src/worktree/tmux.ts:559`); `sendKeys()` flattens newlines to spaces before `tmux send-keys -t <name> <text> Enter` and classifies `no server running`, `can't find pane` (retried, `src/worktree/tmux.ts:611`), and `session not found` errors separately (`src/worktree/tmux.ts:580`); `getCurrentSessionName()` returns null outside tmux by checking the `TMUX` environment variable (`src/worktree/tmux.ts:406`).

## 6. Headless process spawning
For runtimes with `headless === true`, `ov sling` bypasses tmux entirely (`src/worktree/process.ts:5`). `spawnHeadlessAgent(argv, opts)` (`src/worktree/process.ts:84`) splits argv into executable plus args (`src/worktree/process.ts:88`), throws `AgentError` on empty argv (`src/worktree/process.ts:89`), maps `stdoutFile`/`stderrFile` to `Bun.file()` targets and defaults both streams to pipes otherwise (`src/worktree/process.ts:95`), spawns with explicit `cwd`, full `env` (no implicit merge with `process.env`), and piped stdin (`src/worktree/process.ts:98`), and returns a `HeadlessProcess` of `{ pid, stdin, stdout }` where `stdout` is null in file-redirect mode (`src/worktree/process.ts:24`, `src/worktree/process.ts:106`). File redirection is the recommended mode because it removes pipe backpressure: without a consumer, an OS (operating system) pipe buffer of roughly 64 KB fills and blocks the child (`src/worktree/process.ts:68`). Options are typed in `SpawnHeadlessOptions` with `cwd`, `env`, `stdoutFile`, `stderrFile` (`src/worktree/process.ts:46`). Liveness and kill helpers are deliberately not duplicated here; they live in `tmux.ts` (`src/worktree/process.ts:9`).

## 7. Process-tree termination
The kill path handles both tmux-hosted and headless agents. `isProcessAlive()` (`src/worktree/tmux.ts:290`) sends signal 0 via `process.kill(pid, 0)` (`src/worktree/tmux.ts:293`): no signal is delivered, existence alone is probed. `getDescendantPids()` (`src/worktree/tmux.ts:255`) runs `pgrep -P <pid>` (`src/worktree/tmux.ts:256`), treats exit 1 as "no children" (`src/worktree/tmux.ts:259`), parses child PIDs (`src/worktree/tmux.ts:264`), recurses depth-first, and returns deepest-descendants-first ordering so children die before parents and are not reparented to init (`src/worktree/tmux.ts:272`, `src/worktree/tmux.ts:278`).

`killProcessTree(rootPid, gracePeriodMs = 2000)` (`src/worktree/tmux.ts:317`) uses a 2000 ms default grace constant (`src/worktree/tmux.ts:212`): it collects descendants (`src/worktree/tmux.ts:321`), sends `SIGTERM` deepest-first then to the root (`src/worktree/tmux.ts:330`), sleeps the grace period (`src/worktree/tmux.ts:336`), then sends `SIGKILL` to survivors only after re-checking liveness (`src/worktree/tmux.ts:339`). With no descendants it just `SIGTERM`s the root (`src/worktree/tmux.ts:323`). `sendSignal()` ignores `ESRCH` (already dead) and `EPERM` (permission) errors (`src/worktree/tmux.ts:355`). `killSession()` (`src/worktree/tmux.ts:376`) composes the two layers: fetch pane PID first (`src/worktree/tmux.ts:378`), kill the tree (`src/worktree/tmux.ts:382`), then `tmux kill-session -t <name>` (`src/worktree/tmux.ts:386`), treating "session not found" as success (`src/worktree/tmux.ts:390`).

## 8. CLI surface: `worktree`, `stop`, `run`
`ov worktree list | clean` is defined in `src/commands/worktree.ts:295`. `handleList()` (`src/commands/worktree.ts:29`) lists worktrees (`src/commands/worktree.ts:30`), joins each against the session store (`src/commands/worktree.ts:32`), filters to `overstory/`-prefixed branches (`src/commands/worktree.ts:40`), and emits JSON (JavaScript Object Notation, a machine-readable data format) records of `{ path, branch, head, agentName, state, taskId }` or human-readable blocks (`src/commands/worktree.ts:43`, `src/commands/worktree.ts:63`). Logs are never auto-deleted (`src/commands/worktree.ts:1`).

`handleClean()` (`src/commands/worktree.ts:78`) defaults to completed-only: sessions not in `completed` or `zombie` state are skipped unless `--all` flips `completedOnly` off (`src/commands/worktree.ts:109`, `src/commands/worktree.ts:324`). Lead agents skip the merge check because their branches are never merged (`src/commands/worktree.ts:114`); all other branches must satisfy `isBranchMerged()` against the canonical branch unless `--force` (`src/commands/worktree.ts:117`), with unresolvable status treated as unmerged and the branch pushed to a `skipped` list (`src/commands/worktree.ts:126`). Live tmux sessions are killed first on a best-effort basis (`src/commands/worktree.ts:134`). `--force` on unmerged branches prints a warning (`src/commands/worktree.ts:146`). Lead `.seeds/` changes are preserved before removal (`src/commands/worktree.ts:160`). Removal always uses `{ force: true, forceBranch: true }` because deployed config files create untracked files that defeat non-forced removal, and finished-agent branches are typically unmerged (`src/commands/worktree.ts:177`, `src/commands/worktree.ts:183`). Afterward the command purges the agents' mail (`src/commands/worktree.ts:199`), marks cleaned sessions `zombie` (`src/commands/worktree.ts:219`), prunes zombie records whose paths no longer exist (`src/commands/worktree.ts:228`), and reports `{ cleaned, failed, skipped, pruned, mailPurged, seedsPreserved }` as JSON (JavaScript Object Notation) or text (`src/commands/worktree.ts:241`). Flags are `--completed`, `--all`, `--force`, `--json` (`src/commands/worktree.ts:311`).

`ov stop <agent-name>` (`src/commands/stop.ts:1`) looks up the session by name (`src/commands/stop.ts:102`), throws for unknown agents (`src/commands/stop.ts:104`), and throws for already-completed agents unless `--clean-worktree` is passed (`src/commands/stop.ts:110`). Headless detection is `session.tmuxSession === "" && session.pid !== null` (`src/commands/stop.ts:118`): headless agents are killed via `killTree(pid)` after an `isAlive(pid)` check (`src/commands/stop.ts:125`), TUI (terminal user interface) agents via `isSessionAlive` plus `killSession` (`src/commands/stop.ts:134`), all injectable through `StopDeps` for tests (`src/commands/stop.ts:31`). The session is then marked `completed` with refreshed activity (`src/commands/stop.ts:142`). With `--clean-worktree`, the worktree is removed with `{ force, forceBranch: false }` and the branch deleted via best-effort `git branch -D`, both non-fatal (`src/commands/stop.ts:149`, `src/commands/stop.ts:164`, `src/commands/stop.ts:53`). JSON (JavaScript Object Notation) output reports `tmuxKilled`, `pidKilled`, `worktreeRemoved`, `branchDeleted`, `wasZombie`, and `wasCompleted` (`src/commands/stop.ts:173`).

`ov run` does not spawn or stop processes despite its name: it manages runs, defined as coordinator session groupings (`src/commands/run.ts:1`). State lives in `.overstory/current-run.txt` (`src/commands/run.ts:28`) read by `readCurrentRunId()` (`src/commands/run.ts:35`). Subcommands are bare `run` for current-run status (`src/commands/run.ts:70`), `run list` with `--last <n>` defaulting to 10 (`src/commands/run.ts:113`, `src/commands/run.ts:297`), `run complete` which marks the run completed and unlinks `current-run.txt` (`src/commands/run.ts:161`, `src/commands/run.ts:176`), and `run show <id>` which joins the run against its agents via `getByRun()` (`src/commands/run.ts:199`, `src/commands/run.ts:226`).

## 9. Why isolation prevents merge conflicts
Isolation works because sharing is removed at two levels. At the filesystem level, each agent writes only inside `{baseDir}/{agentName}` (`src/worktree/manager.ts:55`), so two agents never contend on the same working-tree files, untracked outputs, or build artifacts. At the version-control level, each agent commits only to its own `overstory/{agent}/{task}` branch parented on the same base (`src/worktree/manager.ts:56`, `src/worktree/manager.ts:58`), so concurrent work cannot produce in-tree merge markers or clobber another agent's uncommitted state. Convergence happens later through an explicit merge pipeline that checks `merge-base --is-ancestor` before cleanup (`src/worktree/manager.ts:178`), refuses to clean unmerged branches by default (`src/commands/worktree.ts:117`), and requires `--force` plus a warning to destroy unmerged work (`src/commands/worktree.ts:146`). The `-d` versus `-D` distinction in `removeWorktree()` (`src/worktree/manager.ts:227`) encodes the same policy at the git level: safe deletion only for merged branches, forced deletion only when the operator opts in.
