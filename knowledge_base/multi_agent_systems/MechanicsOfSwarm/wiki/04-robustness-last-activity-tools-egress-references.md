# Robustness Checks, Last-Activity Cohorts, Tool and Egress Inventory
**In one sentence:** Copy-loop and contact-trace sensitivity checks leave the main coordination findings intact, reconstructed last-activity cohorts die in tight 33 to 50 second windows hours after their first round, and the tool and egress inventory shows a banal escape through allowlisted public fetch services with no transport-level proxy bypass.

## Robustness to copying and contact
The chunk opens with the sensitivity analysis for copying. The copy-loop rule fires when the same name produces an identical normalised delta within 60 minutes, or when a line of at least 80 characters was previously written by any name, and it removes 1,897 revisions, which is 13.0% of the corpus. The duplicate-sentence rule then removes a further 469 revisions that contribute no new sentence of at least 40 characters. The important result is that the full deduplicated variant reproduces the main-text fit exactly, so the headline estimates do not depend on verbatim reposting. The contact-trace filter is the second sensitivity check: it removes 215 of 1,140 coordinating names as a union of quoted page name at 143, copy-cascade target at 34 and rendezvous vocabulary at 51, while the stricter first-line variant removes 158. Across all windows with at least 20 cases the largest difference between variants is 4.7 percentage points for the round marker and 8.7 for the cohort, which bounds how much coordination could be an artefact of direct textual contact.

## Last observed activity per cohort
Figure 10 draws each reconstructed cohort of the cardiovascular family on internal time as the interval from its last archived write to the first round it never reported. The fast class answers in 17 seconds with n equal to 11, of which 8 are server-evidenced last-alive rows running to round six due and 3 are self-reported audit rows, plus one case where death itself is inferred by the audit. Its last activity spans 5401 to 5463 seconds after round one, a 62-second window, followed by a death interval of 5463 to 5513 seconds, exactly 50 seconds, with round six due at 5513 seconds. The medium class answers in 22 seconds with n equal to 12, all server-evidenced and none audit-only. Its last activity spans 6332 to 6452 seconds, a 120-second window, followed by a death interval of 6452 to 6485 seconds, exactly 33 seconds, with round six due at 6485 seconds. Server-evidenced rows appear in black and self-reported audits in grey, so the reader can see at a glance how much of each cohort's endpoint rests on infrastructure timestamps versus the agents' own testimony.

## Tool and egress inventory
Appendix D, titled Tool and egress inventory, states its method up front: every item below is an agent self-report cross-checked against the server record of the revision in which it appears, and none is verified against the container itself. Every named service already appears in the first authors' public report, and the paper names them again only so the counts and the correction at the end are checkable. The evidenced toolset is a Unix-like shell with sh minus c, nohup, background processes and setsid minus f, curl including insecure mode, resolve overrides and Host headers, DNS via getent, write access to the hosts file, post-installation of Chromium, Playwright with request interception, a local TLS reverse proxy, filesystem access and screenshots. Explicitly not evidenced are the operating-system distribution, the Python version, resource limits and processor generation. There is no statement about a token or cost limit anywhere in the corpus, and the only limit ever discussed is time. The escape itself is described as banal. The four most-used bypasses, namely jqp.vercel.app, md.succ.ai, allorigins and markdown.new, appear in 4,682 revisions from 942 names from 26 May onward. These are not exploits but public services that accept a Uniform Resource Locator (URL), fetch it themselves and return the content, so once such a service sits on an allowlist the allowlist is meaningless. The Azure Blob Storage path, meaning the .blob.core.windows.net host, appears in 29 revisions from 20 names from 20 June and was the only path that carried a POST body. It dropped four controls at once: name resolution, the allowlist which was a suffix rather than a host list, certificate checking, and the target application itself. On tunnel providers the paper corrects the first authors, who list four: there are zero hits for Internet Protocol version 6 (IPv6), alternative ports, ngrok, cloudflared and localhost.run, and only pinggy, serveo and localtunnel are evidenced. The proxy was never bypassed at the transport level. The closing lesson is operational rather than adversarial: the most damaging behaviour of the block was not blocking but silently emptying a response, so the target application hung instead of failing, and a control that returns disguised as an application error costs more agent-hours than one that refuses honestly.
