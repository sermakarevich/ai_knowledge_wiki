# Agora: Git as Shared Memory for Collective AutoResearch

**Paper:** [Agora: Git as Shared Memory for Collective AutoResearch (Zhang et al., 2026)](https://arxiv.org/pdf/2609.18094)

## Human Readable TL;DR

Imagine a dozen scientists who never meet, never chat, and never share a desk — but all write in the same lab notebook where every page is permanent, dated, and stapled to the pages it builds on. Agora is that notebook for AI research assistants, built on Git: every idea, failed experiment, check, and guess becomes a page anyone can reopen and rerun, and a built-in map shows what is hot, what is unverified, and which corners nobody has explored. When thirteen AI workers shared this notebook for nearly twelve days on a hard puzzle — giving a new frozen brain good starting values without any training data — they went from random guessing to surprisingly capable, and when they all piled onto one popular idea for five days, a single map of their own crowding pulled them out within a day.

## TL;DR

Agora reframes multi-agent research as an append-only contribution DAG stored in Git, where every result, insight, hypothesis, verification, and report is an immutable commit whose parent edges declare what it builds on, and where the Git history is the only state passed between workers who share no conversation, manager, runtime, or filesystem. Quality is set by downstream evidence rather than votes: an evidence score counts what other accounts built on a node with self-citations excluded and replaceable verification verdicts, while diversity-aware attention combines metric leaders, leaves, unverified and contested results, open hypotheses, semantic clusters, and a diversity-aware upper-confidence-bound ranking shown in exploit, explore-known, and explore-novel slots. A small Go service with CLI plus Next.js web interface implements this with per-project bare repos, an eight-table SQLite index rebuildable from Git, 26 HTTP routes, and 15 CLI groups. In the first sustained run, thirteen uncoordinated coding-agent workers over nearly twelve days published 1,703 contributions on a no-training weight-transfer task with 141 donor models and a frozen 119.6M-parameter attention-SSM hybrid, driving the evaluator from 3.39 to 1.899 bits per byte and closing 62% of the gap to a trained GPT-2 124M, with a 145-commit winning ancestry across fifteen accounts, 165 independent reproductions with no failures, and a single mid-run human intervention on May 2 that broke a five-day monoculture.

## Problem & Motivation

Single autonomous coding agents can already improve a training setup unattended, but their learning is stuck in a session transcript or a temporary worktree: the next session does not know which learning rate diverged, which branch was abandoned, or which result still needs an independent check. Adding more workers makes this worse rather than better, because each session starts from scratch, so more agents mean more duplicated search, earlier convergence onto the same leader, and more reconstruction of who did what. Existing multi-agent frameworks organize conversations, roles, or staged workflows inside one task or episode, which does not serve an asynchronous research community that needs state outliving any worker: a public frontier, immutable lineage, negative results, independent verification, and attention-spreading without dictating a single workflow. Agora is proposed as that coordination substrate rather than a lab manager, in the spirit of collective-intelligence and institutional views of science where discovery is decentralized but coordinated through shared public knowledge. Its design stance is explicit: the system does not try to decide what is true, but makes claims, dependencies, verification status, and untried alternatives visible enough that a mixed community of humans and agents can coordinate around them, with projects defining their own instructions, metrics, artifact contracts, and safety boundaries.

## Main Original Ideas

1. **Append-only Git-backed research DAG** — A project state is a directed acyclic graph in which every contribution is a Git commit and every parent edge means builds on, so history is append-only and acyclic by construction. Light metadata-only and heavy code-bearing publication paths yield the same node kind carrying commit hash, account, tags, description, metadata, optional metric, parent set, and server timestamp, and code-bearing contributions carry the full repository state so any claim can be checked out and rerun. Git holds the canonical immutable content-addressed artifacts while SQLite holds a derived searchable index, and every figure and analyze view is rebuildable from the Git history alone.

2. **Evidence-weighted quality instead of votes** — Quality is computed from downstream use by other accounts rather than popularity. The evidence score sums tag-weighted follow-on work with self-citations excluded, giving plus five for setup, result, insight, hypothesis, and report, plus twenty, plus ten, or minus twenty for confirmed, partial, or failed verifications, and zero for endorsements and work in progress, with the newest verification verdict replacing the old one's effect while both commits remain. A separate descendant count tracks qualifying downstream work, so work that others reproduced or built on ranks as more actionable than work that was merely voted for.

3. **Diversity-aware attention allocation with three slots** — Because a leaderboard is a good exploitation signal and a poor map that pulls every worker toward the same parent and hides negative results, the analyze call returns metric leaders, most built-on nodes, leaves, promising but underexplored results, unverified and contested results, open hypotheses, activity, tags, contributors, and single-link semantic clusters with coverage, entropy-based effective counts, evenness, histograms, and a small-cluster frontier. Candidates are ranked by a diversity-aware upper-confidence bound combining quality percentile, follow-on-work density, near-duplicate counts, and an exploration constant that grows when scores bunch near the best, and are shown in exploit, explore-known, and explore-novel slots. The split matters more than the exact score because it puts the explore-exploit trade-off in front of participants and makes monoculture collapse visible.

4. **Minimal auditable prototype** — The prototype is deliberately small enough to audit end to end: a Go service with command-line client and Next.js web interface, per-project bare repositories with canonical contribution refs, eight SQLite tables covering agents, projects, contributions, parents, tags, cross-project references, embeddings, and rate limits, plus bearer authentication on writes, clones, and fetches with rate limits and a Docker image bundling API, web interface, and storage. The loop is analyze, pick a parent, run locally, publish, and analyze again, starting from an agora init setup contribution.

5. **No-training weight-transfer demonstration and matched-evaluation proposal** — The paper stages a demanding test where a frozen 14-layer hybrid target with hidden size 672, seven heads, untied embeddings, and dimensions matching no donor must be initialized using only the weights and forward passes of 141 donor models with no training corpus and no gradient update, scored on 200 FineWeb-Edu texts as summed next-token loss per UTF-8 byte. Reproducibility appendices then define what a retained community run must preserve, a minimal contribution and verification record, and a matched community-level comparison across Isolated, Flat log, Central planner, and Agora arms with the entire community run as the analysis unit.

## Key Findings

The community of thirteen worker accounts, five on A100 nodes and eight on H100 nodes running Claude Code with Claude Opus and Codex with GPT-5.5 behind a two-page brief and a one-line prompt, sustained roughly 170 contributions per day over eleven days and nineteen hours for 1,703 contributions comprising 1,124 scored results, 284 insights, 203 hypotheses, 165 verifications, and one report, with 233 new bests and more than 400 prediction bands declared from late April. The winning recipe compresses donor next-token statistics into the target's embedding and output head and then adds short-range context through sparse edits to attention, feed-forward, and state-space blocks: Stage A queries six GPT-2-vocabulary donors over 28 single-token contexts into a 50257 by 50257 bigram table with heavy weight on GPT-2 small, splits off a column-mean anchor, factorizes the centered table to rank 671 by randomized SVD, and zeroes all sublayers, while Stage B wires uniform causal attention and gated depthwise convolutions over 96-dimensional bands with small fixed scalars plus a 0.009-scale projection of GPT-2 small's first MLP into the layer-zero feed-forward block. The trajectory is steep then flat, with a slice-copying attempt at 4.68 worse than random published as a negative result, a unigram prior at 2.52 thirty minutes later, bigram statistics under 1.93 within six hours across four accounts, six donors and 28 contexts reaching 1.9136, a better SVD sketch reaching 1.9062, the first SSM edit at 1.9028 after a landscape read, and cross-band writes closing at 1.899044, so that the first eighteen scored contributions deliver about 98% of the total reduction while the remaining thousand-plus find the last three hundredths. Without training data or a single gradient update this closes 62% of the gap from 3.39 random initialization toward about 1.0 for a trained GPT-2 124M, resting on a 145-commit ancestry spanning fifteen accounts with most parent edges crossing accounts, 165 verifications covering 95 distinct targets with no reported failures, bit-identical same-hardware reproductions and cross-hardware variation within about a thousandth of a bit per byte, and 53 explicitly tagged negative results ruling out larger prefix sets, flattened spectra, transplanted blocks, direct embedding copies, and mismatched-tokenizer priors. Coordination dynamics show both the mechanism working and its limits: fast exploitation with most descent in the first eight improvements, a narrow spine with short abandoned side branches, heavy parallel rediscovery with most identical cross-account scores landing within hours, and a five-day basin refining one recipe by hundred-thousandths per step that was left within a day after the May 2 deployment of clustering, diversity summaries, and the diversity-aware ranking, when a worker followed a thin state-space cluster instead of the dominant one. Verification was done at three levels by recomputing every count from a server export, algebraically checking the best score, and reading the winning commit's 83-module import chain to confirm no evaluation-data access and no gradient updates, though the winning method itself was not rerun and the authors stress trusting the move from 3.39 to about 1.90 rather than the final decimals.

## Suggestions & Future Directions

The paper is candid that causality remains unsettled because the same models and compute were never run without Agora or with a plain leaderboard, and the community left its first basin only after being shown a map of it, so the central next step is measurement through the proposed matched comparison that distinguishes when a research DAG improves discovery per unit of compute from when it merely files parallel waste more neatly. Within the mechanism, the authors point toward stronger diversity handling since a shared leaderboard alone did not stop duplicate work and the graph stayed exploitation-biased, alongside fuller retention of immutable identities from instructions and scoring policy through code, model, data, hardware, prompt, seed, budget, event-level evaluator outputs, and frozen aggregation code. Verification records should additionally carry target hashes, reproduction configurations, evaluator identities, and reproduced values, since a verdict without those artifacts is only a coordination hint rather than strong validation evidence. The reproducibility and evaluation appendices, together with the open questions on what the trace does and does not establish, frame Agora as a first sustained existence proof whose follow-up must be preregistered, community-level, and reuse-matched rather than another anecdotal scale-up.
