# A Generalized Software Architecture for Swarm
**Paper:** [A Generalized Software Architecture for Swarm](http://127.0.0.1:8765/Agentic_AI1.pdf)

## Human Readable TL;DR
Today's teams of AI agents usually work like an orchestra with a single conductor who hands out every part and collects every result, so if the conductor fails or gets overwhelmed the whole performance stops. This paper replaces the conductor with something more like an ant colony or a farmers' market: every agent is a peer that breaks big goals into smaller jobs, advertises them to neighbors, bids on work it is good at, and shares news by gossip while keeping a shared notebook that merges cleanly even when copies disagree. The result is a single reusable coordination recipe that keeps making progress when agents join, leave, fail, or get temporarily cut off, without ever needing to rewrite the rules for a new kind of task.

## TL;DR
The paper proposes a generalized, task-agnostic, fully decentralized software architecture for swarms of heterogeneous large language model (LLM, a large neural network trained to understand and generate language) agents in which global behavior emerges from local peer interactions rather than central orchestration. Coordination is organized into three interacting planes — a task plane for recursive goal decomposition and capability-aware, load-sensitive bidding; a state plane for gossip-disseminated, CRDT-synchronized (CRDT, conflict-free replicated data type, a data structure whose replicas can be updated independently and always merge to the same result) shared context; and a membership plane for dynamic join, departure, and failure handling — implemented as a five-layer stack that strictly separates task-agnostic coordination from domain-specific agent reasoning. The design rests on five principles (locality of decision, protocol–semantics separation, redundancy by default, graceful degradation, composable primitives), combines standard distributed-systems tools (Contract Net-style bidding, gossip, CRDTs, structured peer-to-peer overlays such as DHTs, SWIM-style failure detection, ephemeral Raft quorum consensus for irreversible commitments), and claims sub-linear per-agent overhead into the thousands of agents with bounded staleness and continuity under churn, failure, and partition.

## Problem & Motivation
Single LLM agents are limited by bounded context windows, constrained reasoning depth, and strictly serialized execution, which motivates concurrent cooperative multi-agent systems for demanding goals such as scientific discovery, software synthesis, knowledge curation, and large-scale data analysis. Most current multi-agent LLM frameworks nevertheless use a centralized orchestrator–worker or static role hierarchy in which one planner decomposes the goal, assigns sub-tasks, and aggregates outputs, and the paper argues this reproduces exactly the deficiencies distributed-systems research has long tried to avoid: a single point of failure, a throughput bottleneck as swarm size grows, and task-specific prompt and control-flow assumptions that impair generalization. Classical multi-agent systems, swarm intelligence, and distributed coordination each solve part of the puzzle but not the whole, so the paper states three joint requirements with no widely adopted reference architecture yet satisfying them together: task-agnosticism in which coordination is independent of domain semantics, full decentralization of coordination, state, and decisions, and operational resilience that tolerates dynamic membership change, agent failures, and network partitions without losing task progress. The scope is deliberately software-level coordination substrate, communication, consensus, and network dynamics, explicitly excluding physical hardware, embodied robotics, sensor fusion, and actuation.

## Main Original Ideas
1. **Three-plane decentralized swarm model.** The swarm is formalized as a dynamic graph of agents with no privileged coordinator, organized into a task plane governing the goal and sub-task lifecycle (decomposition, advertisement, bidding, execution, result integration), a state plane holding eventually consistent shared context (ongoing work, completed sub-tasks, outstanding dependencies), and a membership plane tracking composition and reallocating responsibilities on join, departure, and failure events. The planes interact through well-defined interfaces but evolve independently, and collective problem-solving capacity becomes a function of protocol design rather than central control.
2. **Agent and goal formalization with reputation.** Each agent is modeled as `ai = <idi, Ci, Li, Si, κi>` where `idi` is a unique identifier, `Ci` is a self-declared but peer-verifiable capability profile of executable task classes, tools, modalities, and estimated competence, `Li ∈ [0,1]` is normalized load, `Si` is the local state replica, and `κi ∈ [0,1]` is reputation from historical contribution quality such that persistent misrepresentation degrades future awards. A submitted goal `G` is an abstract decomposition-agnostic descriptor dynamically expanded into a task dependency DAG (directed acyclic graph, a graph of nodes and one-way edges with no cycles) `T = (V, E)` in which vertices are sub-tasks and edges encode output dependencies, while each sub-task is a tuple `t = ⟨id_t, ρ_t, δ_t, π_t, σ_t⟩` carrying its required capability descriptor, dependency identifiers, acceptance predicate for result validity, and lifecycle status.
3. **Recursive decomposition with capability-aware tempered bidding.** Any goal is first held by a temporary root holder with no special authority beyond initiating a domain-specific decomposition function `D : G ↦ {t1, …, tm}`, whose outputs are inserted into the shared DAG and gossiped, and any assigned sub-task may itself be recursively decomposed so tractable work proceeds in a pipeline while abstract work is still being refined. Each `PENDING` sub-task is announced toward the overlay neighborhood most likely to match, bids take the form `b_i,t = ⟨id_i, u_i,t, e_i,t⟩` with self-estimated utility `u_i,t = α·cap(C_i, ρ_t) + β·(1 − L_i) + γ·κ_i` balancing capability match, spare capacity, and reputation, and after a bounded window the holder awards greedily with probability `1 − ϵ` or softmax-samples over the top-k with probability `ϵ` to avoid work concentration and adversarial bidding, with deterministic identifier tie-breaking so reordered messages still converge to one assignment and optional top-r redundant assignment reconciled by the acceptance predicate for critical tasks.
4. **Gossip plus CRDT state plane with selective strong consistency.** Shared state `S = {task DAG T, result store R, membership view M}` is CRDT-encoded with an OR-Set plus last-writer-wins registers for `T`, a grow-only map for immutable results in `R`, and a delta-state CRDT for `M` to bound overhead under churn, and disseminated by anti-entropy gossip in which each agent exchanges deltas with a fixed fan-out of neighbors every interval `τ`, converging in `O(log n)` rounds with vector clocks used to detect concurrency and defer decisions on unacceptably stale views. Routine progress runs under eventual consistency with pre-execution assignment checks and deterministic post-merge conflict resolution to suppress redundant work, while only irreversible commitment points such as goal completion escalate to an ephemeral on-demand Raft-style quorum drawn from the relevant neighborhood and dissolved afterward, giving linearizability exactly where it matters.
5. **Five-layer stack with strict coordination–reasoning separation and gossip-based fault tolerance.** The software stack runs from a Transport Layer over QUIC (Quick UDP Internet Connections, a fast encrypted transport protocol) or TLS-secured TCP (Transport Layer Security over Transmission Control Protocol, the standard reliable internet connection), through an Overlay Layer for structured peer-to-peer discovery, routing, and capability-targeted dissemination, a State Synchronization Layer hosting CRDT replicas and gossip, a Coordination Layer implementing allocation, membership, failure detection, and on-demand consensus, up to an Agent Reasoning Layer holding decomposition, capability evaluation, execution, and acceptance checking that communicates only through coordination interfaces so domain semantics never leak downward. Inside each agent a coordination client, bidding engine, task executor, state observer over `T`, `R`, and `M`, and health monitor with heartbeats and load reports drive a lifecycle in which any agent can accept a goal, gossip its decomposition, collect bids, award work, and recursively execute until an on-demand quorum confirms completion, while joins use bootstrap peers plus gossip, graceful leaves release assignments cleanly, SWIM-style random probes plus indirect probes detect silent failures, orphans return to `PENDING` for rebidding or fail over instantly to bounded shadow agents, and partitions make local progress before CRDT merge and deterministic assignment resolution reconcile them.

## Key Findings
The paper is architectural rather than empirical and therefore offers analytical claims organized around scalability, consistency, fault tolerance, and generality instead of benchmark wins. Peer lookup and routing cost `O(log n)` messages on the structured overlay, gossip converges in `O(log n)` rounds at constant per-round per-agent cost for `O(n log n)` aggregate messages per cycle, CRDT merges cost `O(|Δ|)` in recent delta size rather than total state, and per-sub-task allocation costs `O(k)` in solicited bidders independent of swarm size, which together are said to admit sub-linear per-agent overhead supporting growth into the thousands of agents under realistic message budgets. Routine state stays eventually consistent with staleness bounded by gossip period and fan-out, which the authors argue matches monotonic agentic workloads tolerant of brief inconsistency, while goal completion and selected irreversible transitions gain linearizability through lightweight consensus. Under the baseline non-Byzantine assumption the design is claimed to tolerate any minority of simultaneous failures inside a consensus quorum and any number of failures in the broader swarm as long as the overlay stays connected, with orphan reassignment latency bounded by failure-detection timeout plus one bidding round or instantaneous under shadow agents, and partitions reconciled on healing. Generality follows from operating purely on opaque task descriptors and capability profiles, so collaborative research, distributed code synthesis, document analysis, and knowledge-graph construction are all said to run without protocol modification with specialization confined to the reasoning layer. Structural invariants offered as the formal contract to higher layers include eventual assignment uniqueness, result immutability once `COMPLETED`, dependency safety gating execution on observed `COMPLETED` dependencies, and bounded-latency convergence of the membership view under stable membership.

## Suggestions & Future Directions
The authors are explicit that analytical claims still need empirical grounding and name large-scale simulation with realistic latency and failure models as the required validation, alongside systematic characterization and tuning of the interacting gossip parameters, CRDT delta sizes, and bidding latencies whose joint optimization remains unmapped. Three limitations are acknowledged as research prompts: the non-Byzantine baseline must be extended with Byzantine fault-tolerant consensus and verifiable computation for open untrusted swarms despite substantial overhead, the scalar capability-match score in the utility function should grow into richer multi-dimensional matching for highly heterogeneous swarms, and open agent markets still lack economic incentives for participation. The decomposition function `D` is deliberately left in the reasoning layer yet strongly conditions efficiency, so principled and learning-based decomposition strategies are flagged as a major open challenge. For engineering, the recommended pathway reuses mature open-source pieces — an existing structured overlay library, a CRDT library, and Raft for on-demand consensus — and builds only the coordination layer plus agent reasoning interfaces as novel work to reduce risk and permit incremental validation.
