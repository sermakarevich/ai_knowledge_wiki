# Engineers from doers to reviewers and designers

**In one sentence:** Software engineers must shift from writing code to reviewing machine-generated code with advanced forensics skills, learn to select and combine models so one model quality-controls another, and move upstream into user stories, code frameworks, and business-outcome thinking as generative Artificial Intelligence (gen AI) absorbs basic coding.

## Key points

- A significant percentage of current-generation gen AI code needs correction, forcing developers to shift from doer to reviewer — and some proficient coders are not good reviewers.
- Good reviewers judge compatibility with existing repositories and architectures and write code another team can maintain, skills senior engineers often have but juniors must still build.
- Beyond spotting duplicates and obvious errors, engineers need advanced forensics skills to find and fix subtle defects, plus the harder ability to "train up" gen AI tools that learn on the job.
- Engineers must learn to select and combine gen AI applications and models, for instance using one model to provide quality control for another specific model.
- As basic coding is automated, engineers develop higher-value upstream skills: writing user stories, building code frameworks such as libraries and support programs, understanding business outcomes, and anticipating user intent.
- The junior-engineer implication is sharp: review and forensics judgment, once earned slowly through writing code, must now be taught deliberately since the machine writes first drafts.
- Trust cuts both ways for engineers — neither blind faith in generated code nor reflexive distrust — which is why standard tool training is insufficient without judgment-building.

## Review: the doer-to-reviewer shift

### Why reviewing is its own skill

"* Review. A significant percentage of code generated by the current generation of gen AI tools needs some correction. At one level, this requires developers to shift from doer to reviewer, which is not as basic as it sounds. Some proficient coders aren't good reviewers." The bar for good review is concrete and organizational: "Good reviewers must be able to evaluate code-based compatibility with existing code repositories and architectures, for example, and understand what is required so another team can easily maintain the code—skills that more experienced engineers often have but more junior colleagues need to build."

### Forensics and training the tool itself

The article raises the standard from error-spotting to investigation: "Developers will need to not just spot duplicates or obvious errors but ensure high-quality code by developing advanced forensics skills to identify and address issues. Even more complex will be the "training up" of gen AI tools, which have to learn on the job to get better." Model orchestration becomes an engineering competence in its own right: "A critical skill that engineers must develop is how to select and combine gen AI applications and models (for example, how one model might be good at providing quality control for another specific model)."

## Design: moving upstream

### Higher-value work machines cannot do yet

"* Design. As gen AI technology takes over more of the basic coding tasks, engineers can develop a new set of higher-value "upstream skills" such as writing user stories, developing code frameworks (for instance, code libraries, support programs), understanding business outcomes, and anticipating user intent." The logic connects directly to the product development life cycle compression on Page 1: when generation is cheap, the scarce human contribution is deciding what to build, framing it so machines build it well, and anchoring it in business outcomes and user intent.
