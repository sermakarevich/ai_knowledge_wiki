# Four priorities for technology leaders

**In one sentence:** Leaders should train developers in prompting and risk awareness, chase use cases beyond code generation, plan for shifting skill needs, and install governance for privacy, legal, ethical, and security risks.

## Key points

- The article prescribes a structured approach of training and coaching, use case selection, workforce upskilling, and risk controls, operationalized as four priorities: skill development, advanced use cases, skill shifts, and risk management.
- Initial training must cover prompt engineering through hands-on exercises, plus workshops on data privacy, intellectual-property issues, and how to review AI-assisted code for design, functionality, complexity, standards, and quality.
- Developers with under a year of experience need extra coursework in syntax, data structures, algorithms, design patterns, and debugging, followed by ongoing senior coaching and community channels for sharing examples.
- Using both AI tools together on a task delivered 1.5 to 2.5 times more time improvement than using one, which motivates pursuing combined and advanced use cases beyond plain code generation.
- Freed capacity should be redirected deliberately, for example toward business expansion or more frequent product updates, with developers building new design and architecture skills to fill emerging gaps.
- Governance must confront four named risks: data privacy and third-party security exposure via prompts, legal and regulatory change such as the General Data Protection Regulation (GDPR), ethics and reputation around copyrighted or contested code, and security vulnerabilities in generated code.

---

## The four priorities

### 1. Provide training and coaching

"For developers to effectively use the technology to augment their daily work, they will likely need a combination of training and coaching. Initial training should include best practices and hands-on exercises for inputting natural-language prompts into the tools, often called prompt engineering." Risk literacy is part of the curriculum: "workshops should equip developers with an overview of generative AI risks, including any industry-specific data privacy or intellectual-property issues and best practices in reviewing AI-assisted code for design, functionality, complexity, coding standards, and quality, including how to discern good versus bad recommendations from the tools." Juniors get a foundations track: "additional coursework in foundational programming principles — for example, coding syntax, data structures, algorithms, design patterns, and debugging skills." Learning continues on the job "with ongoing coaching from senior team members and community building, such as dedicated online channels and team meetings to share practical examples."

### 2. Pursue advanced use cases beyond code generation

The two-tool finding is the lever: "when developers used both generative AI tools within a given task, as opposed to only one, they realized an additional time improvement of 1.5 to 2.5 times." Leaders should therefore look past single-tool code generation toward combined and higher-value applications.

### 3. Plan for skill shifts

"Leaders should consider how to use their additional capacity and what upskilling is needed to close any skill gaps that may emerge. They might, for example, apply their talent to enable new business expansion or update existing products more often. These assignments would require developers to build new skills in software design and architecture."

### 4. Provide risk controls

"New data, intellectual-property, and regulatory risks are emerging with generative AI–based tools. Given the speed at which developers can write or update code with these tools, it's easy to imagine how any problems from, say, a coding error or data issue could snowball." The four risks to govern are: "data privacy and third-party security, such as the potential for developers to expose confidential information when prompting the tools"; "legal and regulatory changes, including changes to the European Union's General Data Protection Regulation (GDPR) and other regulations limiting the use of the technology"; "ethics and reputational issues that could arise from using a snippet of code copyrighted by another entity or amid debates on ownership of code the tools generate"; and "security vulnerabilities that can crop up in AI-generated code and put systems (and the organization) at risk."

## Closing promise

"Generative AI is poised to transform software development in a way that no other tooling or process improvement has done. Using today's class of generative AI–based tools, developers can complete tasks up to two times faster — and this is just the beginning." The foundation: "A structured approach encompassing generative AI training and coaching, use case selection, workforce upskilling, and risk controls can lay a solid foundation for organizations to pursue generative AI's promise of extraordinary productivity and unparalleled software innovation."
