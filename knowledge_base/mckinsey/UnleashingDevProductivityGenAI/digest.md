# Digest — Unleashing developer productivity with generative AI

## 01 — Speed gains and caveats

**In one sentence:** McKinsey's lab study found developers complete coding tasks up to twice as fast with generative Artificial Intelligence (AI) tools, but the gains collapse on complex tasks and for junior developers.

- Documenting code functionality for maintainability took half the time with generative AI assistance, the largest saving among the three task types studied.
- Writing new code took nearly half the time with AI assistance, while optimizing existing code, known as code refactoring, took nearly two-thirds of the unassisted time.
- Time savings shrank below 10 percent on tasks developers rated high in complexity, for example when they lacked familiarity with a required programming framework.
- Developers with less than one year of experience sometimes took 7 to 10 percent longer with the tools than without them, showing the gains depend on existing skill.
- Code quality did not fall as speed rose when developer and tool collaborated, and automated reviews rated readability of AI-assisted code marginally better.
- Maintaining quality still depends on the developer, who must understand what makes code good and prompt the tool toward the right outputs.

## 02 — Research design: the developer lab

**In one sentence:** McKinsey ran a controlled lab experiment with more than 40 of its own developers across the United States and Asia, comparing AI-assisted and unassisted work on generation, refactoring, and documentation tasks.

- The lab enrolled more than 40 McKinsey developers in the United States and Asia with varied software development experience, and continues as an ongoing test bed for new tools.
- Participants performed common tasks in three areas — code generation, refactoring, and documentation — over several weeks, with a test group using two generative AI tools and a control group using none.
- Each developer served in the test group for half the tasks and the control group for the other half, giving a within-subject comparison that controls for individual skill.
- Time measurement relied on self-recorded start times, end times, and break times, paired with per-task surveys of perceived complexity and developer experience.
- Output quality was judged two ways: human judge evaluations during code demos identified successful submissions, and automated open-source-platform reviews scored readability and maintainability and detected bugs.
- A demographics survey captured years of experience, expertise, and prior knowledge, and a post-experiment survey collected impressions of the tools across tasks.

## 03 — Where generative AI shined

**In one sentence:** The tools delivered their biggest wins on routine work, first drafts, and code updates, still helped developers push through complex unfamiliar tasks, and left developers markedly happier.

- Generative AI expedited manual and repetitive work such as auto-filling standard functions, completing statements as the developer types, and documenting functionality in a standard format from a prompt.
- Facing a blank screen, developers requested suggestions through a prompt window or inside their integrated development environment (IDE) and reported helpful starting points that broke writer's block and brought "flow" sooner.
- Participants making changes to existing code reported faster, larger edits when they prompted the tools effectively.
- On complex tasks the tools helped developers rapidly brush up on an unfamiliar code base, language, or framework, making them 25 to 30 percent more likely to finish within the allotted time (Exhibit 2).
- Developers who used both AI tools on a task, rather than just one, gained an additional time improvement of 1.5 to 2.5 times.
- Developers with AI assistance were more than twice as likely to report overall happiness, fulfillment, and a state of flow, a morale effect the article ties to retaining talent (Exhibit 3).

## 04 — Where humans still matter

**In one sentence:** The tools are only as good as their users, so developers must still hunt AI-introduced bugs, supply project-specific context, and steer the trickier judgments the tools cannot make.

- Participant feedback identified three areas where human oversight and involvement were crucial, summarized by the article as proof that tools match the skill of the engineers using them.
- AI assistants sometimes gave wrong coding recommendations and even introduced errors, forcing one developer into many corrective prompts and another to "spoon-feed" the tool to debug correctly.
- Off-the-shelf tools lack knowledge of a specific project's integration needs, performance and security requirements, and end-user goals, so developers must inject that context through prompting.
- Developers must specify how the code will be used and by whom, which interfaces and systems it touches, and what data it uses — details no general model can infer alone.
- A third oversight area, opening with the words "Navigating tricky," was confirmed to exist but its exact content could not be recovered from any retrieved extract.
- Junior developers were the sharpest illustration of the skill dependency, taking 7 to 10 percent longer on some tool-assisted tasks because they lacked the foundations to steer and check the output.

## 05 — Four priorities for technology leaders

**In one sentence:** Leaders should train developers in prompting and risk awareness, chase use cases beyond code generation, plan for shifting skill needs, and install governance for privacy, legal, ethical, and security risks.

- The article prescribes a structured approach of training and coaching, use case selection, workforce upskilling, and risk controls, operationalized as four priorities: skill development, advanced use cases, skill shifts, and risk management.
- Initial training must cover prompt engineering through hands-on exercises, plus workshops on data privacy, intellectual-property issues, and how to review AI-assisted code for design, functionality, complexity, standards, and quality.
- Developers with under a year of experience need extra coursework in syntax, data structures, algorithms, design patterns, and debugging, followed by ongoing senior coaching and community channels for sharing examples.
- Using both AI tools together on a task delivered 1.5 to 2.5 times more time improvement than using one, which motivates pursuing combined and advanced use cases beyond plain code generation.
- Freed capacity should be redirected deliberately, for example toward business expansion or more frequent product updates, with developers building new design and architecture skills to fill emerging gaps.
- Governance must confront four named risks: data privacy and third-party security exposure via prompts, legal and regulatory change such as the General Data Protection Regulation (GDPR), ethics and reputation around copyrighted or contested code, and security vulnerabilities in generated code.

## The argument in five moves

1. Generative AI lets developers finish routine coding tasks up to twice as fast without losing quality.
2. Gains shrink on complex work and vanish for juniors, so skill gates the benefit.
3. The wins cluster in repetitive work, first drafts, updates, and unfamiliar-territory ramp-up, plus higher morale.
4. Humans must still debug AI errors, supply organizational context, and make the hard judgments.
5. Leaders must therefore train, extend use cases, reskill, and govern four concrete risks.
