# Plain-language explainer — AI in software development: interview with Jellyfish CEO Andrew Lau

## What it is

A December 2025 McKinsey interview with Andrew Lau, the head of a company called Jellyfish that measures how software teams work. Two McKinsey consultants ask him how artificial intelligence (AI) is changing the way software gets built and how companies can tell whether those tools are actually helping.

## Why it matters

Every company is buying AI coding assistants right now, but most see only modest speedups. Lau argues the real prize — more than doubling output — goes only to organizations that change their workflows, roles, and measures end to end. For anyone deciding where AI investment goes, the interview reframes the question from which tool to buy to how the whole operation must adapt.

## How it works

Think of software delivery as an assembly line with stations for planning, writing code, reviewing it, testing it, and releasing it. Today's AI tools mostly speed up one station: writing code. Lau's core point is that a faster station does not speed up the line — the pileup just moves to the next station, such as code review or testing. So he proposes measuring in three layers: first whether people actually use the tools, then how fast work flows through every station, and finally whether the business itself benefits through faster road maps, fewer bugs, and happier customers. Transformation itself comes in three stages — training people, matching the right tools to each codebase, and finally redesigning jobs and incentives — and the last stage is the hardest, especially for older companies with established habits.

## Where it is used

The ideas apply to any organization building software with AI assistance, from startups that can shape roles freely to large regulated firms that must prove every change is safe. The testing discussion matters most for companies with old systems lacking written specifications, and the review discussion for teams drowning in AI-generated code that still needs human sign-off.

## Takeaways

The life cycle of software development will look unrecognizable within three years. Broad but shallow AI use yields roughly a quarter more output, while near-total adoption can more than double it. Faster coding without pipeline-wide measurement just relocates the bottleneck. The next advances will come in AI-assisted review, agent coordination, and testing. And the most valuable human skill shifts from writing code to describing precisely what should be built.

## Jargon decoder

- Software development life cycle: the full journey of software from idea and requirements through coding, testing, release, and monitoring.
- Product development life cycle (PDLC): McKinsey's term for the same end-to-end flow, emphasizing the product view.
- Pull request: a developer's proposal to merge new code into the shared codebase; its rate and speed are common flow metrics.
- Cycle time: how long a code change takes from first draft to accepted merge.
- CI/CD: automated practices that continuously integrate, test, and deliver code changes.
- IDE: the editor environment where developers write code, now with built-in AI assistants.
- Spec: the written description of what software should do — Lau's candidate for the core human artifact.
- Systems thinking: treating the pipeline as one connected flow instead of optimizing each station alone.
- Independent validator: a checker separate from the code's author, required by regulators — an open question is whether an AI agent can play that role.
