# Natural Language Knowledge Graph Query Execution: Leveraging Controlled Semantics in the LLM Context Window

**Paper:** [arXiv:2609.14652v1](https://arxiv.org/abs/2609.14652v1) — arXiv, 2026

## Human Readable TL;DR

Asking a database a question in plain English is like asking a librarian for a book when you only know a vague description, and the librarian has to guess which shelf and catalog code you mean. This paper argues the fix is to hand the librarian a precise, fully labeled map of the library inside every request, so words like author, venue, or year already carry exact machine-readable meanings instead of being guessed from prose. It does this by putting the complete domain ontology into the language model's context window and generating the database query in one shot, adding a clean translator layer when the underlying database uses messy or cryptic names. The result is much more reliable question-to-query translation, reaching about 90% on a thousand-question bibliography benchmark and near-perfect scores in two other domains.

## TL;DR

NLKGQ executes natural-language questions over knowledge graphs with single-call, zero-shot SPARQL generation in which the system prompt carries SPARQL instructions, the complete domain OWL ontology, a small domain-specific rider, and the user question, with model output stripped of fences and reasoning traces before execution. Its central claim is controlled semantics: formally typed ontology tokens with declared domain and range, class hierarchy, and ObjectProperty versus DatatypeProperty distinctions map directly onto query patterns and transfer concepts more effectively than informal schema dumps, fine-tuning, agentic exploration, or retrieval pipelines. For uncontrolled vocabularies it introduces wrapper ontologies that present a clean, readable, typed namespace to the model plus a deterministic SPARQL-to-SPARQL rewriter to native predicates and patterns before execution on the unchanged endpoint, including a DBLP plus OpenCitations federation and a flattened SemOpenAlex vocabulary. Evaluated with Qwen3.6-27B at temperature 0.0 on QLever, the approach scores 89.9% Match and 81.3% Exact on the revised 1,000-question DBLP-QuAD 3.1, 98/100 on SemOpenAlex against a published 86/100 baseline, and 100% on 21 neuroimaging competency questions, with the wrapper alone contributing about 25 Exact-match points on DBLP.

## Problem & Motivation

Large language model applications usually transfer domain concepts informally through prompt prose, schema dumps, and examples, leaving the model to invent relationships and conventions when it writes database queries. The paper shows how brittle this is on real vocabularies, where native DBLP makes no lexical distinction between a venue name returned as a plain string and a venue returned as a URI, and where prior work compensates with fine-tuning, multi-call agentic exploration, or retrieval-augmented pipelines. This matters because memorization confounds many results on well-known graphs such as Wikidata, while less-memorized graphs such as DBLP make the context window the model's only source of schema knowledge and therefore a stricter test of generalization. The motivation is sharpened by an early controlled-domain result on neuroimaging metadata, where a purpose-built ontology achieved 100% on 21 competency questions against 43% for SQL from an auto-generated schema, rising only to 57% even with ontology annotations in column comments.

A second motivation is benchmark reliability. DBLP-QuAD 2.0, a 5,000-pair log-derived question-to-SPARQL set evaluated on 1,000 test questions, contains pervasive non-determinism and reference defects, including LIMIT without ORDER BY in most references, ambiguous machine-generated questions, echo queries, wrong predicates, missing grouping, and undocumented dependence on OpenCitations data. The paper argues these defects dominate measured performance, with re-executed references varying by several Match points run to run and graded F1 scores reflecting reference quality rather than system quality, which motivates both the method and a deterministic revision of the benchmark.

## Main Original Ideas

1. **Controlled semantics in the context window:** schema tokens in the prompt carry declared, machine-readable meaning through the full OWL ontology, including explicit domain and range, class hierarchy via `rdfs:subClassOf`, property typing as `owl:ObjectProperty` versus `owl:DatatypeProperty`, human-readable annotations, and semantically descriptive naming, so the model maps typed terms directly to joins, filters, and class coverage without enumerating cases.

2. **Single-call zero-shot NLKGQ mechanism:** one deterministic LLM call combines SPARQL instructions, the complete ontology, a domain rider, and the user query, with output cleaning before execution and no fine-tuning, few-shot examples, or entity linking, making the ontology rather than prompt cleverness the main carrier of domain knowledge.

3. **Wrapper ontologies with deterministic rewriting:** a clean namespace with readable typed terms is presented to the model and then mechanically rewritten to native forms before execution, where one wrapper term can expand to several triples, extending controlled semantics to opaque or federated stores such as DBLP plus OpenCitations and flattened SemOpenAlex intermediaries without changing the endpoint.

4. **Domain rider as stable-conventions channel:** the rider holds only small, stable query conventions while vocabulary belongs in the ontology, with the explicit finding that using the rider for incremental concept repair degenerates into ineffective prose patching, summarized as rider additions approaching zero sum as the rider matures.

5. **DBLP-QuAD 3.1 deterministic benchmark revision:** a repair of QuAD 2.0 that preserves intent and provenance with per-case logs, removing non-deterministic LIMITs, scoping under-constrained queries, fixing predicates and aggregations, replacing echo queries, rewriting unnatural questions, scoping entity resolution with bracketed URIs, and documenting the combined DBLP plus OpenCitations snapshot with a self-contained release and QLever instance.

6. **Formal-transfer hierarchy and concept smearing:** the stated ordering of formal concept transfer above model architecture above model scale above prompt engineering, paired with the observation that natural-language prompt tokens are semantically wide while formal tokens are narrow, so prose fixes behave like whack-a-mole and shift untargeted queries even at temperature zero.

## Key Findings

On the DBLP progression with Qwen3.6-27B, moving from the defective QuAD 2.0 to the deterministic QuAD 3.1 transforms measured performance from roughly 53% Match and F1 scores near 17% to 89.9% Match, 81.3% Exact, and SPINACH F1 near 79% in the wrapper configuration, with the paper attributing most of the roughly 61-point F1 swing to deterministic references rather than to a stronger generator. The wrapper ablation is large and consistent, lifting Exact match from 56.0% native to 81.3% wrapper and Match by about 15 points on QuAD 3.1, with the advantage already visible before benchmark repairs, while the neuroimaging ablation shows the same dependence on formalism by dropping from 100% with full OWL to 81% without comments and to 5% as bare graph structure. Cross-domain results strengthen the generality claim because the same single-call setup reaches 98/100 on SemOpenAlex and 100% on neuroimaging metadata, although the DBLP baseline comparison carries the caveat that the cited agentic baseline was measured on the earlier template-generated benchmark rather than on QuAD 3.1.

The ten-model sweep finds the two strongest dense models converging near 90% Match, with Gemma-4-31B leading narrowly on Match while Qwen3.6-27B leads on Exact and both F1 scores, alongside notable scale and architecture effects such as Mistral-Small-24B outperforming a much larger Llama model and FP8 quantization matching full precision. Failures concentrate in interpretable categories rather than random generation errors, including citation queries beyond the 71% OpenCitations mapping coverage, federated calls outside the wrapper vocabulary, differently structured aggregations, timeouts, ontology-introspection queries, and a long tail of heterogeneous cases. Related-work and formalism comparisons frame these results as evidence that schema injection and typed representations matter more than model choice alone, with SPARQL substantially outperforming SQL on the same ontology and data and fine-tuning succeeding on readable vocabularies while failing on opaque ones.

## Suggestions & Future Directions

The paper's limitations point toward evaluating the wrapper-versus-native ablation across more models rather than a single primary model, running the full model sweep in both vocabulary configurations, and including proprietary models alongside locally served open-weight systems. It leaves open the scaling question of placing a full ontology in every call, suggesting future work on retrieval, partitioning, or context-window scaling for larger schemas, as well as automated or semi-automated wrapper construction to replace the current manual design effort. Entity resolution is explicitly out of scope and remains a natural complement, alongside improved handling of federated queries, citation coverage, aggregation robustness, and ontology-introspection questions that the current error analysis isolates. Finally, the benchmark moral is that defective references can move headline scores by tens of points, so the paper implicitly calls for deterministic evaluation design, archived dumps and endpoints, logged repairs, and stricter metrics such as Exact match alongside superset-tolerant Match in future question-to-query benchmarks.
