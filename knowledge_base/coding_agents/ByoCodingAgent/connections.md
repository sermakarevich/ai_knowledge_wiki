# Connections

- [[research/Harness/summary|Harness — Rust Control Plane for AI Agent Fleets]] — Same-problem-different-scope: majiayu000/harness is a production-grade Rust control plane (task/turn lifecycle, Starlark policy engine, multi-agent adapters, workflow runtime) for the same core loop ByoCodingAgent teaches in ~7k lines of Go — read together to see how far the same abstractions (provider seam, tool registry, approval gating) scale from a teaching artifact to a fleet-grade system.
- [[research/OsmaniHarness/summary|Agent Harness Engineering (Addy Osmani)]] — Applies-in-practice: Osmani's "Agent = Model + Harness" framing, the ratchet principle (every failure becomes a permanent rule), and context-rot defenses describe in the abstract exactly what ByoCodingAgent implements concretely — its `SafeSplitPoint` tool-pair-safe compaction and deny-by-default `Confirm` gate are working instances of the guides/sensors split Osmani describes.
- [[research/AmuxHarnessGuide/summary|Harness Engineering: The Complete Guide (amux.io)]] — Applies-in-practice: same Agent = Model + Harness thesis and ratchet principle as OsmaniHarness, but framed as a path from a lean CLAUDE.md to a multi-agent orchestration platform; ByoCodingAgent sits at the lean end of that path — one agent, one provider seam, human-approval-only, no ratchet automation.
- [[research/Superharness/summary|superharness]] — Same-problem-different-scale: Superharness coordinates several external coding-agent CLIs with a SQLite-backed queue and crash recovery, while ByoCodingAgent is the single-conversation harness one of those CLIs would be — contrast a teaching-scale `Agent` loop with MaxTurns against a fleet-scale supervisor with lifecycle gates and watchdogs.
- [[research/GasTown/summary|GasTown]] — Same-problem-different-scale: another Go codebase in this KB, but GasTown orchestrates multiple external coding-agent harnesses in git worktrees with beads-backed tracking, whereas ByoCodingAgent is the single in-process harness being orchestrated, not the orchestrator.
- [[research/NaturalLanguageHarnesses/summary|Natural-Language Agent Harnesses]] — Contrast-in-design: NLAH externalizes harness policy into editable natural-language documents run by a shared runtime, the opposite of ByoCodingAgent's approach of hard-coding policy (MaxTurns, approval defaults, compaction thresholds) directly in Go — useful contrast when asking "how much of this harness's behavior could move out of code and into an editable policy document?"
