# My LLM coding workflow going into 2026 | AddyOsmani.com

**Article:** [My LLM coding workflow going into 2026](https://addyosmani.com/blog/ai-coding-workflow/) — AddyOsmani.com, 2026

## Human Readable TL;DR

Think of the AI as a super-fast but overconfident junior developer who needs a clear blueprint, constant check-ins, and a safety net. The workflow starts by sketching the blueprint together with the AI before any code is written, then building the house one small brick at a time with tests checking each brick. Along the way the human stays in charge like a film director, giving the AI a style guide to follow, reviewing every scene, and saving progress constantly so any bad take can be rewound.

## TL;DR

The article lays out a disciplined, human-supervised workflow for AI-assisted coding built around spec-first planning, small iterative implementation chunks, and verification at every step. It covers using CLI agents (Claude Code, Codex CLI, Gemini CLI) and asynchronous cloud agents (Jules, Copilot Agent) grounded in specs and plans, with the human reviewing line by line, enforcing test-driven loops, and using frequent git commits, branches, and worktrees as safety nets. It further argues for tuning the model with rules files (CLAUDE.md, GEMINI.md), custom instructions, and examples, backed by CI, linters, and review bots, framing the whole approach as AI-augmented rather than AI-automated software engineering in which classic practices like design, testing, and version control matter more, not less.

## Problem & Motivation

LLM programming is powerful but difficult and unintuitive: models write with complete conviction even when producing bugs or nonsense, and diving straight into code generation on a vague prompt routinely yields a jumbled, inconsistent mess that is painful to untangle. At the same time, adoption is already intense — the article notes that around 90% of the code for Claude Code itself is now written by Claude Code — so the practical question going into 2026 is not whether to use AI coding tools but how to use them without surrendering quality, coherence, or accountability. The motivation is therefore to turn raw generation speed into reliable engineering velocity by pairing the model's strength at quick, contained tasks with human judgment, clear direction, and automated guardrails.

## Main Original Ideas

1. **Specs before code, then bite-sized plans.** Brainstorm the requirements conversationally with the LLM, having it ask clarifying questions until edge cases are covered, then compile a comprehensive spec.md with requirements, architecture decisions, data models, and testing strategy. Feed that spec into a reasoning-capable model to produce a mini design doc of bite-sized milestones, iterating and asking the model to critique it until coherent, in what Les Orchard is quoted as calling a rapid waterfall-in-15-minutes phase that aligns human and model before coding begins.

2. **Small iterative chunks with prompt plans.** Implement strictly one focused step at a time — prompt, code, test, then move on — because large monolithic requests produce inconsistency and duplication, described as being like ten developers working without talking to each other. A structured prompt-plan file with a sequence of per-task prompts, executable one by one in tools like Cursor, enforces these small loops, reduces catastrophic errors, and pairs naturally with generating tests per piece.

3. **Supervised agents across the lifecycle.** Use in-directory CLI agents for reading files, running tests, and multi-step fixes, and asynchronous cloud agents that clone the repo, work in the background, and return a PR with code plus passing tests, always grounded by loading the spec or plan into context first. Orchestration tools can run several agents in parallel, but the recommended default is one main agent plus a secondary reviewer, since parallel threads are mentally taxing and these remain power tools where the human controls the trigger.

4. **Verify everything: test, review, stay accountable.** Treat every AI snippet as junior-developer output that must earn its way in, instructing the agent to run the test suite after each task and debug failures, and reviewing generated code line by line with extra scrutiny because it can be superficially convincing while hiding flaws. A second AI session or a different model can serve as critic, runtime bridges like the Chrome DevTools MCP give agents eyes on the DOM, traces, and logs for UI diagnosis, and only code the human understands gets merged, with explanatory comments or rewrites demanded for convoluted output.

5. **Version control as an undo button and steering aid.** Commit early and often — even more than in hand-coding — with clear messages after each tested chunk, treating commits as save points in a game so any sideways AI change can be reverted or cherry-picked without losing hours. A tidy history of small commits also becomes AI context, since models parse diffs well and can use logs and bisect to locate regressions, while branches or fresh git worktrees per feature let parallel AI sessions run without interference and failed experiments be discarded cleanly.

6. **Onboard the AI like a new hire with rules and examples.** Maintain periodically updated rules files such as CLAUDE.md and GEMINI.md with project style, lint rules, banned functions, and preferences like functional over OOP, plus short global custom instructions in Copilot and Cursor, so suggestions match team idioms instead of default style. Prime by mimicry with one or two examples, showing how X was implemented and asking for Y in the same vein, and prepend truthfulness and explanation rules such as asking for clarification rather than hallucinating and narrating bug fixes briefly in comments.

7. **Automation as the strict teacher over the AI's shoulder.** Require CI on every commit and PR, enforced style checks, and ideally staging deployments, then feed failures back verbatim into the model for correction and route reviewer-bot comments back as refactor prompts, preferring agents that refuse to declare done until tests pass. This discipline compounds with continuous learning: solid fundamentals, clear specs, and reviews become more powerful with AI while weak foundations risk amplified confusion, so the workflow calls for studying AI output, asking it to explain rationale and compare trade-offs like an encyclopedic mentor, and periodically coding without AI to keep raw skills sharp.

## Key Findings

The central finding is that upfront planning pays off enormously and scope discipline determines success: contained tasks with a shared spec produce smooth, testable progress, while huge single-shot generations consistently degrade into duplication, mismatched names, and incoherent architecture. Practitioners with strong testing, review, and git habits extract the most from agents, since a good test suite lets agents fly while its absence lets them blithely claim success after breaking things, and small per-chunk commits make breakage localizable in a way one giant AI-changes commit never does. Tuning matters more than most developers assume: a little upfront investment in rules files, custom instructions, and examples keeps the model on track and reduces off-script output, and feeding tool output such as test logs and linter errors back into the chat reliably drives correction. The cautionary thread is that AI amplifies the engineer's existing level, rewarding senior skills in design, complexity management, and judgment while punishing hands-off generation, which is why the author insists on remaining the accountable engineer and senior developer in the loop.

## Suggestions & Future Directions

The article points toward more tests, more monitoring, and more automation around AI-written code going into 2026, including AI-on-AI code reviews in which a second model catches what the first missed. It recommends standardizing rules files, custom instructions, truthfulness clauses, and example-driven priming across projects, tightening the loop so every commit and PR runs tests, style checks, and staging with failures routed back to the agent. It also advocates deeper agent integration with runtime observability, worktree-based isolation for parallel experiments, and deliberate skill upkeep through reviewing AI code and periodic unassisted coding, alongside a forthcoming AI-assisted engineering book with O'Reilly whose free tips extend the workflow. The overarching direction is AI-augmented rather than AI-automated software engineering, with the human engineer as the director of the show.
