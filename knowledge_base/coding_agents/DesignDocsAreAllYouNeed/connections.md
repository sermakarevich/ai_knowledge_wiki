# Connections

- [[../AutonomousLongRunningCodingAgents/summary|Autonomous Long-Running Coding Agents]] — Same orchestration problem from the agent side: long-horizon coding agents decomposing work, scheduling subtasks, and recovering from failure. SMART's per-doc subagent + topological scheduler + struggle-log is a concrete instance of that pattern with an added feedback instrument (friction log → spec refinement) worth importing.
- [[../AgentSkillsCanBeHarmful/summary|Agent Skills Can Be Harmful]] — Directly relevant counter-evidence to SMART's core bet: that paper confirms 307 cases where skill/instruction content *caused* agent failures, mostly via agents over-trusting examples as requirements. SMART's worked-example doctrine assumes examples guide correctly; read both together — examples need the reconciliation-anchor discipline precisely because examples can mislead.
- [[../../research_topics/coding_agents/SpecDrivenDevelopment|Spec-Driven Development]] — Shares the "specification as durable artifact" philosophy at the single-task level (spec → plan → implement); SMART extends it to repository scale with regeneration-from-scratch and machine-discovered dependency structure. Natural companion for comparing spec-discipline practices.
- [[../../research_topics/coding_agents/EvaluatingAgentsMdAreRepositoryLevelContextFilesHelpfulForCodingAgents|Are Repository-Level Context Files Helpful for Coding Agents]] — Studies whether repo-level instruction files (AGENTS.md/CLAUDE.md analogues of SMART's design docs) actually help coding agents; provides the empirical lens SMART lacks for its own doc-quality claims.
- [[../../research_topics/llm_theory_and_multimodal/tutorials/llm_blocks/06_mlp_and_moe|MLP and MoE (LLM Blocks tutorial)]] — Background on the Mixture-of-Experts routing and expert-parallel communication patterns behind SMART's flagship validation cases (DeepSeekV3/MoE serving) and the dispatch/combine `all_to_all` discussion.
