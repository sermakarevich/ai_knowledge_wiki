# Give your agent a laboratory
**Article:** [Give your agent a laboratory](https://brianlovin.com/writing/give-your-agent-a-laboratory-jH5ryjC) — Brian Lovin, Writing, Jan 14, 2026

## Human Readable TL;DR
Think of a coding agent like an apprentice chef who keeps asking you to taste every dish because they are not allowed in the kitchen to taste it themselves. The article argues that the fix is not better-worded recipes but giving the apprentice their own tasting spoons and timers, a little laboratory where they can check their own work. One example is a performance lab with stopwatches and before-and-after charts, and another is a design lab where the agent screenshots its own web page and compares it side by side with the Figma mockup until every spacing and color detail matches. Once a workflow like that proves itself, you save it as a reusable recipe card (a skill) so the agent can rerun it on its own next time.

## TL;DR
Coding agents in January 2026 are only as good as their feedback loop, so the highest-leverage prompting move is to give the agent tools and scaffolding to view, measure, and verify its own work rather than refining prompt wording. Vague asks like "make it faster" or "implement this design" fail through short effort, constant verification requests, and regressions, while laboratories — a benchmark-driven performance loop and a screenshot-driven Figma refinement loop — turn them into self-correcting workflows. Discovered workflows that work should eventually be encoded as reusable skills, commands, or subagents in `./claude/skills`, but only after enough repetitions to develop a feel for how much scaffolding each kind of task needs.

## Problem & Motivation
The core frustration the piece addresses is that most agent prompts are vague outcome wishes — "make it faster, find bugs, refactor the code, simplify the design" — and they produce predictably disappointing behavior: the agent works only briefly, keeps asking the human to check its work, or fixes one thing while quietly breaking something elsewhere. The author's claim is that prompt wording is a secondary concern and the real bottleneck is the absence of a verifiable loop, meaning the agent has no way to see, measure, or test what it just did. This motivates a shift in mental model away from writing cleverer instructions and toward building the agent a laboratory first, with the standing rule that whenever the agent asks the human to do something manually, the human should stop and think hard about how to give the agent the tools to do that thing by itself.

## Main Original Ideas
1. **Feedback loop over wording:** the central thesis is that coding agents are only as good as their feedback loop, so every serious task should begin by giving the agent the ability to view and verify its own work. This reframes prompting skill as laboratory design rather than prose craft, and it explains why terse prompts keep failing regardless of model cleverness.
2. **The performance laboratory:** for "the app is slow" work, the article prescribes a four-phase scaffold of instrumentation (benchmark harness, timing utilities, Chrome Devtools MCP console-time markers and traces, recorded baselines for critical paths), diagnosis (benchmark analysis into a top 3–5 bottleneck list with causal hypotheses and web-searched library gotchas), iteration (one hypothesis at a time with re-benchmarking, test checks, and a commit per win), and reporting (an HTML before/after report with charts), bounded by flagging large architectural changes instead of attempting them silently.
3. **The visual-laboratory refinement loop:** for Figma-to-code work, the article replaces "implement this design" with a loop that pulls the design via Figma MCP, builds an admittedly wrong first pass, and then iterates screenshot-via-Chrome-Devtools-MCP, comparison against the Figma source, exhaustive difference listing across spacing, color, typography, radius, shadows, borders, alignment, and responsive behavior, and one-by-one fixes until no differences remain. The stated quality bar is deliberately obsessive, holding that the gap between "close enough" and "correct" is where polish lives, with a fallback to asking the human when something is ambiguous or impossible as specced.
4. **Reps before skills:** the article adds a meta-practice of not formalizing too early, urging practitioners to get repetitions first to build intuition for how much scaffolding different jobs need, and then to distill proven workflows into reusable skills, commands, or subagents. It even supplies a verbatim prompt for that distillation step, asking the agent to create a clearly named and described skill in `./claude/skills` from everything learned in the conversation so the exact workflow can be rerun later.

## Key Findings
The performance-laboratory pattern converts a one-shot "audit and speed up" request into a disciplined empirical cycle where baselines make regressions visible, single-variable iteration makes wins attributable, and per-win commits preserve cherry-pickable progress. The visual-laboratory pattern similarly converts pixel-polish from a matter of taste into a mechanical convergence loop, where the browser screenshot is the ground truth and the difference list is the work queue, so the agent can keep improving without human eyeballs in the loop. Across both examples the article finds that verbosity requirements are task-dependent and should shrink as models improve, which is why it pairs the heavyweight examples with pragmatic notes on using a dictation app like Monologue to lower the cost of detailed prompting in the meantime.

## Suggestions & Future Directions
The practical recommendation is to treat every manual verification request from the agent as a tooling gap to close, whether that means wiring up benchmarks, browser inspection, or design-source access before touching product code. Practitioners are advised to calibrate scaffolding weight through repetition rather than defaulting to maximal ceremony, and to invest in learning how their agent stack handles skills, commands, and subagents so successful laboratories become durable defaults. The piece gestures forward to a near future where improving models reduce the need for verbose prompting, and it cross-links a companion idea in "Give your agent a stopwatch" for readers who want to continue down the measurement path.
