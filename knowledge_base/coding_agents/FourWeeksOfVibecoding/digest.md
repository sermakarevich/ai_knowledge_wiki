# 4 Weeks of Vibecoding: What I Built, What I Learned, and… | Pokharna Talks — Digest

## 1. [[wiki/01-vibecoding-definition-and-built-projects|Vibecoding Is Not Coding. It Is the Wrong Word.]]

**In one sentence:** Vibecoding is not writing code but specifying vision, problem understanding, and exact desired behaviour in detail for AI coding tools to execute — proven by a complete non-coder shipping four live projects in four weeks.

## Key points

- On February 12, 2026 the author could not set up a GitHub repo, had never used a terminal to push code or written a commit message; by March 12 he had 197 commits across multiple live projects.
- Prior background was a decade building coliving companies, advising 70+ operators across 14 countries, and running a 36,000-subscriber newsletter — with zero shipped lines of code.
- Definition: "You do not write code. You write the details of how you want things to be done and what exactly you want them to do. The AI coding tools just execute."
- The author does not know JavaScript, TypeScript, Prisma, or why Next.js has an "App Router" — but knows the domain: listing fields, admin permissions, discovery-to-booking journeys, SEO architecture.
- BookMyColiving.com: two-sided marketplace with 3 user roles (tenant, operator, admin), moderation workflows, messaging, reviews, lead management, CSV exports, 2,500+ SEO pages; built on Next.js, TypeScript, Prisma, PostgreSQL, deployed on Vercel.
- EverythingColiving.com rebuild: from 170+ pages to a planned 300+ pages, plus 15 interactive operator tools, a vendor directory, an operator directory, a markets section, and a free templates library.
- JumboTiger: a complete PRD written as a Claude Code execution document (architecture, module deep dives, design system, technical specs, content strategy), precise enough to build without a single clarifying question.
- Process: product requirements spoken into a voice memo app (while walking/driving/between calls), transcribed and structured by AI into a specification, then fed to Claude Code — a detailed prompt becomes a live feature within hours instead of a Jira ticket sitting in backlog for weeks.

## 2. [[wiki/02-lessons-limits-and-takeaway|The Real Takeaway]]

**In one sentence:** Vibecoding success comes down to intent — knowing what you want to build and describing it precisely — not to technical skill or AI tools.

## Key points

- The chunk frames the story explicitly as "not a story about AI tools" but "a story about intent."
- It lists common reasons for not starting — not knowing how to code, how to set up a repository, how to understand the technology — and declares them "all valid" but "all irrelevant now."
- It states the only thing that matters is whether you know what you want to build and are willing to describe it precisely enough for it to get built.
- It rejects technical vs. non-technical as the dividing line, replacing it with clarity vs. lack of clarity on what needs to exist.
- The author self-describes as a zero-technical ex-founder turned freelancer turned entrepreneur again with 11 years in coliving who "could not write a for loop."
- The author claims that in four weeks he shipped more product than in the previous two years combined.
- It closes with a direct call to action: "Start. The tools are ready. The question is whether you are."

## The argument in five moves

1. A complete non-coder goes from zero (no repo, no terminal, no commits) to 197 commits and multiple live projects in four weeks.
2. Vibecoding is therefore redefined: not writing code, but specifying vision, problem understanding, and exact desired behaviour for AI tools to execute.
3. Domain expertise substitutes for syntax knowledge — listing fields, permissions, user journeys, and SEO architecture become the specification.
4. The working method is spoken requirements (voice memos while walking/driving) turned into structured specs, so a detailed prompt becomes a live feature within hours instead of a backlog ticket.
5. The proof is shipped product: a full marketplace, a large rebuild with operator tools and directories, and an execution-ready PRD.
6. Hence the takeaway is intent over tools: the dividing line is clarity versus lack of clarity, so the only question left is whether you will start.
