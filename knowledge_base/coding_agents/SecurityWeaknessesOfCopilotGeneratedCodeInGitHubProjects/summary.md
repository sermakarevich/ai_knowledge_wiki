# Security Weaknesses of Copilot-Generated Code in GitHub Projects: An Empirical Study

**Paper:** [Security Weaknesses of Copilot-Generated Code in GitHub Projects: An Empirical Study (Fu et al., 2025)](https://arxiv.org/abs/2310.02059v4)

## Human Readable TL;DR

Imagine hiring a brilliant but hasty apprentice who learned carpentry by watching millions of backyard builders, including all their sloppy shortcuts. About one house in four that this apprentice helps build has a faulty lock, a shaky staircase, or an easily jimmied window, and the faulty houses average three defects each. The good news is like calling the apprentice back with a building inspector's checklist in hand: pointed at exactly what failed, the apprentice can fix more than half the problems, though some tricky wiring jobs still defeat them.

## TL;DR

This empirical study collects 733 Copilot, CodeWhisperer, and Codeium-generated Python and JavaScript snippets actually committed to GitHub projects and scans them with CodeQL plus language-specific analyzers (Bandit for Python, ESLint for JavaScript), followed by manual verification and CWE mapping. It finds that 27.3% of snippets contain security weaknesses (29.5% of 419 Python files and 24.2% of 314 JavaScript files), totalling 628 weaknesses across 43 CWE types and averaging about three weaknesses per vulnerable snippet, with CWE-330 (Use of Insufficiently Random Values), CWE-94 (Code Injection), CWE-79 (Cross-site Scripting), and CWE-78 (OS Command Injection) the most frequent and eight of the 43 types belonging to the 2023 CWE Top-25. On a 90-snippet subset holding 295 weaknesses, asking Copilot Chat to repair the code fixes 19.3% with the built-in `/fix` command, 31.8% with a basic security prompt, and 55.5% with an enhanced prompt that pastes in the static-analysis warning messages, with success varying sharply by CWE and language.

## Problem & Motivation

Large language model code assistants such as GitHub Copilot, Amazon CodeWhisperer, and Codeium generate functionally convincing code from prompts ranging from function names to natural-language comments, and evaluations report high validity rates such as 91.5% for Copilot alongside broad developer adoption since Copilot's 2021 launch. The security problem is that these models are trained on billions of lines of public open-source code that already contain unsafe patterns, with Copilot's underlying Codex model pre-trained on untrusted GitHub data known to hold buggy programs, so generated suggestions can inherit and propagate weaknesses, potentially even feeding back into future training data in a vicious cycle. GitHub places responsibility for security and quality on the user while Copilot's suggestion algorithms are incentivized toward acceptance rather than qualities like readability or safety, and Snyk reports suggest Copilot may replicate weaknesses already present in the user's codebase. Prior research emphasized correctness, developer experience, and controlled high-risk prompting scenarios such as Pearce et al.'s 89 cybersecurity scenarios with 40% vulnerable suggestions, leaving open how often real developers encounter weaknesses when they accept generated code in everyday open-source production, which this study addresses by mining GitHub for code explicitly attributed to these tools and checking it comprehensively across all CWE types.

## Main Original Ideas

1. **Production-grounded dataset of attributed AI-generated code** — Rather than prompting the model with risky scenarios in the lab, the authors query the GitHub REST API with constrained keyword combinations of {by, use, with} plus {GitHub Copilot, CodeWhisperer, Codeium} over Python and JavaScript, deduplicate 9,927 raw hits to 3,589 results, and manually filter them over two weeks with high inter-rater agreement (Cohen's Kappa 0.84, disagreements resolved by negotiated agreement) down to 116 fully-generated Repository-label projects and 335 Code-label files, yielding a curated and released dataset of 733 files (672 Copilot, 38 CodeWhisperer, 23 Codeium; 419 Python and 314 JavaScript) that reflects what developers actually commit, while characterizing project popularity (small, low-star, median zero, with the OnmyojiAutoScript outlier at 1,672 stars), file sizes (combined mean 183.38 lines of code, median 74), and six application domains from Game to Web Application to Utility Tool by author consensus.

2. **Dual-tool static analysis with manual CWE adjudication** — Each snippet is scanned with two analyzers (CodeQL security-and-quality suites with 168 Python and 203 JavaScript checks, plus Bandit's 73 default Python rules or ESLint's security plugins for JavaScript), counting only Warning and Error severities while ignoring style Recommendations, deduplicating overlapping reports and manually verifying every finding against line numbers and, for Code-label files, against surrounding comments proving AI generation (with Kappa 0.85 for Repository and 0.82 for Code labels). Because analyzer rules do not map one-to-one onto CWEs, two authors independently map each warning to a CWE identifier over ten days (Kappa 0.82, ties broken with a security-expert co-author) and publish the correspondences, enabling a full-spectrum count across all CWE types instead of only scenario-targeted ones.

3. **Copilot Chat in-the-loop repair experiment with graded prompts** — To test whether the same assistant family can clean up its own mess, the authors randomly select 50 Python and 40 JavaScript Repository-label snippets holding 295 known weaknesses (163 plus 132) and attempt repairs in Copilot Chat under three treatments on the weakness-containing function block: the built-in `/fix` slash command, a basic prompt asking whether a weakness exists and to return fixed code, and an enhanced prompt that declares the snippet is known-vulnerable and pastes in the analyzer warning messages, re-scanning each result at recorded positions to measure true fixes per prompt, language, and CWE.

## Key Findings

Around a quarter to a third of committed AI-generated snippets are vulnerable, and vulnerable snippets tend to carry multiple flaws. Of the 733 snippets, 200 (27.3%) contain at least one confirmed weakness, split into 124 of 419 Python files (29.5%) and 76 of 314 JavaScript files (24.2%), with 102 of those 200 (over half, or 13.9% of the whole corpus) holding more than one issue and 628 total weaknesses averaging 3.14 per vulnerable snippet (Python mean 3.12 with median 2, JavaScript mean 3.17 with median 1, maximum 22 in a single 1,595-line file), and vulnerable code concentrates in Utility Tools and Games for Python but in Web Applications followed by Utility Tools for JavaScript, a split the authors attribute to differing language purposes and to dynamic typing that lets the generator emit working code without reasoning over the whole program.

The 628 weaknesses span 43 distinct CWE types, led decisively by CWE-330 Use of Insufficiently Random Values at 114 instances (18.15%), then CWE-94 Code Injection at 62 (9.87%), CWE-79 Cross-site Scripting at 60 (9.55%), and CWE-78 OS Command Injection at 39 (6.21%), with a long tail of sub-one-percent types showing that weakness kinds track the scenarios where developers invoke generation. Severity is not merely theoretical because 233 instances (37.1%) fall into eight entries of the MITRE 2023 CWE Top-25, including high-ranking CWE-79 and CWE-78, while the absence of some other Top-25 entries suggests Copilot may already sanitize certain patterns, and rare-but-dangerous cases such as a single CWE-732 Incorrect Permission Assignment instance remind that non-Top-25 weaknesses remain exploitable. Language and domain signatures are sharp: Python's top five are CWE-330, CWE-78, CWE-427 Uncontrolled Search Path Element, CWE-457 Use of Uninitialized Variable, and CWE-772 Missing Release of Resource, reflecting data processing and system calls, whereas JavaScript's top five are CWE-94, CWE-79, CWE-22 Path Traversal, CWE-685 Function Call with Incorrect Number of Arguments, and CWE-770 Allocation Without Limits, reflecting Node.js file operations and dynamic execution, and within Web Applications JavaScript skews toward XSS while Python skews toward CWE-89 SQL Injection, with Network Communication code showing relatively fewer weaknesses, attributed to mature protocols and stricter standards.

Copilot Chat can fix a meaningful share of its own weaknesses, but only when given specific diagnostic context, and some injection flaws resist repair almost entirely. Over the 295-weakness repair subset, the `/fix` command resolves 19.3% (leaving 238), the basic prompt 31.8% (leaving 201), and the enhanced warning-fed prompt 55.5% (leaving 132), with the enhanced prompt lifting Python from 29.4% to 58.3% and JavaScript from 34.8% to 51.5%, erasing the small JavaScript advantage seen with `/fix` that the authors attribute to easier in-context tracing versus Python's system-call complexity. Gains are highly CWE-dependent: straightforward issues such as CWE-259 Use of Hard-coded Password, CWE-685, CWE-20 Improper Input Validation, and CWE-456 Missing Initialization reach 100% under the enhanced prompt, while CWE-78 OS Command Injection and CWE-284 Improper Access Control sit at 0% under all three prompts and CWE-94 Code Injection barely moves from 16.7% to 14.3% even with warnings, whereas context-hungry cases jump dramatically with detail, notably CWE-330 from 9.1% to 98.2% and CWE-79 from 0% to 70%, confirming that richer analyzer-derived context reduces ambiguity for some families but that complex injection and access-control logic still needs human review and design.

## Suggestions & Future Directions

The authors recommend continuous security analysis as standard practice for AI-generated code, meaning developers should routinely scan accepted suggestions with automated analyzers for known CWEs, feed precise warnings into Copilot Chat or another LLM for a first repair pass, re-analyze to confirm, and still perform manual security review with a gated check-in build for AI-originated code, since weaknesses appear in both languages and in certain suggestions but not all, so careful tool-assisted selection among alternatives matters. Prevention should be targeted and standardized at once: prioritize the dataset's high-frequency, language-specific risks such as path validation and dynamic execution in JavaScript versus system calls and library loading paths in Python, while using the CWE Top-25 list plus analyzer documentation and MITRE mitigations as an audit and remediation guide for common privilege-control and configuration flaws. For generation and repair alike, security must enter the prompt early through security-aware prompt patterns and joint security-utility instruction tuning, and developers should match the fix method to issue complexity by letting Chat handle standard access-control and configuration fixes quickly while reserving multi-layered input logic and injection-prone flows for human design, always supplying the chat model with specific warning text, surrounding context, and clear instructions rather than a bare fix request.
