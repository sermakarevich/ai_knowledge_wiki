# Connections

- [[coding_agents/HowAIAgentsSpendYourMoney/summary|How Do AI Agents Spend Your Money?]] — independently confirms the read-dominated cost structure this article relies on: that paper finds input-token accumulation (re-reading prior history on every step) drives ~1000x higher token consumption in agentic coding vs. single-round tasks, and that frontier models systematically underestimate their own usage. Prewalk's "the bill is essentially O(reads)" claim and its 9%-edit/91%-read split is the same phenomenon, reframed as a design lever (avoid re-reading via trajectory handoff) rather than just measured.
- [[agent_harness/ScalingLawsAgentHarnesses/summary|Scaling Laws for Agent Harnesses]] — proposes EFC (Effective Feedback Compute), crediting harness feedback only when informative/non-redundant/retained, as a far better fit (R²=0.99) for agent performance than raw token/tool-call counts. Directly relevant to why `/plan` fails: its handoff duplicates feedback the executor already effectively "has" via the frontier model's exploration, but discards it as a plan document instead of retained context — the EFC framework would predict low informativeness for that duplicated read.
- [[AgentAsARouter/summary|Agent-as-a-Router: Agentic Model Routing for Coding Tasks]] — addresses the adjacent but distinct question of *which* model should handle a given task (learned routing across a pool of models via a C-A-F bandit loop), whereas Prewalk addresses *how* to hand a single task off mid-trajectory between two pre-chosen models. Both attack the "smart-model-is-expensive" problem from opposite ends: Agent-as-a-Router optimizes model *selection*, Prewalk optimizes context *transfer* once a swap has been decided on.
- [[coding_agents/Composer2TechnicalReport|Composer2 Technical Report]] — a complementary strategy for the same underlying cost problem: Cursor's Composer 2 trains a mid-sized model (Kimi K2.5 + RL) to match frontier coding performance directly, avoiding the handoff question entirely by making the cheap model good enough on its own. Worth reading against Prewalk as an alternative solution — train a better cheap model vs. hand off a better context to an existing cheap model.
