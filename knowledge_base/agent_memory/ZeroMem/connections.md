# Connections

- [[agent_memory/GaamaGraphAugmentedAssociativeMemoryForAgents|GAAMA: Graph Augmented Associative Memory for Agents]] -- same-problem-different-method, closest relative: GAAMA also builds a graph over conversational history and evaluates on LoCoMo (78.9% mean reward on LoCoMo-10), but its concept-mediated hierarchical KG is built via LLM extraction of facts/reflections and retrieved with edge-type-aware Personalized PageRank -- specifically to avoid the "mega-hub problem" of entity-centric graphs like HippoRAG; Zero-Mem's entity-context graph is exactly the entity-centric design GAAMA sought to move away from (spaCy NER co-occurrence edges over context units), but it sidesteps the LLM-extraction cost entirely and instead controls hub effects through query-conditioned routing, evidence closure, and deterministic calibration rather than concept nodes and hub dampening.
- [[agent_memory/StructMem/summary|StructMem: Structured Memory for Long-Horizon Behavior in LLMs]] -- same-problem-different-method: StructMem also organizes memory hierarchically with temporal anchoring for LoCoMo (76.82% overall, strong on temporal reasoning) and prizes token efficiency (~18x fewer tokens, ~51x fewer API calls than a graph baseline), directly paralleling Zero-Mem's temporal hierarchy (turn/window/episode/local) and efficiency framing -- but StructMem still relies on LLM calls for dual-perspective extraction and periodic cross-event consolidation (1.937M tokens, 1,056 API calls), whereas Zero-Mem eliminates memory-operation LLM calls and tokens completely (0 vs. StructMem's non-zero budget).
- [[agent_memory/AnatomyOfAgenticMemory/summary|Anatomy of Agentic Memory]] -- contradicts/critiques the evaluation Zero-Mem relies on: this survey's empirical critique flags HotpotQA as "High" saturation risk (fits trivially in modern context windows) and LoCoMo as "Moderate," and shows F1/BLEU systematically diverge from semantic correctness (e.g., punishing correct-but-paraphrased answers); Zero-Mem's headline results are F1/BLEU-1 gains on precisely these two benchmarks, so this entry directly questions whether Zero-Mem's reported margins over GAM/CompassMem reflect genuine evidence-selection quality or benchmark/metric artifacts the anatomy paper catalogs.
- [[papers/AreWeReadyForAnAgentNativeMemorySystem/summary|Are We Ready For An Agent-Native Memory System?]] (unfiled -- still in the `papers/` staging area, not yet moved into `ai_papers/agent_memory/`) -- builds-on/validates-thesis: this 12-system benchmark's key findings -- "Representation Granularity: preserving usable evidence matters more than making memory compact" and "Late Filtering Principle: extraction should preserve context at write time rather than aggressively filter early" (its ablation shows *User-Only Raw* beats summarized/compressed variants on LoCoMo and LongMemEval) -- are close to Zero-Mem's central bet that keeping raw provenance-bearing traces (rather than generated abstractions) as the source of record improves fidelity; Zero-Mem can be read as a more radical instance of that same finding, pushed to zero generative extraction rather than just favoring raw-over-compressed within an LLM-based pipeline.
- [[agent_memory/StatelessDecisionMemory/summary|Stateless Decision Memory for Enterprise AI Agents]] -- shares-technique: both papers pursue determinism and provenance by removing incremental LLM-generated intermediate representations from the memory pipeline -- DPM replaces stateful summarization with an append-only event log plus a single temperature-0 LLM projection at decision time (deterministic replay, auditable rationale), while Zero-Mem's deterministic evidence calibration performs an analogous role using rule-based evidence-support/type/format checks instead of any LLM call; DPM still spends one LLM call per decision (plus the final reader), so Zero-Mem's "zero calls outside final QA" regime is a step further along the same axis DPM stakes out.
- [[agent_memory/GraphBasedAgentMemory/summary|Graph-based Agent Memory: Taxonomy, Techniques, and Applications]] -- same-problem-different-method / taxonomic context: this survey's lifecycle framework (extraction -> storage -> retrieval -> evolution) and its Knowledge Graph + Temporal Graph storage families map directly onto Zero-Mem's entity-context graph and temporal hierarchy, but Zero-Mem's "extraction" stage is unusual within the surveyed space -- non-generative NER-based node/edge construction rather than the LLM-based triple extraction the survey treats as standard, and it has no "evolution" stage at all since nothing generated ever needs reconciling.
