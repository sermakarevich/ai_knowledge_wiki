# agent_memory -- for engineers building agent second-brain systems

## What this means for you

- **Default to local-first, inspectable storage.** The viable pattern across all four lanes is plain Markdown files (Obsidian-compatible) plus SQLite/on-device indexes, with cloud or model calls confined to explicit opt-in edges such as transcription or enrichment.
- **Treat capture as a provenance-preserving pipeline, not filing.** Heterogeneous ingest lanes — subtitle-first platform capture via `yt-dlp`, clipboard capture with a keep-gate, Telegram voice/text via Deepgram transcription, direct Zotero-store indexing, folder-drop bulk builds — all record source identity at ingest time (URLs, digests, entry ids, file-and-page identity) and feed maintained indexes with dedup, retry, validation gates, and rebuilds.
- **Keep Markdown human-readable; put the graph beside it, not under it.** Durable memory compiles sources into interlinked Markdown plus a companion provenance layer: source/claim ledgers, tagged edges (`extracted`/`inferred`/`ambiguous`), contradiction flags, and evidenced edges with span, confidence, and asserting document.
- **Retrieve with hybrid, scoped, budgeted recall.** Every lane fuses lexical (BM25/FTS), vector, and graph signals (RRF, rerank, traversal, proximity weights) rather than flat chat replay or pure vector search. Scope recall by subtree, bank, team, or ACL boundary, and budget it with layered tiers (L0 abstract → L1 overview → L2 full) so agents judge relevance before loading full text.
- **Gate every graph write.** New links land through inspected transaction bundles, `compile --approve` staging with `lint --conflicts`, review-gated entity-resolution proposals, or suggestion-only Canvas verdicts — never silently.
- **Model time and staleness explicitly.** Attested mechanisms: freshness/review ledgers plus dead-link/orphan lint, freshness decay scoring (`freshness.defaultHalfLifeDays`), bi-temporal edges with contradiction invalidation and `as_of` queries, and Hot/Cold tiering from links plus recency.
- **Package action as skills over memory.** The shared harness idiom is skills-as-executable-markdown (e.g. a 33-skill vault catalog, a 20–21-skill plugin where each `SKILL.md` is the artifact with no build step), executed over the memory substrate with a brain-first read rule and citation conventions.
- **Separate lead reasoning from cheap data work, and checkpoint instead of replaying.** Delegated orchestration (lead/worker fan-out, parent/child agents, durable Team Runs over a shared board) plus checkpointed durability (goal checklists/leases/artifacts, thread checkpoints with exactly-once completion, `AC-n`-traced run ledgers) is the attested recovery model.
- **Route providers with failover; bound tools with approvals.** Ordered provider chains with health-tracked cooldowns, or side-by-side local Ollama plus provider keys/OAuth/custom endpoints, beat single-model pinning. Every harness bounds tools with manifests, RBAC/Tool Guard approval flows, path protection, work budgets, read-only verifiers, and audit trails.
- **Pick a deployment shape deliberately.** Attested options: zero-server Markdown plugins (personal state outside the repo), local desktop with OS-credential-store secrets, one-JAR/Docker self-hosted runtime over PostgreSQL, or a single user-owned Cloudflare Worker (D1 + Vectorize + Workers AI + KV) shared over REST and MCP.

## Decisions this informs

- **Store shape:** plain-file vault vs. relational/pgvector banks vs. virtual filesystem vs. file-backed SQLite vs. shared skill wiki — trade governance (ACLs, visibility boundaries, hash chains) against a minimal core.
- **Graph weight:** persistent typed graph with traversal queries vs. ledgers plus file links/MOCs vs. ephemeral suggestion-only Canvas links promoted to wikilinks.
- **Recall machinery weight:** four-strategy fan-out with cross-encoder rerank (heaviest) vs. scan-before-read tiers and progressive retrieval (lightest); keyless BM25 default with opt-in embeddings/LLM vs. LLM on every retain/recall/reflect path vs. embedding-only service with agent-side judgment.
- **Capture mouth and keep-decision:** OS clipboard, Telegram chat, platform subtitles, existing Zotero library, or bulk folder drops; human-gated per item vs. agent-classified vs. build-validated publishing; subtitle-first reuse vs. cloud transcription vs. local whisper/FunASR vs. structure-preserving Office/PDF renderers.
- **Gating and freshness math:** single-orchestrator transactions vs. compile-pipeline staging vs. suggestion-only verdicts; bi-temporal invalidation vs. decay half-life vs. live Hot/Cold vs. lint-reported staleness.
- **Harness coupling:** file-only skills riding the host agent (zero inference of their own) vs. self-hosted runtimes with provider failover vs. user-cloud Worker with pinned inference bindings.
- **Tenancy:** single owner-operator custody vs. personal↔team siblings with sensitivity tagging vs. multi-user workspaces with channel isolation vs. private-by-default with deliberate canonical moves to one shared layer.

## Risks and unknowns

- **Benchmark and outcome claims are weak or absent.** Recall lifts (LoCoMo 80–83% with 34–91% fewer tokens; claimed 95.2% R@5 with 92% fewer tokens; LongMemEval SOTA) are vendor-reported or snapshot claims with version discrepancies; the action-harness lane reports no task-success, latency, or precision figures at all — claims there are structural, not measured.
- **Engine internals are unverified.** Rust/C++ cores, index schemas, handler-level code, ranking formulas, and several `src/` internals were out of scope or truncated in the underlying summaries; CLI/behavior-level claims are stronger than engine-internals claims.
- **Local-first framing has exceptions.** OpenWiki's default-on Jina Reader/Google Translate calls weaken its local-first posture; file-only harnesses inherit whatever egress the host agent performs.
- **Ingest has known format gaps.** Chubbyskills PDF import is text-layer only with no OCR, so image-only scans fail at ingest; transcription quality splits across subtitle reuse, cloud, and local stacks with no head-to-head evidence.
- **Identity and dedup are not solved automatically.** Aliasing is configurable (frontmatter aliases, user-definable relation vocabularies, query-time synonym lists) with review-gated merges and opt-in LLM keep/fold/drop passes — expect curation work, not free dedup.
- **Provider and route details are partial.** Exact model IDs and full REST tables are marked unverified in places; LLM dependence ranges from required-on-every-path to forbidden-in-service, so latency, cost, and offline behavior vary sharply by choice.
