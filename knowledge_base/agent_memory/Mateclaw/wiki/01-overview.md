# Overview
**In one sentence:** MateClaw is a self-hosted, pluggable agent runtime ("second brain") that runs digital employees over native or DSH engines with multi-provider failover, linked knowledge/memory, tools, channels, and durable team execution in one deployment.
## Key points
- MateClaw positions itself as a whole-widget deployment — reasoning, knowledge, memory, tools, and channels built together in one deployment, with automatic retry on the next healthy provider when the primary model fails (01-overview.md:43-45, 01-overview.md:51-57).
- A provider health tracker parks failing vendors in a cooldown window and only returns an error when the available chain is exhausted; providers are ordered in Settings → Models (01-overview.md:55-57).
- The `AgentRuntimeProvider` contract separates employee identity from the execution engine, offering a native StateGraph runtime (ReAct, Plan-and-Execute, Goals, Team Runs) or a managed DSH (`dsh-jsonrpc-agent`) external loop over authenticated JSON-RPC with normalized runtime events (01-overview.md:41-42, 01-overview.md:94-95).
- Persistent Goals make long work recoverable: the database preserves checklist, continuation state, attempts, cooldowns, leases, and user input, and the supervisor reconciles interrupted attempts after a single-backend restart instead of repeating the task (01-overview.md:99-102).
- One durable Team Run (`runId`) links objective, task DAG, worker executions, synthesis, and deliverables, with chat as outcome surface, Agents Live for observation, and Teams for history/governance over a shared board with parallel dispatch, leases, cancel-interrupt, and approval gates (01-overview.md:108-110).
- The LLM Wiki digests raw materials (PDF, markdown, scraped pages) into structured pages with `[[links]]` and traceable citations plus a citation drawer and hot cache auto-injected into system prompts (01-overview.md:63-65, 01-overview.md:114).
- Capability is extended three ways — SKILL.md packages (manifest + prompt + tool list + LESSONS.md), MCP (stdio/SSE/Streamable HTTP with per-employee binding), and ACP (Claude Code/Codex bridged to skill cards) — all bounded by Tool Guard RBAC, approvals, and path protection (01-overview.md:120-124).
- Enterprise posture is multi-user workspaces with approval-gated sensitive actions, full audit trail, Actuator health monitoring, per-channel error isolation, and an Admin Runtime Console (Settings → System → Runtime) with force-recycle, consistent lifecycle semantics, and per-event SSE IDs for safe reconnects (01-overview.md:37-40, 01-overview.md:135-136).

## Identity and positioning
Self-described as "Your second brain" and "Pluggable Agent Runtime · Native + DSH · Spring Boot inside" (01-overview.md:9-11). Targets IT-sign-off versus single-person agents: multi-user workspaces, approval-gated sensitive actions, full audit trail, Actuator health monitoring, per-channel isolation, one JAR in the user's environment with user-controlled persisted data (01-overview.md:37-40). Pricing line: "$0 · No tokens metered. No seats billed. Your server. Your data. Your keys." (01-overview.md:83).
## Release note (v2.3.0)
v2.3.0 (released 2026-09-20) adds JSON acceptance and execution evidence for persistent Goals — configurable required JSON fields bound to current requirements and immutable artifact versions — plus controlled worker intervention, skill document/folder uploads, and fixes for DSH history, output budgets, vLLM reasoning, and SSE framing (01-overview.md:33).
## Provider failover
On expired keys, 401s, network blips, or drained quota, MateClaw tries the next healthy provider in configured order — including DashScope, OpenAI, Anthropic, Gemini, DeepSeek, Kimi, Ollama, LM Studio, and MLX — and errors only when the chain is exhausted (01-overview.md:51-55). A provider health tracker parks bad vendors in a cooldown window; ordering happens in **Settings → Models** with a live health dashboard (01-overview.md:55-57).

## Digital employees
Coworkers, not chat boxes: each has a **Role**, **Goal**, **Backstory**, runtime, pixel-art avatar, and color; six built-in templates ship ready — General Assistant · Product Assistant · Research Analyst · Customer Support · Data Analyst · Code Reviewer (01-overview.md:89-90). Identity and governance stay stable across engine changes (01-overview.md:90).
## Agent runtime (native or DSH)
The `AgentRuntimeProvider` contract separates employee from engine (01-overview.md:94). The native runtime keeps ReAct, Plan-and-Execute, persistent Goals, and Team Runs inside MateClaw; the DSH runtime manages `dsh-jsonrpc-agent` as an authenticated child process streaming thinking, text, tool calls, usage, completion, and cancellation as normalized events (01-overview.md:94-95). MateClaw retains session, workspace, credentials, tools, approvals, messages, and UI projection; runtime availability/capabilities are validated before startup and DSH can be installed, verified, connection-tested, enabled, or disabled from the console (01-overview.md:95).
## Durable Goals and recovery
Persistent Goals turn hours-long work into bounded, recoverable segments with persisted checklist, continuation state, attempts, cooldowns, leases, and busy-worker user input; after a single backend restart the supervisor reconciles the interrupted attempt from checkpoints/artifacts and schedules the next safe segment (01-overview.md:99-101). File-producing work is expected to keep a progress ledger, append small verifiable units, inspect the tail after recovery, and call `completeGoal` only after reproducible acceptance checks; exactly-once is not promised for external side effects (payments, sends, publishes, destructive calls need idempotency or review) (01-overview.md:102). Prompt pattern (verbatim): "Create a persistent Goal first. Save the plan and progress in the workspace, write in small checkpoints, resume from existing evidence after errors or restart, and call `completeGoal` only after every criterion has verifiable evidence." (01-overview.md:104).
## Team Runs
One request yields one durable Team Run with a stable `runId` linking objective, task DAG, worker executions, synthesis, and deliverables (01-overview.md:108-109). Chat is the outcome surface, Agents Live groups workers for real-time observation, Teams owns history and governance — all consuming the same server projection; worker conversations stay out of the normal sidebar with summaries/files leading and drill-down to tasks, evidence, approvals, and read-only worker records (01-overview.md:109). Underneath, the 2.0 shared board provides dependency orchestration, parallel dispatch, prerequisite hand-off, execution leases, cancel-interrupt, and human approval gates (01-overview.md:110).
## Knowledge and memory
- **LLM Wiki** — raw materials digest into linked pages with citations; hot cache auto-injects into every employee system prompt; Transformations engine (1.3.0+) turns the Wiki into a processing pipeline (01-overview.md:114).
- **Workspace memory** — `AGENTS.md`, `SOUL.md`, `PROFILE.md`, `MEMORY.md`, daily notes (01-overview.md:115).
- **Memory lifecycle** — post-conversation extraction, scheduled consolidation, Dreaming workflows; workflows can write to `MEMORY.md` via the `write_memory` step (01-overview.md:116).
## Skills, MCP, ACP, Tool Guard
- **SKILL.md packages** — manifest + prompt + tool list + **LESSONS.md**; 2.1 reflection and recurring-request mining produce improvements; promotion, constrained auto-binding, curator handover/governance, origin policy, snapshots, and restore points keep evolution observable, workspace-scoped, reversible; eight starter templates plus five-step wizard with pre-flight checks (01-overview.md:121).
- **MCP** — stdio / SSE / Streamable HTTP; per-employee binding (1.3.0+) prevents toolbox bleed (01-overview.md:122).
- **ACP** — Claude Code and Codex brought in as employees, auto-bridged to skill cards with wrapper tools (01-overview.md:123).
- **Tool Guard** — RBAC + approval flow + path protection (01-overview.md:124).
## Business orchestration
- **Workflow** — linear DSL composing employees plus system actions (approval / channel dispatch / write-memory); publishable, triggerable, replayable; seven step modes (`sequential` / `fan_out` / `collect` / `conditional` / `await_approval` / `dispatch_channel` / `write_memory`); JSON-first authoring with Monaco + schema validation or natural-language draft generation (01-overview.md:129).
- **Triggers** — six pattern types (`cron` / `webhook` / `channel_message` / `agent_lifecycle` / `content_match` / `workflow_completion`); default-on governance: dedup, per-trigger rate limit, bot-self filter, recursion guard, fail-closed unknown patterns (01-overview.md:130).
- **Wiki Transformations** — user-authored templates over raw materials or pages with cross-material map-reduce, reverse-citation extraction, JSON output mode, per-template model picker (01-overview.md:131).
## Observability and multimodal
Admin Runtime Console (`Settings → System → Runtime`) shows who runs, which provider owns the turn, step, token use, and one-click force-recycle; native and DSH events share one thinking/tool/answer projection with consistent completion/failure/usage/cancellation semantics and per-event SSE IDs (01-overview.md:135-136). Multimodal creation covers text-to-speech, speech-to-text, image, music, video, 3D; sidecar routing (1.3.0+) lets a vision model describe images for a text-only main model; image edit references attachments by `msg:<id>:<idx>`; four document tools (`DocxRenderTool` / `XlsxRenderTool` / `PptxRenderTool` / `PdfRenderTool`) render Markdown to Office files — chunk text cuts off mid-word at "insi", so the remainder of this claim is unavailable (01-overview.md:140-141).
