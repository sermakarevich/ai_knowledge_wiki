**What it shows.** The figure is a workflow/pipeline diagram (not a quantitative plot, so there are no numeric axes; the only "trend" is the directional data flow, left‑to‑right with internal loops). It depicts a multi‑hop question‑answering system over a knowledge graph. **Takeaway.** The architecture is a *plan → retrieve → validate → enhance* loop over a knowledge graph, with explicit early‑exit ("enough") and failure ("no information") handling, and a final aggregation stage that composes per‑sub‑question answers into one response. The design's emphasis is on iterative, self‑correcting exploration (the continue/validate/enhance cycle) rather than a single retrieval pass, which is what enables multi‑hop reasoning and graceful no‑answer behavior.
