# Connections

- [[ai_papers/graph_rag/ArxivGraphRAGLocalToGlobal/summary|GraphRAG: From Local to Global (Microsoft)]] — shares the foundational thesis that structuring a corpus as an LLM-derived knowledge graph beats flat-chunk retrieval, but targets the opposite problem: Microsoft's GraphRAG answers *global* sensemaking queries over an entire corpus via community summarization, while this paper answers *targeted*, single-ticket lookup queries via a much lighter per-document tree + inter-document edge schema — a narrower, cheaper design fit for its narrower task.
- [[ai_papers/graph_rag/ArxivLightRAG/summary|LightRAG]] — both build a hybrid graph (LightRAG: dual-level specific+thematic; this paper: intra-ticket tree + explicit/implicit inter-ticket edges) with incremental-update concerns in mind (LightRAG optimizes for cheap updates; this paper flags dynamic KG updates as unsolved future work) — worth reading together as two different answers to "how much graph structure is actually needed."
- [[ai_papers/graph_rag/ArxivGraphRAGSurvey/summary|GraphRAG Survey]] — this paper is a concrete instance of the survey's three-stage indexing/retrieval/generation pipeline abstraction, specialized to customer-service tickets; useful to read the survey first for vocabulary, then this paper as a worked production example.
- [[ai_papers/graph_rag/ArxivRAGvsGraphRAG/summary|RAG vs GraphRAG]] — that paper's finding that flat RAG and GraphRAG are complementary (best combined via hybrid selection/integration) is a useful counterweight to this paper's clean "KG-RAG beats baseline" framing — this paper's baseline is a matched-LLM/embedder flat retriever, but it never tests a hybrid flat+graph strategy, which the benchmark paper suggests might do even better.
- [[ai_papers/graph_rag/ArxivGraphRAGBench/summary|GraphRAGBench]] — contrasts as a rigorous, independently released public benchmark (1,018 questions, 20 textbooks) against this paper's single, unreleased internal golden dataset and production A/B — GraphRAGBench is the kind of evidence this paper's claims would need to be independently checkable.
- [[ai_papers/graph_rag/ArxivSevenFailurePointsRAG/summary|Seven Failure Points in RAG]] — that paper catalogues recurring RAG deployment failure modes from three real deployments; this paper's undercharacterized fallback-trigger rate and unmeasured graph-construction error rate (see [[critical_thinking|Critical Analysis]]) are exactly the kind of silent production failure points that report would predict.

This entry is the KB's clearest **production case study** among the graph_rag papers — most others are benchmark or methods papers; this one pairs well as "does the theory survive contact with a live business metric."
