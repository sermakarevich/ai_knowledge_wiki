**Figure 4 — Graph community structure of the MultiHop‑RAG entity graph (Leiden clustering).**

- **What it shows:** Two side‑by‑side network visualizations of the same entity graph, colored by community assignment from a hierarchical Leiden partition. (a) *Root communities at level 0* and (b) *Sub‑communities at level 1*. The graph is rendered as a node‑link embedding (OpenORD + Force Atlas 2 layout); node **size** encodes degree (so the few large circles are high‑degree hub entities) and node **color** encodes community membership.
- **Axes:** None — these are geometric graph layouts, not quantitative plots, so there are no x/y axes or plotted value series.
- **Trend (hierarchical refinement):** Level 0 (a) resolves the graph into a small number of broad, spatially coherent color regions (dominant root communities at maximum modularity), each anchored by a hub node and surrounded by a dense cloud of low‑degree nodes. Level 1 (b) refines those same regions into finer sub‑clusters, so the broad blocks in (a) split into multiple smaller colored patches, exposing internal structure within each root community.
- **Takeaway:** The entity graph is not a uniform blob but a well‑organized hierarchy — a handful of dominant, high‑degree‑anchored topical communities, each with internally coherent sub‑communities. This modular, hub‑and‑spoke organization is what downstream community‑based retrieval/indexing can exploit.
