**Figure 1 — Technical Summary**

**What it shows.** The figure is a process (pipeline) diagram, not a quantitative plot; it has no numerical axes or trends. It depicts the *GraphRAG* workflow as two vertically stacked stages separated into a left column ("Indexing Time") and a right column ("Query Time"), with the middle label "Pipeline Stage" marking the transition. The legend colors encode this split: purple boxes = indexing time, green boxes = query time.

**Left column (indexing time, top→bottom).** Source Documents → *text extraction and chunking* → Text Chunks → *domain‑tailored summarization* → Entities & Relationships → *domain‑tailored summarization* → Knowledge Graph. An off‑axis arrow labeled "community detection" then carries the Knowledge Graph over to the right column's Graph Communities node.

**Right column (query time, bottom→top).** Graph Communities → *domain‑tailored summarization* → Community Summaries → *query‑focused summarization* → Community Answers → *query‑focused summarization* → Global Answer.

**Key elements (per caption).** The graph index's nodes are entities, edges are relationships, and covariates are extracted claims/relationships; an LLM produces these via domain‑tailored prompts. Community detection (e.g., Leiden) partitions the graph so the LLM can summarize communities in parallel at both indexing and query time. The final "global answer" is generated by a query‑focused summarization pass over the community summaries, weighting relevance to the query.

**Takeaway.** GraphRAG augments standard chunk‑based retrieval with an LLM‑built entity–relation graph plus community‑level summaries, enabling answers to *global sensemaking* questions (not just local fact lookup) by compressing the corpus into summarizable communities and then synthesizing a query‑focused global answer.
