**Figure 4 — Illustration of the GrgPoison attack against GraphRAG (three panels, a–c)**

**Purpose / overview.** The figure contrasts a naive baseline poisoning approach with the two-stage GrgPoison strategy, using the malware "Stuxnet" as the running example. It shows how adversarial text is mapped into the underlying knowledge graph (KG) and how the graph topology is manipulated so that the injected content survives GraphRAG's retrieval and summarization.

**Legend (entity types).** Green = Source Entity (the query-relevant node, e.g., Stuxnet = $u_r$); open blue = Intermediate Entity (original KG neighbor, e.g., DLL Injection = $v_r$); red = Injected Competing Entity ($v_r^*$); purple = Supporting Entity ($v_r^+$).

**Panel (a) — PoisonedRAG (baseline).** Shows two independent query→misinformation pairs, each marked with a devil icon: query "How to mitigate the malware Stuxnet?" paired with the false statement about network intrusion prevention/user training, and query "How to detect the malware Stuxnet?" paired with the false statement about process creation. The takeaway encoded here is that the baseline treats each query in isolation with a distinct misstatement.

**Panel (b) — GrgPoison: Relation Injection.** A small graph is drawn with an original edge Stuxnet ($u_r$) —*Utilize*→ DLL Injection ($v_r$). The attack adds a **competing relation** $r^*$: a red dashed edge Stuxnet —*Utilize $r^*$→ Process Hollowing ($v_r^*$), turning $v_r^*$ into an injected competing entity. Below the graph, the corresponding KG text records are shown: the genuine $d_r$ ("…utilizes DLL injection") and the injected $d_r^*$ ("…utilizes Process Hollowing"). This step writes the poisoning directly into the KG as a rival relation for the same source node.

**Panel (c) — GrgPoison: Relation Enhancement.** Starting from the same base edge, this panel adds the injected red node (Process Hollowing, $v_r^*$) **plus a supporting purple node** (Process Creation, $v_r^+$) and extra dashed edges linking Stuxnet → Process Hollowing (via *Utilize* and *Detected By*) and Process Hollowing → Process Creation (*Detected By*). The associated text $d_r^+$ ("Process Creation can detect Process Hollowing, which is utilized by the malware Stuxnet") is shown beneath. The enhancement thus densifies the local subgraph around the injected entity.

**Flow / architecture (across panels).** Baseline (a) only appends free-text misstatements per query. GrgPoison (b→c) instead (1) injects a competing relation/edge into the KG, then (2) adds supporting entities and edges around that injected node. The combined relational poisoning text is the union of the injection text ($d_r^*$) and the enhancement text ($d_r^+$), concatenated into the poisoning dataset for the target relation.

**Takeaway.** The figure demonstrates that GrgPoison's relation‑injection + relation‑enhancement design makes the injected relation $r^*$ and entity $v_r^*$ appear inside GraphRAG's two retrieval channels—both the retrieved relevant relations $R(x)$ and the community summaries $S(x)$—so the adversarial content is reinforced in the graph structure rather than merely appended as standalone text.
