**What the figure shows.** This is an architecture (schematic) diagram, not a quantitative plot, so it has no data axes or trends. It depicts the *SodaMem* system as a left‑to‑right pipeline with three panels — **Ingest**, **Temporal Graph Store**, and **Answer** — connected by thick arrows, and a bottom banner stating the goal: "Evidence‑grounded temporal graph memory."

**Ingest (left, top‑to‑bottom flow).** Multi‑session dialogue → an LLM‑based *FactEvent Extractor* → a *Provenance Check* → an optional *Timeline Resolve* step → the output, shown in a dashed box, of "typed FactEvents with source spans."

**Temporal Graph Store (middle).** Three numbered components: (1) *FactEvent Nodes* with fields `kind / predicate / time / validity`; one example node lists `kind=Event`, `predicate=visited`, `time≈2024‑05‑12T10:15Z`, `validity≈[2024‑05‑12, ∞)`, `source≈doc42:12‑18` (these are illustrative values, not measured data), flanked by two graph‑node circles and an ellipsis. (2) *Edges*, typed and directed (A→B), in four colors/styles: **SUPERSEDES** (black solid), **CONTRADICTS** (red dashed), **UPDATES** (green solid), **DERIVED_FROM** (purple dashed). (3) *Dual Indexes*: a BM25 **lexical/sparse index** (stacked‑bar glyph) and a **dense‑vector semantic index** (the only axis‑like element — a conceptual 2‑D embedding scatter, not a trend plot).

**Answer (right, top‑to‑bottom flow).** *Hybrid Retrieve* → *Planner* with memory tools (`search`, `inspect`, `timeline`) → *Reader + Citations* → *Final Answer*.

**Takeaway.** SodaMem is a memory architecture that turns multi‑session dialogue into provenance‑checked, time‑stamped fact events, organizes them in a temporal graph with explicit relation types (supersedes / contradicts / updates / derived‑from), indexes them both lexically and semantically for hybrid retrieval, and then plans and reads over that evidence to produce cited, temporally aware answers. The few numerals present are examples inside a sample node, not plotted quantities.
