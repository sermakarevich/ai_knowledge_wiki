# Connections

- [[graph_rag/ArxivHippoRAG/summary|HippoRAG]] — the canonical OpenIE-triples-plus-Personalized-PageRank graph memory that HiGram's flat-graph critique implicitly targets; HippoRAG retrieves over one global graph per query, whereas HiGram's whole contribution is avoiding exactly that by localizing to a MicroGraph before scoring evidence paths.
- [[papers/ArxivSodaMem/summary|SodaMem]] *(unfiled, papers/)* — the closest sibling in this KB: also a temporal, evidence-grounded graph memory for LLM agents with explicit lifecycle/status tracking on memory units. SodaMem emphasizes provenance and multi-tunnel retrieval fusion; HiGram emphasizes coarse-to-fine localization plus coordinated dependency rewriting — both attack the "flat graph + independent unit updates" failure mode from different angles.
- [[papers/RethinkingMemoryContinuouslyEvolvingConnectivity/summary|Rethinking Memory as Continuously Evolving Connectivity (FluxMem)]] *(unfiled, papers/)* — a contrasting philosophy: FluxMem restructures its whole connectivity graph continuously based on usage feedback, while HiGram deliberately keeps memory structure fixed and confines every update to one localized, scored evidence path — a "grow and prune everywhere" design vs. a "touch only what's proven affected" design.
- [[papers/MSCEMemorySkillCoEvolution/summary|From Memory to Skills: Evidence-Grounded Co-Evolution Governance]] *(unfiled, papers/)* — shares HiGram's evidence-grounded framing for what gets trusted/promoted in agent memory (only evidence-backed changes are committed), but operates at a different level: promoting raw experience into reusable skills/habits, rather than reconciling conflicting facts within a graph.
- [[papers/AreWeReadyForAnAgentNativeMemorySystem/summary|Are We Ready For An Agent-Native Memory System?]] *(unfiled, papers/)* — a positioning/survey-style paper on what an agent-native memory system needs; useful as the broader landscape HiGram's specific localization+rewrite mechanism is one concrete answer within.
