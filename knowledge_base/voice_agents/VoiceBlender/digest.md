# VoiceBlender/voiceblender — Digest

## 1. [[wiki/01-overview|Overview]]
**In one sentence:** A Go service that bridges SIP and WebRTC voice calls with multi-party audio mixing, a REST API, and real-time webhooks (01-overview.md:9).
## Key points
- VoiceBlender bridges SIP and WebRTC voice calls with multi-party mixing, a REST API, and real-time webhooks (01-overview.md:9).
- SIP supports inbound and outbound calls with codec negotiation (PCMU, PCMA, G.722, Opus, AMR-WB, AMR-NB), digest auth, and RFC 4028 session timers, plus optional TLS on a second port, 183 early media, and hold via re-INVITE sendonly/sendrecv (01-overview.md:15-18).
- Leg types include WebRTC via SDP offer/answer with trickle ICE, WhatsApp Business Calling over SIP-TLS + ICE/DTLS-SRTP + Opus, WebSocket legs with binary or `json_base64` framing, and experimental MoQ legs disabled by default (01-overview.md:19-22).
- Rooms mix N participants with mixed-minus-self audio at 8/16/48 kHz (default 16 kHz), support bridging two same-rate mixers with configurable direction, and per-room role-based audio routing applied atomically at leg-join time (01-overview.md:23-25).
- Media and AI surface covers RFC 4733 DTMF, T.140 RTT over RTP per RFC 4103 with RFC 2198 redundancy, stereo WAV recording with pause/resume and S3/GCS upload, WAV/MP3 playback, TTS and real-time STT from named providers, AI agents, AMD, webhooks with HMAC-SHA256 and `event_id`/`X-Event-Id`, VSI event stream at `GET /v1/vsi`, and Prometheus metrics at `GET /metrics` (01-overview.md:29-39).
- REST listens on `:8080` and SIP on `127.0.0.1:5060` by default; the HTTP surface has no credential auth and is gated solely by the `ALLOWED_IPS` allowlist and network placement (01-overview.md:52, 01-overview.md:82-90).
- Configuration is entirely via environment variables with the full reference in `CONFIGURATION.md` and an editable template at `voiceblender.env.example` (01-overview.md:64-69).

## 2. [[wiki/02-top-level-files|Top-level-files]]
**In one sentence:** Top-level files define the REST/VSI API contract, generated OpenAPI/AsyncAPI specs, environment-variable configuration, contributor regeneration workflow, dependency pins, and test commands (02-top-level-files.md:5).
## Key points
- `API.md` (5101 lines) documents `Base URL: http://localhost:8080/v1` with `Content-Type: application/json` and asynchronous SIP-triggering endpoints returning `202 Accepted` with progressive-form status strings like `holding`, `ringing`, `answering` (02-top-level-files.md:6-17).
- `API.md` defines a leg object with `id`, `type` (`sip_inbound`, `sip_outbound`, `webrtc`, `whatsapp_in`, `whatsapp_out`, `websocket_in`, `websocket_out`, `moq_in`, `livekit_publish`, `livekit_participant`), `state`, `room_id`, `muted`, `deaf`, `held`, `role`, `headers`/`sip_headers`, `custom_data`, plus `custom_data` echo semantics capped by `CUSTOM_DATA_MAX_BYTES` (02-top-level-files.md:42-129).
- `asyncapi.yaml` (7206 lines) is generated by `cmd/asyncapi-gen` with `DO NOT EDIT BY HAND`, describes AsyncAPI `3.0.0` `VoiceBlender Streaming Interface (VSI)` on `/v1/vsi` with JSON-text frames, a `connected` frame, webhook-identical events, and `<command>.result`/`error` frames echoing `request_id`, sourced from `internal/api/vsi_meta.go` (02-top-level-files.md:205-215).
- `openapi.yaml` (6746 lines) declares OpenAPI `3.1.0` `VoiceBlender API` bridging SIP/WebRTC with mixing, STT/TTS, agents, recording, and webhooks, and embeds an `x-config-vars` table (`INSTANCE_ID`, `HTTP_ADDR`, `ALLOWED_IPS`, SIP/TLS, codecs, RTP, recording, webhooks) (02-top-level-files.md:710-716).
- `CONFIGURATION.md` (145 lines) and `voiceblender.env.example` (277 lines) state all configuration is via environment variables, with the example copied via `cp voiceblender.env.example voiceblender.env` and kept in sync with `internal/config/config.go` (02-top-level-files.md:506-510, 02-top-level-files.md:979-984).
- `CLAUDE.md` (42 lines) mandates `gofmt`, `make openapi`/`make asyncapi`/`make specs` regeneration via `RoutesMetadata()` in `internal/api/openapi_meta.go` and VSI registries in `internal/api/vsi_meta.go`, `API.md`/`CONFIGURATION.md`/`voiceblender.env.example`/`README.md`/`TESTING.md` updates, unit plus `tests/integration/` tests, no API churn, and never running `git commit` (02-top-level-files.md:464-496).
- `TESTING.md` (726 lines) gives `go test ./internal/...`, `go test -tags integration -timeout 60s ./tests/integration/`, the `TestConcurrentRoomsScale` benchmark, `docker/docker-compose.cluster.yml` cluster, and a per-package test-count table; `go.sum` (404 lines) pins module hashes including `github.com/VoiceBlender/goamr-nb` and `goamr-wb` (02-top-level-files.md:885-899, 02-top-level-files.md:582-632).

## The system in five moves
1. A Go service bridges SIP and WebRTC voice calls with multi-party mixing, exposed through a REST API on `:8080` and real-time webhooks.
2. Calls arrive as typed legs — SIP with codec negotiation and digest auth, WebRTC with trickle ICE, WhatsApp over SIP-TLS, WebSocket, and experimental MoQ — each with hold, early media, and transfer controls.
3. Legs are composed into rooms that mix N participants with mixed-minus-self audio, bridgeable across same-rate mixers with role-based routing.
4. The media and AI layer adds DTMF, RTT, recording, playback, TTS/STT, agents, AMD, webhooks, the VSI event stream, and Prometheus metrics.
5. The REST/VSI contract is codified in `API.md` plus generated `openapi.yaml`/`asyncapi.yaml`, with async SIP endpoints returning 202 and a rich leg object with `custom_data` echo semantics.
6. Everything is configured via environment variables and guarded by contributor rules: regenerate specs from metadata registries, keep docs and env template in sync, test at unit and integration level, and secure the HTTP surface by `ALLOWED_IPS` allowlist alone.
