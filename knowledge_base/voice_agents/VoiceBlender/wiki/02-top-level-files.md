Async rule verbatim (02-top-level-files.md:17):

```text
Every endpoint that triggers a SIP request or response (e.g. INVITE, BYE, re-INVITE for hold/unhold, REFER for transfer, 100/180/183/200 for inbound calls) is **asynchronous**. The HTTP handler validates inputs synchronously (returning 4xx if anything fails up front) then queues the SIP work on a goroutine and returns **`202 Accepted`** with a progressive-form status string (e.g. `holding`, `unholding`, `hanging_up`, `early_media`, `ringing`, `answering`).
```

Outcome events (02-top-level-files.md:21-30):

| Event | When |
|---|---|
| `leg.connected`, `leg.early_media`, `leg.hold`, `leg.unhold`, `leg.disconnected`, `leg.transfer_*` | Successful completion |
| `leg.command_failed` | SIP work failed after HTTP `202`; payload `{leg_id, command, error}` with `command` one of `ring`, `early_media`, `hold`, `unhold`, `add_to_room`, etc. |
| `leg.stream_added` / `leg.stream_removed` / `leg.stream_rejected` / `leg.stream_failed` | Multi-stream negotiation/teardown outcomes |
| `leg.stream_room_changed` / `leg.stream_role_changed` | Room attach/detach or routing-role change |

Synchronous surface verbatim (02-top-level-files.md:32):

```text
GET endpoints, in-memory state-change endpoints (`/mute`, `/deaf`, `/dtmf/accept`, `/dtmf/reject`), audio-pipeline endpoints (`/play`, `/record`, `/tts`, `/stt`, `/agent/*`), `/dtmf` (sends RTP, not SIP), and room CRUD remain synchronous.
```

```text
WebSocket protocol for real-time event streaming and command dispatch on /v1/vsi. All frames are JSON text. The server sends a `connected` frame on connect, then event frames whose shape is identical to webhook payloads (see openapi.yaml x-webhooks). Clients may issue commands at any time; each command receives a matching `<command>.result` or `error` frame echoing the request_id.
This file is generated from internal/api/vsi_meta.go — every VSI command and every event in internal/events MUST be present in the registries there or this spec is incomplete.
```
