# Enabling Streaming User Transcription in Full-Duplex Speech-to-Speech Models
**Paper:** [Enabling Streaming User Transcription in Full-Duplex Speech-to-Speech Models](https://arxiv.org/abs/2609.15759)

## Human Readable TL;DR
Imagine talking to a voice assistant that can listen and speak at the same time, like a natural phone call where both sides can interrupt each other, but it never writes down what you said so there is no transcript to review or caption to read. This paper fixes that blind spot by giving the talking AI a second pen that writes out your words live while its main mouth keeps answering, both sharing the same brain so they stay in sync. It works a bit like a court stenographer sitting inside the speaker's head, using clever timing tricks to keep the captions accurate without making the assistant slower to respond or worse at taking turns. The result is a full-duplex chatbot that can caption you in real time, handle interruptions gracefully, and even answer factual questions slightly better because it can read what it heard.

## TL;DR
The paper extends the SALM-Duplex full-duplex speech-to-speech architecture with a lightweight parallel streaming ASR head that transcribes the user in real time alongside agent response generation from a shared LLM backbone. Frame-level supervision comes from on-the-fly torchaudio CTC forced alignment with the MMS-FA model using left (word-start) alignment and `<pad>`-filled gaps, plus tunable user and agent text delays that trade transcription latency against turn-taking responsiveness. With `du = 1.2s` and `da = 0.16s`, the duplex model reaches 10.21% average WER on Open ASR Leaderboard sets while holding 90% turn-taking precision, 95% recall, and 100% barge-in accuracy, and the same architecture trained standalone reaches 7.73% average WER.

## Problem & Motivation
Full-duplex speech-to-speech models promise natural conversational AI by listening and speaking simultaneously, yet existing systems generally lack explicit streaming transcription of the user side, which limits conversation logging, accessibility such as live captions, and downstream use of what the user said. Prior streaming ASR systems like FastConformer, Parakeet, Kyutai STT, and Qwen-ASR deliver strong recognition but are encoder- or chunk-based and are not integrated into conversational full-duplex dialogue, while full-duplex dialogue models such as Moshi, PersonaPlex, SyncLLM, OmniFlatten, Freeze-Omni, and SALM-Duplex enable simultaneous listening and speaking but provide no streaming user transcription or depend on external voice activity detection and turn detection rather than truly simultaneous processing. Even approaches that interleave ASR and reasoning tokens in a single text monologue stream conflate transcription and reasoning in one channel instead of treating recognition as a dedicated output. The paper therefore asks how to add real-time user transcription to a full-duplex S2S model with minimal extra parameters and without degrading turn-taking, barge-in, or intelligence.

## Main Original Ideas
1. **Parallel streaming ASR head on a shared duplex backbone:** a dedicated ASR module with its own embedding layer and prediction head, initialized from backbone LLM layers, runs in parallel to the agent text head on top of a 600M-parameter Parakeet streaming encoder at 80ms frame rate fused with the 9B-parameter NVIDIA Nemotron-Nano-9B-v2-Base decoder-only LLM, so a single decoding pass jointly produces user transcription and agent response tokens with user and agent embeddings time-aligned and added before the LLM and generated tokens fed back autoregressively.
2. **Joint multi-channel training with agent-preview decoding:** training combines multi-channel next-token prediction with equal loss on user and agent text plus an ASR loss term, while agent text is predicted without word-level alignment so users get a preview of the response before speech generation finishes and the agent output path feeds streaming TTS, preserving reasoning and instruction-following through a diverse SFT mixture of interleaved S2S data, text-to-text conversations, multi-turn synthetic conversations, multiple-choice QA, single-turn speech instruction data, and 16k hours of English ASR data with background-noise augmentation.
3. **On-the-fly CTC forced alignment with delay tuning:** frame-level targets are produced during training by torchaudio CTC forced alignment with the MMS-FA acoustic model yielding word-level timestamps, using left alignment at word starts which beats right alignment because speech onset is easier to detect, filling inter-word frames with `<pad>` tokens, and exposing user text delay `du` and agent text delay `da` hyperparameters that explicitly control the latency-accuracy trade-off for transcription versus response timing.

## Key Findings
With delays set to `du = 1.2s` and `da = 0.16s` to balance reasonable ASR quality against immediate agent response, the duplex model with the integrated ASR head achieves 10.21% average WER across LibriSpeech test-clean and test-other, SPGISpeech, GigaSpeech, Earnings22, AMI, TED-LIUM, and VoxPopuli while simultaneously generating agent responses, which is better than the dedicated streaming baselines FastConformer-80ms at 11.71% and FastConformer-multi at 11.27%. Turn-taking and barge-in stay competitive with the no-ASR baseline on the internal multi-turn set at 90% precision and 95% recall with 431ms latency versus 86.1% and 96.9% with 410ms latency, plus 100% barge-in accuracy with 374ms latency versus 393ms, and adding the ASR head does not significantly change turn-taking except for increased smooth turn-taking latency on FDB-v1. On FDB-v1 the model beats Moshi on smooth turn-taking takeover rate at 96.12% versus 94% and produces far fewer pause-handling false takeovers at 44.4% versus 98%, while trailing Moshi on user-interruption takeover rate at 94% versus 100% but scoring dramatically higher on interruption response quality at 3.99 versus 0.77, with higher smooth-turn latency reflecting the pause-handling trade-off. Intelligence scores improve on OpenbookQA from 66.59% to 69.01% after adding the ASR head, suggesting the model benefits from the text modality, alongside AlpacaEval 3.83 and CommonEval 3.11, ahead of Moshi and slightly above Qwen2-Audio on OpenbookQA but behind it on conversational evals. Trained standalone without agent heads, the same architecture reaches 8.47% average WER at 1.6s delay and 7.73% after adding YODAS and YTC data, with ablations at 7.99% for 1.2s latency and 8.64% for a smaller Qwen 2.5-1.5B-Instruct backbone, leaving a gap to Nemotron-Speech-0.6B at 7.16% attributed to Granary subsets unavailable at training time and trading higher WER for lower latency versus Qwen3-ASR and Kyutai STT.

## Suggestions & Future Directions
The authors point to incorporating the full Granary dataset once the missing portions become available in their pipeline as the direct path to closing the remaining gap to Nemotron-Speech-0.6B, and more broadly the work enables conversation logging and accessibility features built on live user transcripts. Natural follow-ups implied by the results include tightening the smooth turn-taking latency penalty introduced by the ASR head on FDB-v1, further exploring the delay frontier between transcription accuracy and responsiveness, and testing whether the OpenbookQA gain from the text modality generalizes to other knowledge and conversational benchmarks.
