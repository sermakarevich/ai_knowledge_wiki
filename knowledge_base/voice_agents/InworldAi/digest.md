# api-evangelist/inworld-ai — Digest
## 1. [[wiki/01-overview|Overview]]
**In one sentence:** This repository is a third-party API Evangelist profile of Inworld AI's real-time voice-AI platform, cataloging its TTS, Voice, STT, and Realtime APIs behind one API surface and billing relationship.
## Key points
- The profile covers Inworld AI as a real-time voice AI infrastructure provider delivering TTS, STT, speech-to-speech Realtime API, and an OpenAI/Anthropic-compatible LLM Router (01-overview.md:73).
- The repository contains no software, build, release, or binary — only text and machine-readable API descriptions (01-overview.md:57-60).
- The repo position is Consuming with 3rd-Party access, tagged AI, Voice, Text To Speech, Speech To Text, Realtime, LLM Routing, Voice Cloning, Conversational AI, and Game AI (01-overview.md:79-93).
- The Inworld TTS API provides Realtime TTS-2 (100+ languages), TTS 1.5 Max (15 languages), and TTS 1.5 Mini (sub-120 ms first-token) with sync, server-streamed, and WebSocket synthesis (01-overview.md:104).
- The Inworld Voice API manages custom voices via instant cloning from audio samples and natural-language voice design, with list/get/update/delete plus a workspace publish endpoint (01-overview.md:135).
- The Inworld STT API offers synchronous transcribe and streaming WebSocket transcription with multi-provider routing (Whisper variants via Groq), 99+ languages, word timestamps, voice profiling, and prompt biasing (01-overview.md:161).
- The Inworld Realtime API is an end-to-end STT+LLM+TTS pipeline over WebSocket and WebRTC using an OpenAI-Realtime-API-compatible event protocol with VAD, tool calling, MCP tunneling, and Twilio integration (01-overview.md:187).
## 2. [[wiki/02-top-level-files|Top-level Files]]
**In one sentence:** The repository root metadata declares the Inworld AI API catalog, records how every derived artifact was produced, and publishes an independent Tier-1 consuming review.
## Key points
- `apis.yml` declares the catalog root as `aid: inworld-ai` with `name: Inworld AI` and a raw GitHub `url` for the file itself (02-top-level-files.md:9-11).
- The catalog lists a Realtime API for "Realtime speech-to-speech sessions" (02-top-level-files.md:13-15), a Speech To Text API to "Transcribe audio to text" (02-top-level-files.md:80-82), a Text To Speech API to "Synthesize speech from text using Inworld voice models" (02-top-level-files.md:147-149), a Voices API for "Voice cloning, design, and lifecycle" (02-top-level-files.md:214-216), and a Chat Completions API for "OpenAI-compatible chat completions through the LLM Router" (02-top-level-files.md:281-283).
- The first four API entries each repeat the same machine-readable property set pointing at an per-API OpenAPI file plus the shared `asyncapi/inworld-ai-asyncapi.yml`, `json-schema/inworld-tts-synthesis-schema.json`, and `json-ld/inworld-ai-context.jsonld`, alongside TTS, voice, STT, and realtime Documentation and GettingStarted URLs (02-top-level-files.md:21-46).
- `provenance.yml` is version `provenance: '0.1'` and states `unknown` means no authorship record, generated by `build-provenance-manifest.py` with drift checked by `check-provenance-manifest.py` (02-top-level-files.md:304-307).
- Collections and postman artifacts are marked `method: derived` with `evidence: openapi/<api-name>`, while the six `openapi/_original/` specs are `method: harvested` as provider-fetched byte-identical sources and the seven `openapi/inworld-ai-*-openapi.yml` specs are `method: derived` as path subsets split from the harvested specs (02-top-level-files.md:318-320, 02-top-level-files.md:546-548, 02-top-level-files.md:564-566).
- `review.yml` records `reviewedBy: API Evangelist`, `reviewedAt: '2026-05-25'`, `position: Consuming`, and `tier: 1` for `aid: inworld-ai` / `name: Inworld AI` (02-top-level-files.md:611-616).
- The review's strengths claim one base URL and billing surface, OpenAI Realtime / Chat Completions / Anthropic Messages compatibility, cloning plus phoneme/viseme alignment, an open-source TTS model with on-prem support, public `llms.txt` indexes, and five-tier pricing with rollover, while its weaknesses cite no public OpenAPI download, a narratively documented Realtime WebSocket protocol, and an unsurfacing status page (02-top-level-files.md:626-639).
## The system in five moves
1. An independent API Evangelist profile frames Inworld AI as real-time voice infrastructure, not software, with only text and machine-readable descriptions.
2. Four voice capabilities — TTS variants, Voice cloning/design lifecycle, multi-provider STT, and an end-to-end Realtime STT+LLM+TTS pipeline — are cataloged behind one API surface and billing relationship.
3. The repository root formalizes this in `apis.yml` as five entries (Realtime, STT, TTS, Voices, Chat Completions via the LLM Router) with per-API OpenAPI plus shared AsyncAPI, JSON Schema, and JSON-LD artifacts.
4. `provenance.yml` makes the derivation chain explicit: harvested byte-identical provider specs split into derived path-subset OpenAPIs, which in turn generate collections and Postman artifacts.
5. `review.yml` closes the arc with an independent Tier-1 Consuming verdict, crediting unified billing, OpenAI/Anthropic drop-in compatibility, cloning with phoneme/viseme alignment, open-source/on-prem TTS, and llms.txt indexes.
6. The same review tempers that verdict with machine-readability gaps — reconstructed OpenAPIs, a narratively documented Realtime protocol, and an unsurfacing status page.
