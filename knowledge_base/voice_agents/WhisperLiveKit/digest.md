# QuentinFuxa/WhisperLiveKit — Digest

## 1. [[wiki/01-overview|Overview]]
**In one sentence:** WhisperLiveKit is a real-time streaming speech-transcription/translation kit with a multi-backend server, `wlk` CLI, and WebSocket plus OpenAI-compatible API, built on simultaneous-speech research for low-latency incremental processing.
## Key points
- WhisperLiveKit does real-time streaming transcription/translation using simultaneous-speech research (Simul-Whisper/Streaming with AlignAtt, NLLB-based NLLW, WhisperStreaming with LocalAgreement, Streaming Sortformer diarization, Qwen3-ASR-causal, AlignAtt4LLM) instead of naively running Whisper on every audio batch, which loses context and cuts words mid-syllable (01-overview.md:9-17).
- The backend supports multiple concurrent users and uses Voice Activity Detection to reduce overhead when no voice is detected (01-overview.md:26).
- Installation is `pip install whisperlivekit` and the `wlk` CLI covers server start (`wlk --model base --language en`, `wlk run whisper:tiny`), offline file transcription (`wlk transcribe meeting.wav`), subtitle generation (`wlk transcribe --format srt podcast.mp3 -o podcast.srt`), model management (`wlk models`, `wlk pull large-v3`, `wlk rm large-v3`), and benchmarking (`wlk bench`) (01-overview.md:32-72).
- The server exposes an OpenAI-compatible REST endpoint (`POST http://localhost:8000/v1/audio/transcriptions`), works with the OpenAI Python SDK (`OpenAI(base_url="http://localhost:8000/v1", api_key="unused")`), and a native real-time WebSocket (`ws://localhost:8000/asr`) with per-session query parameters `language`, `target_language`, `context`, `mode`, and `token` (01-overview.md:76-103).
- Optional backends and stacks are installed as extras via `uv sync --extra <name>` or `pip install -e ".[<name>]"`, including `mlx-whisper`, `funasr`, `voxtral-mlx`, `cpu`, `cu129`, `translation`, `sentence_tokenizer`, `voxtral-hf`, `qwen3-vllm`, `qwen3-streaming`, `qwen3-vllm-metal`, `diarization-sortformer`, `diarization-diart`, and `canary` (01-overview.md:117-132).
- Heavy extras have environment conflicts declared in `[tool.uv].conflicts` in `pyproject.toml`: `qwen3-vllm` needs a separate environment from `cu129`, `voxtral-hf`/`qwen3-vllm-metal`/vLLM stacks conflict with one another, and `canary` conflicts with `voxtral-hf` and `qwen3-vllm-metal` but is compatible with `diarization-sortformer` (01-overview.md:155).
- Accuracy/speed claims are backed by reproducible LibriVox/Project Gutenberg scatter benchmarks (6 minutes of audiobook audio per language: 30s + 60s + 120s + 180s, H100-measured, raw results in `benchmarks/h100_scatter/`, reproducible with `python scripts/run_scatter_benchmark.py`), plus companion clients including the bundled web UI at `http://localhost:8000`, a native SwiftUI macOS client, and a `chrome-extension` audio-capture demo (01-overview.md:159-176).

## 2. [[wiki/02-top-level-files|Top-Level Files]]
**In one sentence:** Top-level files define WhisperLiveKit's build context, ignore rules, deployment profiles, citation/security policy, contributor runtime boundaries, and experimental/dev notes.
## Key points
- `.dockerignore` (15 lines) excludes VCS, venvs, caches, and build artifacts from the Docker build context, including `.git`, `.venv`, `__pycache__`, `*.pyc`, `dist`, and `build` (02-top-level-files.md:6-23).
- `.gitignore` (140 lines) is a standard Python ignore plus project-specific entries for audio/models (`*.wav`, `*.mp3`, `*.pt`), run scripts (`run_*.sh`), generated chrome-extension bundles, local benchmark runs (`/benchmarks/runs/`), and test scaffolding (`/test_*.py`, `/test/` with `!tests/` kept) (02-top-level-files.md:25-167).
- `.gitmodules` registers one submodule, `third_party/qwen3-asr-causal`, pointing at `https://github.com/QuentinFuxa/Qwen3-ASR-causal.git` (02-top-level-files.md:169-175).
- `CITATION.cff` (cff-version 1.2.0, Apache-2.0) cites WhisperLiveKit by Quentin Fuxa and additionally requires citing the AlignAtt4LLM IWSLT 2026 paper (arXiv 2606.03967) when using its translation backend, while `CHANGES.md` defers all release notes to GitHub Releases (02-top-level-files.md:177-208).
- `CLAUDE.md` states agent runtime boundaries (`TranscriptionEngine` shared per process, `AudioProcessor` per session, `parse_args()` returns `WhisperLiveKitConfig`, `online_factory()` selects the session processor, `FrontData.to_dict()` defines native WebSocket JSON, `translation_alignatt.py` is a client of a separate server) and a navigation table mapping areas to entry points (02-top-level-files.md:210-241).
- `compose.yml` defines three services sharing an `hf-cache` volume: `wlk-gpu-sortformer` (`--model medium --diarization --pcm-input`), `wlk-gpu-voxtral` (`--backend voxtral --pcm-input`), and `wlk-cpu` built from `Dockerfile.cpu`, with GPU services exposing `8000`/`8001` and passing through `HF_TOKEN` (02-top-level-files.md:243-298).
- `Dockerfile.cpu` is a two-stage (builder/runtime) `debian:bookworm-slim` build using `uv` (`ghcr.io/astral-sh/uv:0.12.10`), Python 3.12, `ARG EXTRAS=cpu`, runtime `ffmpeg`, `EXPOSE 8000`, `ENTRYPOINT ["wlk", "--host", "0.0.0.0"]`, default `CMD ["--model", "tiny"]`, and an HTTP healthcheck on `localhost:8000` (02-top-level-files.md:396-479).
- `DEV_NOTES.md` records SimulStreaming encoder timings, NLLB-vs-CTranslate2 translation timings, and an unfinished 4-to-2 SortFormer speaker-mapping sketch, while `JARVISLAB_AGENTS.md` (187 lines) documents `jl` GPU-VM workflow (resume/exec/upload/download/pause) and `MANIFEST.in`/`SECURITY.md` cover packaging include and private vulnerability reporting (02-top-level-files.md:300-394) (02-top-level-files.md:481-694).

## The system in five moves
1. Start from simultaneous-speech research instead of chunked Whisper, combining AlignAtt, LocalAgreement, causal encoders, and diarization policies for low-latency incremental transcription and translation.
2. Expose that engine as a multi-user server with VAD-gated overhead, reachable via OpenAI-compatible REST, native real-time WebSocket with per-session language/context/mode/token controls, and the `wlk` CLI for serve/transcribe/subtitle/model/bench tasks.
3. Scale across hardware and languages through optional extras backends (MLX, CUDA, Voxtral, FunASR, Qwen3, Sortformer/Diart, Canary), with declared uv conflicts separating incompatible heavy stacks.
4. Ship reproducibly via tightened build context and deployment profiles: dockerignore/gitignore rules, a two-stage CPU image, compose services for GPU-sortformer/GPU-voxtral/CPU, shared HF cache, and H100 scatter benchmarks plus web/macOS/chrome clients.
5. Govern contributions with explicit runtime boundaries (shared engine vs. per-session processor, config/factory/WebSocket JSON contracts), citation/security/changelog policy, and dev notes recording encoder/translation timings and remote-GPU workflow.
