# Retrieval Practice: CodeVoice: AI-Powered Technical Interview Simulator

### Q1. What are the four layers of the CodeVoice system architecture and what role does each play?

> [!tip]- Answer
> > The browser client (`test_room.html` + LiveKit client) captures and plays audio over WebRTC, the LiveKit server (Docker, port 7880) routes audio between parties, the AI bot pipeline (`src/apps/simulation`) runs the voice-to-voice interview loop, and the Django control plane handles users, sessions, PostgreSQL persistence, and the Celery + Redis task queue. See [[wiki/01-codevoice-overview|CodeVoice: AI-Powered Technical Interview Simulator]].

### Q2. Describe the 7-stage Pipecat voice pipeline and the frame types that flow through it.

> [!tip]- Answer
> > Audio flows as `transport.input()` → Deepgram STT → user aggregator → Krutrim LLM → Deepgram TTS → `transport.output()` → assistant aggregator. The stages exchange AudioRawFrame, TranscriptionFrame, TextFrame, LLMMessagesFrame, and TTSAudioRawFrame, each processor transforming its input frames into output for the next stage. See [[wiki/01-codevoice-overview|CodeVoice: AI-Powered Technical Interview Simulator]].

### Q3. How does CodeVoice decide when the candidate has finished speaking, and why does that matter?

> [!tip]- Answer
> > Turn detection uses `LocalSmartTurnAnalyzerV3` (an ONNX model) via `TurnAnalyzerUserTurnStopStrategy`, analyzing silence duration, speech patterns, and end-of-sentence markers to distinguish natural from thinking pauses. The LLM is triggered only when the user is judged done, preventing the bot from interrupting mid-sentence. See [[wiki/01-codevoice-overview|CodeVoice: AI-Powered Technical Interview Simulator]].

### Q4. How does the two-token LiveKit design work, and what is the browser refresh quirk?

> [!tip]- Answer
> > The bot token (identity `ai-interviewer`, generated by `run_bot.py`) and the user token (identity `human-candidate`, generated by `get_user_token.py`) both grant join plus publish/subscribe audio rights in room `interview-room-1`. Because an open `test_room.html` tab keeps its old LiveKit connection alive, the page must be refreshed after restarting the bot, regenerating a token, or changing room config. See [[wiki/01-codevoice-overview|CodeVoice: AI-Powered Technical Interview Simulator]].

### Q5. What does `run_ai_bot()` do, and which management commands launch the bot and join the user?

> [!tip]- Answer
> > `run_ai_bot(room_url, token, room_name)` initializes STT/LLM/TTS, creates the LiveKit transport, builds the Pipecat pipeline, registers the `on_first_participant_joined` greeting and `on_participant_left` cleanup handlers, and manages `LLMContext`. `python src/manage.py run_bot` generates the bot token and starts it with asyncio, while `python src/manage.py get_user_token` prints the user token prefixed by `✅ HERE IS YOUR TOKEN`. See [[wiki/02-simulation-app|1. Simulation App (`src/apps/simulation/`)]].

### Q6. What are the `Question`, `InterviewSession`, and `InterviewTurn` models, and how does the Users app harden identity?

> [!tip]- Answer
> > `Question` holds `text`, `difficulty` (EASY/MEDIUM/HARD), and `expected_key_points` for grading; `InterviewSession` is a `Started` → `Completed`/`Failed` state machine with `user`, `status`, `total_score`, and timestamps; `InterviewTurn` records each exchange with `ai_message`, `user_transcript`, `audio_file`, and a 0–10 `score`. The custom `User` inherits `AbstractUser` but uses UUID primary keys to prevent ID enumeration attacks. See [[wiki/02-simulation-app|1. Simulation App (`src/apps/simulation/`)]].

### Q7. (Evaluation) Which roadmap item should the CodeVoice team build next, and why?

> [!tip]- Answer
> > Advanced evaluation (automatic scoring against `expected_key_points` plus code execution) should come first, because the current bot holds free-form voice conversations while scoring and grading remain unimplemented placeholders. It directly converts the persisted `InterviewTurn` transcripts and scores into the product's core value — credible interview assessment — before dashboard or recording polish. See [[wiki/02-simulation-app|1. Simulation App (`src/apps/simulation/`)]].
