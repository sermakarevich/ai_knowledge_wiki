# CodeVoice: AI-Powered Technical Interview Simulator — Digest

## 1. [[wiki/01-codevoice-overview|CodeVoice: AI-Powered Technical Interview Simulator]]
**In one sentence:** CodeVoice is a real-time voice-to-voice AI interviewer that routes browser audio through LiveKit to a Pipecat pipeline (Deepgram STT/TTS + Krutrim LLM) backed by a Django control plane.
- Service-oriented architecture with three layers: browser client (`test_room.html` + LiveKit client over WebRTC), LiveKit server router (Docker, port 7880), AI bot pipeline (`src/apps/simulation`), and Django control plane (user management, sessions, PostgreSQL, Celery + Redis task queue).
- Bot voice pipeline is a 7-stage Pipecat assembly line: `transport.input()` → STT → user aggregator → LLM → TTS → `transport.output()` → assistant aggregator, passing AudioRawFrame, TranscriptionFrame, TextFrame, LLMMessagesFrame, and TTSAudioRawFrame between stages.
- Speech services are Deepgram for both STT (default streaming model) and TTS (voice `aura-helios-en`); the brain is Krutrim AI (OpenAI-compatible) with model `gpt-oss-120b` at endpoint `https://cloud.olakrutrim.com/v1`.
- Turn detection uses `LocalSmartTurnAnalyzerV3` (ONNX) via `TurnAnalyzerUserTurnStopStrategy` to distinguish natural vs. thinking pauses using silence, speech patterns, and end-of-sentence markers, so the LLM is only triggered when the candidate is done speaking.
- Conversation memory is a full `LLMContext` message list (system → assistant → user → assistant) sent to the LLM each turn, enabling greetings, follow-ups, and contextual evaluation.
- Two LiveKit tokens gate the room `interview-room-1`: bot token (identity `ai-interviewer`, generated by `run_bot.py`) and user token (identity `human-candidate`, generated by `get_user_token.py`), each with join plus publish/subscribe audio permissions.
- Browser connection persistence quirk: an open `test_room.html` tab keeps its old LiveKit connection alive, so the page must be refreshed after restarting the bot, regenerating a token, or changing room configuration.

## 2. [[wiki/02-simulation-app|1. Simulation App (`src/apps/simulation/`)]]
**In one sentence:** The Simulation App is the heart of the AI functionality, running `run_ai_bot(room_url, token, room_name)` as a `Audio In → STT → User Aggregator → LLM → TTS → Audio Out` Pipecat pipeline over LiveKit with `on_first_participant_joined` / `on_participant_left` handlers, launched via `python src/manage.py run_bot` and joined via `get_user_token`, alongside the Interviews/Users/Config apps and a Docker + `.env` + migrate setup.
- Main pipeline function is `run_ai_bot(room_url, token, room_name)`, which initializes STT/LLM/TTS, creates the LiveKit transport, builds the Pipecat pipeline, sets up event handlers, and manages conversation context.
- Audio flows as `Audio In → STT → User Aggregator → LLM → TTS → Audio Out`, with Transcription and Synthesized Speech as side outputs.
- `on_first_participant_joined` greets the user and starts the interview; `on_participant_left` cleans up when the user disconnects.
- `python src/manage.py run_bot` loads LiveKit credentials from Django settings, generates a bot token, and launches `run_ai_bot()` with asyncio; `python src/manage.py get_user_token` creates a LiveKit access token with identity/permissions and prints it with the `✅ HERE IS YOUR TOKEN` prefix.
- Interview data model is `Question` (`text`, `difficulty` EASY/MEDIUM/HARD, `expected_key_points`), `InterviewSession` (state machine `Started` → `Completed`/`Failed` with `user`, `status`, `total_score`, `started_at`, `completed_at`), and `InterviewTurn` (`session`, `question`, `ai_message`, `user_transcript`, `audio_file`, `score` 0–10).
- Custom `User` inherits from `AbstractUser` and uses UUIDs instead of sequential integers to prevent ID enumeration attacks.
- Setup requires Docker Desktop, Python 3.10+, and Deepgram + Krutrim API keys; `docker-compose up -d` provides `codevoice_db`, `codevoice_redis`, `codevoice_livekit`, and `.env` must define `DEBUG`, `DATABASE_URL`, `REDIS_URL`, `DEEPGRAM_API_KEY`, `KRUTRIM_API_KEY`, `LIVEKIT_API_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`.

## The argument in five moves
1. CodeVoice frames the technical interview as a real-time voice loop, splitting the system into a browser client, a LiveKit audio router, a Pipecat AI bot pipeline, and a Django control plane.
2. The bot turns audio into answers through the 7-stage pipeline (transport input → Deepgram STT → user aggregator → Krutrim `gpt-oss-120b` LLM → Deepgram `aura-helios-en` TTS → transport output), gated by ONNX turn detection and full `LLMContext` history so it waits for turn end and responds in context.
3. Access is controlled by the two-token LiveKit design (`ai-interviewer` bot token via `run_bot.py`, `human-candidate` user token via `get_user_token.py` for room `interview-room-1`), with the refresh-the-tab quirk as the operational cost of persistent browser connections.
4. The Simulation App implements that loop in code via `run_ai_bot()` plus join/leave handlers and the `run_bot` / `get_user_token` management commands, while the Interviews app persists `Question` / `InterviewSession` / `InterviewTurn` scoring state and the Users app hardens identity with UUID keys.
5. All of this is made runnable by the Docker + `.env` + migrate setup (Postgres, Redis, LiveKit, Deepgram/Krutrim keys), verified through the start-bot → token → `test_room.html` workflow and troubleshooting guides, and pointed at a roadmap of orchestrator API, WebSocket status, dashboard, advanced evaluation, and recording.
