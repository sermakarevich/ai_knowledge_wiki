# Endpoint Anticipation: method, experiments, and Unmute integration
**In one sentence:** The chunk proposes Endpoint Anticipation — proactive speech-only forecasting of end-of-turn up to 2.56 s ahead to enable speculative LLM-TTS execution — with new latency-vs-redundancy metrics, EPA-S/EPA-M models that beat VAP baselines, and a Unmute integration cutting average latency by 505 ms at 28.4% extra compute.
## Key points
- Shifts from reactive endpoint detection to proactive forecasting of end-of-turn (EOT) signals, anticipating endpoints up to 2.56 seconds in advance to speculatively execute LLM and TTS pipelines on partial context.
- Introduces four metrics separating success from waste: Median Realized Anticipation (MRA), Premature Anticipation Rate (PAR), Expected Redundant Computation (ERC), and Horizon Entry Accuracy (HEA).
- Formulates anticipation as independent binary classification over horizons H = {320, 640, …, 2560} ms at 12.5 Hz frame rate, with trigger threshold θ (Eq. 3) tuning latency reduction versus premature predictions.
- Trains two variants — EPA-S (|H| independent single-horizon models) and EPA-M (shared dual-stream backbone with horizon-specific heads) — with comparable accuracy, but EPA-M avoids horizon-specific retraining.
- At h = 640 ms and ≈33% ERC on SpokenWOZ, EPA-M achieves 640 ms MRA and 67.0% HEA versus VAP's 160 ms MRA and 19.2% HEA; at h = 1280 ms and ≈15% ERC, EPA-M achieves 480 ms MRA and 22.1% HEA versus VAP's 80 ms MRA and 7.2% HEA.
- Anticipation is easier on structured task-oriented SpokenWOZ than spontaneous Switchboard conversation, yielding higher MRA at fixed PAR and higher HEA at fixed ERC for both h = 960 ms and h = 2560 ms.
- Unmute integration (EPA-M, h = 960 ms) reduces average latency from 1195 ms to 690 ms (505 ms saving) with 28.4% ERC, masking ASR-LLM-TTS sequential bottlenecks via trigger-fork, pre-synthesis cache, and verification.

## 1. Introduction
**Covers:** reactive bottleneck → endpoint anticipation → contributions

Cascaded architectures (e.g. Unmute) are bottlenecked by reactive turn-completion detection: endpoint triggers sequential ASR → LLM → TTS, imposing a Time-to-First-Audio (TTFA) lower bound, with modular setups near 1–2 s versus ~250 ms human response gaps.

Proposed fix:

> "shifting from reactive detection to proactive forecasting of end-of-turn signals"

Early forecast lets the system "initiate LLM and TTS processing during the user's" speech, so "the generation process to significantly mask system latency."

Contributions (verbatim):
1. Speech-based Endpoint Anticipation task and model for low-latency spoken dialogue.
2. Metrics quantifying Realized Anticipation versus Premature Anticipation (downstream redundancy from predictions before the valid horizon).
3. Evaluation across anticipation targets 320 ms to 2560 ms.
4. Open-source implementation plus reference Unmute integration.

## 2. Related Work
**Covers:** early EOU prediction, VAP, computation-intensive SDS

- Early End-of-Utterance Prediction: Sakuma et al. two-stage streaming-ASR hypothesis + LM EOU prediction; Chang et al. prefetch via confidence threshold (differs: this work uses fixed anticipation horizon, decoupled from ASR confidence); Zink et al. encoder-decoder ASR decoder for early EOU. Unlike these text-dependent approaches: "our work introduces a speech-only forecasting model that operates directly on the acoustic signal, entirely bypassing the ASR bottleneck."
- Voice Activity Projection (VAP): projects two-speaker future voice activity with TURN-SHIFT task over discrete bins; this work targets "continuous, fixed-horizon endpoint forecasting" and adapts VAP probabilities as the primary baseline.
- Computation-Intensive SDS: chain-of-thought SDS, KAME secondary LLM over partial transcripts, Stream RAG audio tool-calling; cascaded systems remain sequentially bottlenecked, and this framework lets "modular pipelines to integrate complex processing while preserving low-latency interactions."

## 3. Proposed approach
**Covers:** §3.1–3.3, Eq. 1–5

### 3.1 Dual-stream audio representation
Processes User (u) and System (s) streams with independent streaming Transformer encoders Tu, Ts:

`Z≤t(u) = Tu(X≤t(u)), Z≤t(s) = Ts(X≤t(s))` (Eq. 1)

Concatenated context `Z≤t = [Z≤t(u); Z≤t(s)]` feeds prediction heads, letting the model learn anticipation amid backchannels and interruptions.

### 3.2 Endpoint Anticipation (EPA)
Independent binary tasks per horizon h ∈ H. Target (Eq. 2):

`y_t(h) = 1 if 0 ≤ tEOT − t ≤ h, 0 otherwise`

At 12.5 Hz (80 ms period), h = 320 ms equals exactly 4 frames. Inference decision (Eq. 3):

`ŷ_t(h) = 1 if p_t(h) ≥ θ, 0 otherwise`

Deployment: "the first frame where ŷ_t = 1 acts as the trigger for the speculative pipeline."

### 3.3 Model architectures
- EPA-S (Single-Target): |H| independent models; `p_t(h) = σ(W·Z≤t + b)` (Eq. 4); cost scales linearly with |H|; loss on one primary speaker, other speaker as context.
- EPA-M (Multi-target): shared dual-stream backbone, final-layer branching: `p_t(h) = σ(Wh·Z≤t + bh), ∀h ∈ H` (Eq. 5); learns generalized turn-completion features with horizon-specific boundaries.

## 4. Experimental setup
**Covers:** §4.1–4.5, datasets, baseline, metrics, training, Unmute speculative design

### 4.1 Dataset
SpokenWOZ (8 kHz, task-oriented) and Switchboard (8 kHz, conversational); User / Speaker A as primary. Silero VAD strips trailing silence; loss masked for turns < 2 s (plus min 3 words for Switchboard) to exclude backchannels and prevent onset predictions.

### 4.2 Baseline
Pretrained VAP adapted from 50 Hz discrete bins to continuous 12.5 Hz evaluation: non-active speaker's p-future probabilities downsampled via 4-frame mean pooling; best p-bin combination reported — bins [0–1] (0–600 ms) for 640 ms window, bins [1–2] (200–1200 ms) for 1280 ms window.

### 4.3 Metrics
- Median Realized Anticipation (MRA): for turns with successful prediction in [tEOT−h, tEOT], median of tEOT − tpred; actual latency savings.
- Premature Anticipation Rate (PAR): % turns with ≥1 activation before valid window (tpred < tEOT−h); wasteful downstream compute.
- Expected Redundant Computation (ERC): actual premature anticipations / max possible `⌈(T−h)/h⌉` for turn length T, mean %; corrects PAR's duration bias; quantifies discarded speculative compute.
- Horizon Entry Accuracy (HEA): binary task triggering exactly at t = tEOT−h; predictions in two-frame collar {t, t+1} are true positives, [t+2, tEOT] false positives.
- Computed only for turns with T > h; reported as latency vs. early-trigger curves over thresholds.

### 4.4 Training setup
- Features: Mimi neural codec (first 8 codebooks); 24 kHz upsampled input, 12.5 Hz features, zero lookahead; backbone frozen for modular reuse.
- Model: 25M streaming Transformer, 6-layer encoder, 4 heads, FFN 1024, RoPE + causal masking with 250-frame left context.
- Optimization: trained on both datasets; lr 3×10⁻⁴, batch 16, 500-frame (40 s) segments; 10:1 positive:negative weighted loss; loss masked < 2 s turns; early stopping on mean horizon/non-horizon accuracy, patience 6 epochs.

### 4.5 Speech-to-speech integration (Unmute)
Baseline: modular streaming ASR + TTS + LLM (Gemma 3 4B, vLLM), semantic-VAD endpointer, Rust WebSocket server + Python client.

Speculative execution:
1. Trigger & Fork: on anticipated endpoint with horizon h, fork state, LLM generates ~10-token look-ahead buffer from partial transcript.
2. Pre-Synthesis (Cache): tokens fed to TTS, audio frames held in speculative cache, not played.
3. Verification: wait h — success (endpointer confirms within window): release cache, continue from full transcript + generated tokens; failure (no endpoint by end of h): resume anticipation, discard cache on next anticipated endpoint. When cache hits, "system latency is reduced to the response time of the endpointer alone."

Evaluation: Full-Duplex Bench V1 protocol; Average Latency + ERC; interruption handling omitted as orthogonal.

## 5. Results and Discussion
**Covers:** §5.1–5.4, Figure 1–2, Table 1–2

### 5.1 VAP vs EPA
EPA-M dominates VAP in MRA-vs-PAR and HEA-vs-ERC spaces at h ∈ {640, 1280} ms on SpokenWOZ. VAP's generalized training "struggles to produce precise, fixed-horizon endpoint forecasts."

| Model | h | MRA (ms) ↑ | HEA (%) ↑ | PAR (%) ↓ | ERC ↓ |
|---|---|---|---|---|---|
| VAP | 640 | 160 | 19.2 | 68.3 | 34.5 |
| EPA-S | 640 | 640 | 66.3 | 66.5 | 33.9 |
| EPA-M | 640 | 640 | 67.0 | 66.2 | 33.8 |
| VAP | 1280 | 320 | 20.8 | 51.0 | 33.8 |
| EPA-S | 1280 | 1200 | 50.3 | 53.9 | 33.7 |
| EPA-M | 1280 | 1120 | 49.7 | 52.8 | 33.2 |
| VAP | 1280 | 80 | 7.2 | 28.8 | 15.4 |
| EPA-S | 1280 | 480 | 22.0 | 34.4 | 15.1 |
| EPA-M | 1280 | 480 | 22.1 | 34.3 | 15.1 |

Table 1: two operating points ERC ≈ 33% and ≈ 15%.

At ≈33% ERC (33% redundant compute from early discarded predictions), PAR is comparable but EPA-M has far higher HEA/MRA (e.g. h = 640 ms: 640 ms vs 160 ms). At ≈15% ERC, EPA-M holds 480 ms MRA / 22.1% HEA while "VAP yields negligible anticipation."

### 5.2 Conversational vs task-oriented
SpokenWOZ beats Switchboard Eval2000 at h = 960 ms and h = 2560 ms: higher MRA at fixed PAR, higher HEA at fixed ERC. Open-domain spontaneity is harder; anticipation "currently most viable for structured applications."

### 5.3 Architecture (EPA-S vs EPA-M)
"Both models show comparable results, displaying only minor deviations"; EPA-M preferred because it deploys across horizons "without requiring horizon-specific retraining."

### 5.4 System integration
| System | Avg. Latency (ms) ↓ | ERC (%) ↓ |
|---|---|---|
| Unmute Baseline | 1195 | – |
| Unmute + EPA-M | 690 | 28.4 |

Table 2: EPA-M (h = 960 ms). 505 ms reduction with local LLM/TTS (larger gains expected for API models). Residual ~690 ms from low-anticipation turns, semantic-VAD delays, inter-process WebSocket. 28.4% ERC ≈ discarded speculative compute share of theoretical max, eased by efficient inference and shared feature extractor.

## 6. Conclusion
**Covers:** §6–8

Forecasting EOT before completion enables speculative ASR/LLM/TTS; EPA-S/EPA-M plus latency-vs-redundancy metrics; multi-target EPA-M beats VAP on conversational and task-oriented data; Unmute: −505 ms latency at +28.4% speculative compute, masking sequential bottlenecks. Code to be open-sourced; future work: semantic edge cases "such as mid-turn backtracking and late-arriving critical information." GenAI disclosure: Gemini 3 Pro for language refinement only.
