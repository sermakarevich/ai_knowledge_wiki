# Speech schedulers and latency model
**In one sentence:** Each speech scheduler converts irregular gappy speech segments into gapless 200 ms present / 205 ms future window pairs via four admission rules (left-pad, fragment-split, right-pad-at-end, one-boundary-per-window), from which the streamer contributes a response latency of 305–705 ms and an interruption latency of 305–505 ms — both confirmed against OpenAI Realtime and Cartesia Line measurements.
## Key points
- Scheduler role (a component of the rendering worklet, one instance per stream): turns segments with gaps and arbitrarily sized fragments into a continuous gapless sequence of uniformly sized present+future window pairs matching the model's 200/205 ms training windows; completing a future window always means filling it fully.
- Iteration mechanics: each iteration promotes a prefix of the future window to the present window unchanged and builds a new future-window suffix, so present window k+1 is decided on iteration k; markers/fragments enter from the input queue or silence pads the rest.
- Four admission rules: R1 left-pads silence when an admitted segment prefix is shorter than the window (fragments placed at window end); R2 splits an over-long next fragment and re-queues the suffix while a segment is active; R3 right-pads silence at an admitted end marker (all-silence window when no segment is active); R4 never admits the next segment's start into a window where another segment ends.
- Blocking behavior: normally never blocks; if an active segment's fragments arrive late (jitter), the scheduler blocks until they arrive rather than substituting silence — the delayed request surfaces as a playback pause, not response latency.
- Interruption: discards unadmitted fragments/segments, reports admitted-vs-discarded amounts to the bus so a faster-than-real-time voice agent can retract unheard speech from dialogue state; assigns media timestamps to markers and interruption/discard events, delivered at media time rather than wall-clock time.
- Response latency contribution (RLC): from the conversation engine receiving a reply's start marker + first fragment to the first frame carrying that speech reaching the transport; E[T] = Tlead + Tpresent + E[Twait] + E[Tpad] with Tpresent = 200 ms, Tlead = 100 ms, Twait ∈ [0, 200) ms (wait for next iteration), Tpad ∈ [5, 205) ms (left-silence padding behind a 5 ms non-replaceable carried-over prefix) — floor 305 ms, strictly below 705 ms, realistic ceiling mid-600 ms.
- Interruption latency contribution (ILC): voice-agent interruption signal to end of avatar-speech playback; same Twait/Tlead/Tpresent terms (committed present window always plays in full) but Tpad falls to its 5 ms floor because discarding fills the future window with outright silence — floor 305 ms, below 505 ms.
- Derivation conditions: real-time fragment arrival within segments, voice agent exposing discrete speech start/end markers (a marker-less continuous synthesizer is a session-long segment where the RLC bound does not apply), and non-blocking iterations.
- Design trade-offs: R1's bounded padding beats waiting for a full speech window (which would add a fixed 200 ms) for any first-fragment distribution with mean below 200 ms; right-padding would pause mid-speech and feed out-of-domain data; one-chunk render-ahead fixes the promotion term; only Tlead is free.
- Measured validation (Table 3, first 10 reply+interruption exchanges each): OpenAI Realtime RLC 390.4 [315, 491] ms / ILC 362.7 [310, 409] ms; Cartesia Line RLC 454.2 [426, 497] ms / ILC 393.3 [345, 473] ms — every term inside predicted bounds, terms summing to totals within 1 ms logging resolution; Tpresent constant, Tlead ~1–2 ms under configured 100 ms (single-thread loop artifact), agents differing only in deployment-dependent Tpad (OpenAI's large fragments hold the 5 ms floor; Cartesia's smaller fragments raise it in 40 ms-frame multiples).
- End-to-end budget (Table 4, Cartesia): inbound transport 114 ms + streamer→agent hop 5 ms + voice agent 1090 ms (transcription/endpointing 300, LLM TTFB 650, sentence aggregation 20, TTS TTFB 120) + agent→streamer hop 5 ms + streamer RLC 454 ms + outbound 89 ms = 1757 ms end to end — the voice agent dominates, the streamer is second, and the 1500 ms voice-to-voice target is unreachable without cutting voice-agent latency.

## Latency vocabulary
RLC/ILC are the streamer's own contributions (response/stop latency axes from voice-agent turn-taking evaluation); transport and voice-agent latencies sit outside them; the renderer enters only through Tlead covering TTFF, so the contribution is otherwise deployment-insensitive.
