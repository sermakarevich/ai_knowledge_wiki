# NemotronLabs VoiceChat: An Open Full-duplex Speech-to-Speech Model with Tool Calling Capabilities

**Paper:** [NemotronLabs VoiceChat: An Open Full-duplex Speech-to-Speech Model with Tool Calling Capabilities](https://arxiv.org/abs/2609.21967)

## Human Readable TL;DR

Most voice assistants work like a walkie-talkie: they wait until you go completely silent, then think, then answer, and they cannot look anything up mid-sentence without freezing. NemotronLabs VoiceChat works more like a natural phone call where both people can listen and talk at the same time, politely pausing for an "uh-huh," yielding instantly when interrupted, and picking up the thread right after. At the same time it behaves like a receptionist who can put you on a brief, natural hold ("let me check that for you") while calling another department for facts, then come back with the answer. The result is claimed to be the first fully open system that combines this human-like conversational timing with the ability to call external tools, instead of forcing a choice between sounding natural and being useful.

## TL;DR

NemotronLabs VoiceChat is presented as an open unified streaming speech-to-speech model that listens, transcribes, reasons, invokes tools, and speaks concurrently within a single architecture built around a 600M-parameter cache-aware FastConformer streaming encoder, the NVIDIA Nemotron-Nano-9B-v2-Base decoder-only LLM, parallel specialized output streams for agent text and structured function calls, an auxiliary RNN-T branch for incremental user transcription, and a separately trained streaming VoiceChat-TTS codec decoder. The central design claim is that parallel specialized streams preserve low-latency full-duplex behavior because tool interaction never has to be serialized into the conversational text channel the way DuplexSLA serializes planning and action tokens, while a single-pass perception module feeds both the LLM and the transcription branch so no second ASR encoder is needed. Reported results include the lowest pause-handling takeover rates among evaluated open-weight systems on Full-Duplex-Bench 1.0 (15.3% synthetic, 25.5% CANDOR), 100% takeover following user interruptions at 480 ms latency with 4.33/5 post-interruption quality, 93% response resumption after user backchannels on FDB 1.5, a 55.1 normalized VoiceBench average, and 82.5% tool-selection F1 on FDB 3.0 with argument accuracy (42.2%) and end-to-end Pass@1 (33.0%) acknowledged as remaining weaknesses.

## Problem & Motivation

The paper frames conventional voice agents as half-duplex cascaded stacks in which an ASR module feeds a chat LLM whose text output is rendered by TTS, with the whole pipeline gated by a voice-activity-detection module that waits for the user to stop speaking before responding. Human dialogue, by contrast, is inherently full-duplex: speakers continuously listen while speaking and negotiate turns with fine temporal precision through backchannels, overlaps, hesitations, and interruptions, so low-latency speech generation alone does not reproduce conversational dynamics. Prior full-duplex research is characterized as having concentrated on realtime interaction mechanics such as explicit dialogue-state control, synchronous listening-while-speaking architectures, joint modeling of user and assistant audio streams, and modular or controllable conversational behavior, while leaving tool use during full-duplex interaction largely unexplored. Proprietary systems such as the OpenAI Realtime API and Gemini Live already emit structured function calls or support asynchronous tool returns during realtime sessions, and adjacent open work such as DuplexSLA adds a rate-limited textual action channel while MoshiRAG demonstrates asynchronous retrieval without suspending conversational flow, but the stated gap is an open unified model that combines general intelligence, conversational naturalness, transcription accuracy, and tool calling without multiple models or API handoffs and without sacrificing realtime behavior.

## Main Original Ideas

1. **Parallel specialized streams for text, tools, and transcription** — instead of serializing heterogeneous action tokens into one shared autoregressive channel as DuplexSLA does, the architecture maintains separate agent-text and function-call output heads feeding the decoder-only LM plus a parallel user-transcription path, so tool interaction integrates without disturbing the conversational output stream or its latency.

2. **Single-pass streaming perception with dual representations** — a 16-kHz, 128-bin log-Mel front end with 25-ms Hann window and 10-ms stride feeds a 600M-parameter, 24-layer cache-aware FastConformer encoder with 1,024 hidden dimensions, causal depthwise-striding subsampling (8x) producing one state every 80 ms under strictly causal attention (70-frame left context, no right context, causal convolutions); the same encoder states are exposed raw to the RNN-T branch and projected through an identity modality adapter into the LLM, avoiding a second ASR encoder and keeping transcription synchronized with response context.

3. **Frame-level turn-taking supervision on a shared timeline** — agent responses are supervised on the same 80-ms grid with ordinary BOS/EOS tokens repurposed as begin/stop targets (BOS at response onset, subwords in consecutive frames, EOS after brief overlap when the next user turn begins, padding meaning remain silent), distinct from the function-channel boundaries `<SOTC>`, `<EOTC>`, and `<EOTR>`, so the model learns when to speak, stay silent, and yield.

4. **Decoupled auxiliary RNN-T transcription branch** — a two-layer 640-dimensional recurrent prediction network plus 640-dimensional joint network with a 1,024-unit BPE vocabulary plus blank decodes incrementally from the shared encoder states and is exposed as an auxiliary output rather than fed into the LLM, preserving a direct speech-conditioned response path while also serving as the signal for a fallback endpointing mechanism that force-injects BOS/EOS tokens when native turn-taking or barge-in fails.

5. **Persistent streaming TTS with interaction-aware decoding** — the separately trained VoiceChat-TTS decoder stays active across the conversation timeline, generates silence under upstream padding control, and responds to explicit interruption signals without resetting cached state, trading some isolated-response WER against the silence-handling and interruption behavior a full-duplex system requires.

6. **Component-wise training with duplex-specific data and losses** — the full-duplex STT backbone is optimized through CPT and SFT with audio-codec prediction disabled (audio-loss weight 0.0) and no gradients between backbone and TTS, followed by a frozen-backbone RNN-T stage trained with standard transducer loss; the STT loss combines weighted agent-text, function-channel, and text-to-text terms with heavily upweighted sparse boundary and tool-content tokens, while SFT assembles TTS-rendered turns onto a two-channel duplex timeline with early-interruption truncation, backchannel injection, text-channel delay, and stronger acoustic augmentation, plus a multi-agent pipeline for tool-calling data that cannot be obtained by rendering existing text corpora.

7. **Spoken tool-call protocol with latency masking** — tools are declared in the system prompt inside `<AVAILABLE_TOOLS>` with a `<TOOLCALL>[...]</TOOLCALL>` / `<TOOL_RESPONSE>[...]</TOOL_RESPONSE>` format rendered by a Jinja template, and each tool can define a filler message spoken as soon as the triggering text is generated so its duration masks tool-execution delay, skippable for fast tools and extended for slow ones.

## Key Findings

Turn management on Full-Duplex-Bench 1.0 shows the V-Model at 15.3% synthetic and 25.5% CANDOR pause takeover rates, the lowest among reported open-weight systems, alongside 81.5% smooth-turn takeover at 448 ms latency and 100% user-interruption takeover at 480 ms with the highest post-interruption quality score of 4.33 on the GPT-4o 0–5 scale, though PersonaPlex achieves higher smooth-turn takeover (90.8%) at lower latency and GPT-Realtime achieves lower pause rates and higher smooth-turn takeover while responding more slowly and scoring lower after interruptions. On the FDB 1.5 user-backchannel condition the model resumes its response in 93% of cases with only 1% unnecessary responses, exceeding Freeze-Omni's 80% by 13 points, exactly matching the evaluated Gemini Live 2.0 endpoint across all four behavior categories, and beating GPT-4o Realtime's 70% resume rate while showing a much lower unknown rate. Intelligence evaluation on VoiceBench gives a 55.1 normalized average that improves over Moshi by 25.6 points and PersonaPlex by 24.5 points and effectively ties Freeze-Omni at 55.2, with large gains on OpenBookQA (61.3), MMSU (46.1), and AdvBench safety (100.0) offset by weaker SD-QA, open-ended quality subsets, and IFEval, while the cascaded DuplexCascade (65.4) and omni-modal MiniCPM-o 4.5 (76.1, different judge) serve only as system-level references. Spoken tool use on FDB 3.0 under disfluent human speech and chained calls yields 82.5% tool-selection F1 ahead of both Gemini Live baselines, but argument accuracy of 42.2% and Pass@1 of 33.0% trail them, and because Pass@1 requires exactly the expected tools with perfect arguments, the gap indicates routing is substantially stronger than argument extraction and end-to-end execution. Supporting measurements show the standalone VoiceChat-TTS reaching 2.00% WER and 4.380 SQuIM-MOS on first unseen-speaker turns with stable multi-turn intelligibility but zero-shot speaker drift (SECS 0.757 to 0.685 over four turns versus 0.785 to 0.778 for seen speakers), streaming ASR averaging 9.02% WER at 80-ms chunks improving to 8.28% at 160 ms without retraining, and inference at 118 ms per-stream p95 per 160-ms chunk (1.36x realtime with four concurrent streams on one H100).

## Suggestions & Future Directions

The paper's stated limitations point directly at extending the roughly two-minute audio context window so longer conversational history is retained reliably, and at closing the tool-use gap between strong routing and weak argument extraction by improving argument accuracy, end-to-end execution, simultaneous multi-tool invocation, and resistance to invented arguments, skipped or misselected calls, and answering from internal knowledge when a tool should be invoked. Practical guidance in the notes includes exposing no more than five tools per session, designing filler messages whose spoken duration matches each tool's expected latency, and addressing delayed speech after long tool responses along with the current inability to barge in while a tool executes. Robustness work remains in noisy and reverberant conditions with competing speech, where the authors acknowledge limited resilience, and in reconciling the persistent-decoding demands of full-duplex TTS (silence generation, interruption without state reset, speaker-identity stability for zero-shot voices) with the isolated-response quality where conventional TTS systems still score better.
