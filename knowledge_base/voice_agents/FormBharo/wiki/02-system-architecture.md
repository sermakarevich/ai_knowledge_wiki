# System Architecture: Hybrid LLM plus Rule-Based Pipeline
**In one sentence:** FormBharo fills a structured form over a phone call by chaining VAD-gated STT, an EXTRACT LLM that pulls every answered field plus a latency-masking acknowledgement from transcript and history, a rule-based layer that validates values, manages retries and branches, updates the form state and picks the next question, and a REPLY LLM plus TTS that speaks the next question naturally — a design whose model choice is made by Pareto-optimal weighted-sum scalarization across accuracy, latency, and cost because component accuracy does not predict end-to-end form completion.
## Key points
- The call flow is: Voice Activity Detection (VAD) detects the caller stopped speaking, an STT model transcribes the audio, EXTRACT reads transcript plus conversation history, the rule-based layer validates and updates form state and picks the next question, REPLY phrases it naturally, and TTS speaks it back — or the LLM decides to end the call if all fields are answered.
- EXTRACT extracts every field answered in that turn so already-answered questions are not re-asked; the form has free-text, number, date, boolean, and categorical types, and for categorical fields EXTRACT returns the option index rather than the option text.
- In parallel with extraction, EXTRACT generates a short acknowledgement that TTS speaks back to reduce perceived latency.
- The rule-based layer validates each value against field-specific guards (e.g. a minimum length, 10 digits for a phone number, a date restricted to the past); on missing/invalid values it checks per-field maximum retries, passes the validation error plus history to REPLY to re-ask if retries remain, ends the call if a required field exhausts retries, and for an optional field either ends the call or skips it per the field-specific setting.
- Optional-field declines are handled without retries: EXTRACT detects when the caller declines or does not know the answer (the skip flag) and the field is skipped; validated values are written to the form state, the single source of truth for which fields are answered.
- Branching and next-question selection stay rule-based: the flow-control evaluates whether branches activated/disabled (e.g. gestational age asked only if the caller says she is pregnant) and injects the decision into REPLY's history as a tool call, which REPLY phrases for TTS or uses to end the call when complete.
- Interruptions are handled gracefully: if the user starts speaking while agent inference is running, the current turn is terminated immediately and the agent waits for the user to stop speaking.
- End-to-end evaluation decides the configuration: turn-level extraction leaders on reference transcripts rank lower once chained, the rule-based layer recovers many extraction errors so smaller cheaper models match or surpass frontier models, errors both propagate and cancel across the pipeline, and no single model is best on accuracy, cost, and latency at once — so the authors discard deployment-constraint violators, keep Pareto-optimal ones, and rank the rest by weighted-sum scalarization (Marler and Arora 2010) with weights reflecting deployment priorities.

## System architecture (§2)
**Covers:** §2 System Architecture (design principle, call flow, EXTRACT, rule-based validation/retries/skip, form state, branching, REPLY, interruptions)
- Design principle, verbatim: "use LLMs only where they add value: interpreting user inputs, turning unstructured answers into structured fields, phrasing the next question naturally to be spoken back to the user, and deciding when the form is complete. Everything else stays rule-based: validation, retries, branching, and choosing the next question."
- Turn flow, verbatim: "Once the Voice Activity Detection (VAD) model detects that the caller has stopped speaking, an STT model transcribes the audio. The EXTRACT LLM reads the transcript together with the conversation history and extracts every field answered in that turn, so the agent does not re-ask questions already answered."
- Field types: "The form has fields of several types: free text, number, date, boolean, and categorical. For categorical fields, EXTRACT returns the index of the chosen option rather than the option text."
- Acknowledgement, verbatim: "In parallel, EXTRACT generates a short acknowledgement that the TTS model speaks back to reduce perceived latency."
- Validation and retries, verbatim: "The rule-based layer validates each extracted value against field-specific built-in guards, such as a specified minimum length, 10 digits for a phone number, or a date restricted to the past. When a value is missing or fails validation, it checks whether the maximum number of retries for that field is reached. If retries remain, the validation error is passed to REPLY LLM along with the conversation history, which asks the question again. Once retries are exhausted for a required field, the rule-based layer ends the call. For an optional field, it either ends the call or skips it, depending on the field-specific setting."
- Skip flag and form state, verbatim: "EXTRACT also detects when the caller declines or does not know the answer to an optional field (the skip flag). That field is then skipped without triggering a retry. When validation passes, the values are written to the form state, the single source of truth for which fields have been answered."
- Branching and REPLY, verbatim: "The form has several branches conditioned on the values of earlier fields. For example, gestational age is asked only if the caller says she is pregnant. The rule-based flow-control evaluates whether any of the form's branches have been activated or disabled, and decides the next question to ask. This decision is injected into the conversation history of REPLY LLM as a tool call. It phrases the question naturally for the TTS model to speak back to the caller, or ends the call if the form is complete."
- Interruption handling, verbatim: "Finally, if the user starts speaking while the agent's inference is running, the current turn is terminated immediately and the agent goes back to waiting for the user to stop speaking, so interruptions are handled gracefully."
## FormVoiceAgentBench overview (§3 lead) and benchmark statistics
**Covers:** §3 lead and Table 2 (benchmark scale; §3.1 Form Structure start)
- Benchmark framing, verbatim: "FormVoiceAgentBench is a Hindi benchmark, grounded in the maternal and child health enrollment form from our pilot, that pairs 380 audio recordings with 3,760 multi-turn conversation tests across 960 simulated calls (Table 2) without exposing any Personally Identifiable Information (PII) from real callers."
- Two evaluation levels, verbatim: "It evaluates the agent at two levels. Unit tests score each component in isolation: predicted transcripts against reference transcripts, extracted form data against the expected values, reply quality and ability to end the call given that the extraction was perfectly accurate. Integration tests chain the components to measure end-to-end form completion."
- Evaluation-design finding stated in chunk: "Our experiments show that component-level performance does not predict form completion: LLMs that lead turn-level extraction accuracy with reference transcripts as inputs rank lower once the components are chained. The rule-based layer recovers many extraction errors, helping smaller, cheaper models match or surpass frontier models on form completion. Since errors both propagate and cancel across the pipeline, the best configuration emerges only through end-to-end evaluation. Finally, no single model is the best across accuracy, cost, and latency at once."
- Model selection method, verbatim: "To pick the best combination of models, we discard those that fail to satisfy our deployment constraints, keep the Pareto-optimal ones, and rank the rest by weighted-sum scalarization (Marler and Arora 2010), with the weights reflecting our deployment's priorities."
