**What it shows.** The figure is a side‑by‑side conceptual comparison of two retrieval/reasoning paradigms over unstructured text. The left panel, *Vector Search* (muted gray), depicts a search‑beam illuminating a small cluster of document cards — "PROJECT DELAY," "SUPPLY CHAIN ISSUE," "BUDGET OVERRUN" — among a field of many fainter, unselected cards. The right panel, *Knowledge Graph* (blue), shows the same domain content re‑expressed as a node‑and‑edge network, with one fully highlighted, labeled causal chain: **SEVERE WEATHER EVENT →(caused) TRANSPORT DISRUPTION →(delayed) MANUFACTURING HALT →(reduced) QUARTERLY REVENUE**, plus auxiliary nodes ("FUEL COST INCREASE," "COMPETITOR LAUNCH") linked by unlabeled relations.

**Axes and trends.** There are no numeric axes, scales, or quantitative trends; this is a qualitative schematic, not a data plot. The only "trend" is structural: the visual progression from *similarity‑based selection* (a beam picking out top‑k semantically close documents) to *relation‑based reasoning* (a typed graph that exposes the causal pathway between entities).

**Takeaway.** Vector search answers "what looks similar" — it retrieves surface‑level semantic neighbors but cannot see the explicit links between them. A knowledge graph answers "what connects" — it encodes entities and the typed relations/causal edges among them, enabling inference over multi‑step chains (e.g., weather → transport → production → revenue) that a similarity search would miss. In short, the figure argues that for relationship‑ and causality‑aware retrieval, graph‑structured knowledge outperforms pure vector similarity.
