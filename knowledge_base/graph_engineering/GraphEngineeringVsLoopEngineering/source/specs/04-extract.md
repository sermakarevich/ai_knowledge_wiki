## What this chunk covers

This chunk covers (in Chinese, with [MM:SS] timestamps):
- The biggest misconception: hearing "graph" and assuming more nodes/more agents = more
  advanced. The actual root cause of most agent-system failures is the model acting as both
  player and referee for its own output.
- The graph's fix: split "reaching a conclusion" and "verifying it" into two independent nodes.
  One agent produces the conclusion; a separate agent, the **Verifier**, exists specifically to
  try to overturn the prior conclusion -- if the conclusion survives that attack, it passes; if
  not, it gets sent back for rework. The verifier is described as the single highest
  cost-to-value node in the whole graph.
- Checking intensity should match the stakes of the task -- this needs a **Router**, acting like
  a hospital triage desk, directing tasks to different-intensity check paths by importance.
- Three common verification patterns:
  1. **Adversarial** -- send multiple independent skeptics to try to refute the same
     conclusion; it only counts as solid if a majority fail to refute it.
  2. **Multi-perspective** -- check from different angles independently (correctness, safety,
     reproducibility), each checking its own dimension.
  3. **Judge panel** -- multiple candidate solutions are scored in parallel, a winner is picked,
     and good ideas from the other candidates are absorbed into it.
- Agent-to-agent verification alone is not enough. The most critical determinism comes from two
  places: **code** and **reality**. Deterministic work -- format validation, running tests,
  deduplication, sorting, etc. -- should be handed to ordinary code, not to another agent. An
  industry saying: "let the model's judgment live on the nodes, let code's reliability live on
  the edges." If every node in a graph only cross-references conclusions generated by other
  models, with no node actually touching reality, the whole thing is just a more elaborate
  self-congratulation machine. Real anchors must be hard facts that can't be argued away: a test
  that actually ran and passed, a user who actually stayed, money that actually landed in an
  account. What counts as "better" must ultimately be defined by a human, because every loop
  inside the graph presupposes that definition.
