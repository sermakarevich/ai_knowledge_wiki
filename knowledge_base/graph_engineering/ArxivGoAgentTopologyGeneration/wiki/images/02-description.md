**What the figure shows.** Figure 2 is a schematic (not a coordinate plot), so it has no numeric x/y axes; its "axis" is the left‑to‑right pipeline laid out in four teal‑headed stages — *Materials → Design → Optimize → Execution* — that together define the proposed system **GoAgent**. Each stage's internal flow is the "trend" to read: information enters as a task query and a pool of candidate agent groups, is compressed and selected into a directed graph, and is executed into an answer.

**Stage‑by‑stage content (the data flow).**
- *Materials (input side):* A Task Query **Q** (a math word problem, proposed by GPT‑4) and a Collaborative Group Pool **M** of *K* predefined groups (Code, Reason, Debugging, Eval), each specified by a schema of name, expertise, roles, and an *intra‑group* topology (chain, fully‑connected, star). A sentence encoder maps the query to a task vector **z_Q** ∈ ℝ^d and the group descriptions to an embedding matrix **X** (≈ K×d, padded with END tokens to (K+1)×d).
- *Design (generation side):* A Generator (using **z_Q** + History) produces a **CIB** (Conditioned Information Bottleneck) module that compresses a noisy raw feature **x_Q** into a clean, task‑relevant compressed feature. An autoregressive loop then alternates **Group Prediction** P(M_t | G_{<t}, z_Q) (picking the next group M_i) and **Edge Prediction** P(e | M_{t+1:t}, M_{<t}, G_{<t}, z_Q) (wiring it to prior groups), stepping t=1 → t=i+1.
- *Optimize (objective side):* A zoomed‑in view of the CIB shows the encoder posterior q_φ(c|x) and a *task‑conditioned* prior p_θ(c|z_Q), with a KL term (D_KL → L_KL). The annotated trend is the key design point: standard IB compresses "blindly," whereas CIB conditions on the task so it "only removes what's irrelevant to Q." The total loss combines group‑prediction, edge‑prediction, and compressed/KL regularization terms with a β warm‑up schedule.
- *Execution (output side):* The realized generated topology G = (M, E) (e.g., Code → Reason → Eval groups) is drawn with inter‑group edges (solid) vs. intra‑group edges (dashed). A pipeline legend — encode query → autoregressively select group → predict edges → execute with LLMs → final answer — leads to the *Output Solution*, noted as using **fewer tokens than baselines**.

**Takeaway.** GoAgent does not pick individual agent instances but autoregressively *generates a task‑conditioned graph of collaborative groups*, using a conditioned information bottleneck to denoise the task representation and a group/edge prediction head (with a β‑warm‑up KL objective) to assemble the topology; the resulting executed multi‑agent pipeline answers the task more token‑efficiently than baselines.
