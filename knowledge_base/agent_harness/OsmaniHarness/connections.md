# Connections

- [[TheHarnessEffect/summary|The Harness Effect: How Orchestration Design Sets the Token Economics of Enterprise Agentic AI]] — Direct quantitative backing for this article's central, otherwise-anecdotal claim: where Osmani asserts "harness beats model choice" via qualitative examples (Terminal Bench score gaps, a Top 30 to Top 5 jump), this paper measures the same thesis with a controlled swap across 22 locked tasks and 6 fixed models, cutting cost 41%, latency 44%, and tokens 38% by changing only the orchestration layer.
- [[CodeAsAgentHarness/summary|Code as Agent Harness]] — Same-substrate complement: this article's ratchet (turn a real failure into a permanent AGENTS.md rule, hook, or reviewer check) and its hooks-as-enforcement-layer argument both rest on code being executable, inspectable, and verifiable; Code as Agent Harness formalizes that same substrate into a three-layer taxonomy (interface, mechanisms, multi-agent scaling) that Osmani's piece only sketches through worked examples.
- [[VerificationHorizon/summary|The Verification Horizon: No Silver Bullet for Coding Agent Rewards]] — Sharpens this article's throwaway line that "self-grading skews positive" (its justification for generator/evaluator splits and plan-file self-verification): this paper treats verification itself as the binding constraint on agent progress and shows every verifier family (tests, rubrics, user feedback, LLM judges) gets gamed differently as the generator improves, meaning Osmani's evaluator split is necessary but not sufficient without a verifier that co-evolves with the agent.
