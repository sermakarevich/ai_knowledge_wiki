# Claude Squad for Fleet: Targeted Analysis
**In one sentence:** Fleet should learn from Claude Squad that parallel agent workers need almost no abstraction — one tmux session plus one git worktree per worker, a JSON state file reconciled against live tmux on restart, and single-key operator commands gets you nearly everything.
## Key points
- Single Go binary entered via cobra `rootCmd`; refuses to start outside a git repo (`git.IsGitRepo` guard), resolves the agent program string, then runs a Bubble Tea TUI. `main.go:27-50`, `main.go:52-76`
- Each worker maps 1:1 to a tmux session named `claudesquad_` + sanitized title, spawned as `tmux new-session -d -s <name> -c <workdir> <program>`. `session/tmux/tmux.go:60-71`, `session/tmux/tmux.go:93-102`
- Restart recovery is reconciliation, not replay: persisted JSON rows reload, live tmux sessions re-attach via `Restore()`, dead ones park as `Paused` for later resume. `session/storage.go:76-94`, `session/instance.go:248-263`
- Conflict avoidance is structural: one worktree plus one branch per instance under `<configDir>/worktrees/`, created from pinned `HEAD`; push goes through `gh` with a `git push` fallback behind a confirmation modal. `session/git/worktree.go:49-78`, `session/git/worktree_git.go:71-126`, `app/app.go:716-738`
- There is no workflow abstraction: no DAG (Directed Acyclic Graph), no phases, no state machine beyond `Running/Ready/Loading/Paused`; all ops are single keypresses capped at 10 instances. `session/instance.go:18-29`, `keys/keys.go:38-58`, `app/app.go:24`
- Multi-harness support is one string field (`default_program` + optional `profiles`), passed verbatim as the tmux pane command; only three harness constants exist, used solely for prompt/trust string matching. `config/config.go:36-59`, `session/tmux/tmux.go:22-25`, `session/tmux/tmux.go:253-260`
- `reset` is the total-cleanup escape hatch: wipes JSON storage, kills all `claudesquad_*` tmux sessions, removes all worktrees, stops the daemon — but never touches `config.json`. `main.go:80-115`

## Design principles (terminal-first, near-zero setup)
Prerequisites are two external binaries, not libraries: `tmux` for session isolation and `gh` (GitHub CLI) for push. `tmux` is required on `PATH` — every primitive shells out via `exec.Command("tmux", ...)` with no `LookPath` guard (`session/tmux/tmux.go:102`, `session/tmux/tmux.go:478`), and `install.sh` installs it via brew/apt/dnf/yum/pacman (`install.sh:179-214`); `gh` is gated by `checkGHCLI`, which requires both the binary and `gh auth status` (`session/git/util.go:36-45`). The binary must run inside a git repository: `rootCmd` resolves `filepath.Abs(".")` and returns an error naming the invoked binary if `git.IsGitRepo` fails (`main.go:42-50`, `main.go:167-175`). Distribution is a single binary with four cobra commands (`reset`, `debug`, `version` plus root), registered in one `init()` (`main.go:148-165`); `--daemon` is a hidden internal flag routing to `daemon.RunDaemon` instead of the TUI (`main.go:35-40`, `main.go:153-160`). All persistent configuration lives in `~/.claude-squad/`: `config.json` (`ConfigFileName`, `GetConfigDir` at `config/config.go:15-27`), `state.json` for runtime rows (`config/state.go:12`), `worktrees/` for isolation directories (`session/git/worktree.go:11-17`), and `daemon.pid` for daemon coordination (`daemon/daemon.go:115-123`). Missing or corrupt config degrades to defaults plus a log line rather than crashing (`config/config.go:155-185` per wiki 06; defaults: `DaemonPollInterval` 1000, `AutoYes` false, `BranchPrefix` `<username>/` at `config/config.go:84-105`).
## Worker restart handling (tmux sessions, gh CLI)
What survives a TUI restart: everything durable. `Storage.SaveInstances` serializes only `Started()` instances to JSON and delegates to `config.State`, which stores the raw blob in `state.json` (`session/storage.go:57-73`, `config/state.go:112-122`). On startup `newHome` calls `storage.LoadInstances()`, which rebuilds every row via `FromInstanceData` (`app/app.go:106-136` per wiki 02 cross-checked against `app/app.go:106` and `session/storage.go:76-94` read above). Each non-paused row then calls `Start(false)`, which calls `tmuxSession.Restore()` — an existence pre-check plus `tmux attach-session` re-attach (`session/instance.go:248-263`, `session/tmux/tmux.go:187-202` per wiki 03 cross-checked against `session/tmux/tmux.go:192-195`). If the tmux server died (reboot, crash, `tmux kill-server`), `Restore` returns `ErrSessionNotFound` (defined at `session/tmux/tmux.go:62-64`) and the instance parks as `Paused` with worktree and branch intact instead of failing — deliberately, because `LoadInstances` aborts on the first error, so one dead session would otherwise hide all others (`session/instance.go:248-263`, `session/storage.go:85-91`). What does NOT survive: unstarted draft rows are never persisted (`session/storage.go:60-64`); live PTY (pseudo-terminal) attachments are re-created, not resumed; and a single corrupt JSON row is fatal to the whole load (`session/storage.go:80-88`). Reset/cleanup paths are total: `reset` deletes all stored instances, kills every `claudesquad_*` session found via `tmux ls` regex match, removes all worktrees and prunes, then stops the daemon (`main.go:87-111`, `session/tmux/tmux.go:498-526`, `session/git/worktree_ops.go:170-232`). Per-instance `Kill()` always attempts both tmux `Close()` and worktree `Cleanup()`, aggregating rather than short-circuiting errors, and is a no-op on never-started rows (`session/instance.go:288-302`). The daemon's role in restarts: the foreground TUI always stops any inherited daemon before starting (`main.go:71-74`); if autoyes is on, it defers `LaunchDaemon()` so a fresh detached daemon (same binary re-execed as `<self> --daemon`, PID in `daemon.pid`) takes over prompt-accepting after the TUI exits (`main.go:64-70`, `daemon/daemon.go:91-127`); the daemon itself persists instances on `SIGINT`/`SIGTERM` before exiting (`daemon/daemon.go:74-88`).
## Conflict resolution (workspace isolation)
There is no lock, merge queue, or conflict resolver because there is no shared mutable state. Each instance gets a dedicated worktree under `<configDir>/worktrees/<sanitized-branch>_<hex-nanotime>` (`session/git/worktree.go:49-70`, path join plus timestamp suffix at `session/git/worktree.go:66-68`) on its own branch (`BranchPrefix` + session name, sanitized to lowercase `[a-z0-9-_/.]` at `session/git/worktree.go:73-78`, `session/git/util.go:13-33`). Fresh sessions are created from the recorded `HEAD` commit hash, so agents never inherit each other's uncommitted changes; pre-existing-branch sessions set `isExistingBranch=true` so cleanup keeps the branch (`session/git/worktree_ops.go:83-113`, `session/git/worktree.go:95-108` per wiki 04 cross-checked against `session/git/worktree_ops.go:83-92`). The only shared namespace is branch names, partitioned per session. Review-before-push is the human gate: the Diff tab renders `git add -N .` plus `git --no-pager diff <baseCommitSHA>` with `+`/`-` line counts, and `DiffNumstat` sums `diff --numstat` while skipping binary rows (`session/git/diff.go:26-67`). Push itself (`p`, confirmation-gated at `app/app.go:716-738`) builds a timestamped `[claudesquad] update from '<title>'` commit, stages and commits with `--no-verify` only if `IsDirty`, then pushes via `gh repo sync --source -b <branch>` with fallback to `git push -u origin <branch>`, followed by `gh repo sync -b <branch>`; opening the branch URL is best-effort and never fails the push (`session/git/worktree_git.go:71-126`). Checkout (`c`) is Pause behind a help screen: commit locally, detach (not kill) tmux to preserve scrollback, remove and prune the worktree, copy the branch name to clipboard, mark `Paused` (`app/app.go:739-753`, `session/instance.go:423-476` per wiki 02 cross-checked against `session/instance.go:442-476`: `DetachSafely` plus paused commit message at `session/instance.go:466`).
## Workflow abstraction
Deliberately absent. The entire lifecycle vocabulary is four statuses — `Running`, `Ready`, `Loading`, `Paused`, where `Paused` means "worktree removed but branch preserved" (`session/instance.go:18-29`) — plus five operations (create, pause, resume, push, kill) wired directly to keypresses with no phase graph, no DAG, no dependency edges, no retry policy, no scheduler. Dispatch is a flat `switch` on `GlobalKeyStringsMap` (`keys/keys.go:38-58`, `app/app.go:604-612`): `n` new, `N` new-with-prompt, `D` kill, `p` push, `c` checkout/pause, `r` resume, `enter`/`o` attach, `tab` cycle tab, `q` quit (`keys/keys.go:47-57`, handlers at `app/app.go:612-791`). Creation is capped at `GlobalInstanceLimit = 10`, enforced at both creation sites (`app/app.go:24`, `app/app.go:612-644` per wiki 01/05 cross-checked against `app/app.go:24` and `app/app.go:612-644` via grep). What exists vs what Fleet has that this lacks: Claude Squad has durable instance rows, pause/resume, and attention polling (`HasUpdated` hash-compare at `session/tmux/tmux.go:244-267`); it lacks task decomposition, agent-to-agent messaging, phased pipelines, progress tracking beyond diff line counts, and any notion of a run that spans workers. Fleet should treat this as the execution floor — process isolation plus observability — and keep all orchestration above it.
## Multi-harness support
The no-adapter design: harness selection is a plain shell-command string. `Config` holds `default_program`, `auto_yes`, `daemon_poll_interval`, `branch_prefix`, and optional `profiles` (`{name, program}` pairs) with no per-harness section (`config/config.go:29-47`). `GetProgram()` resolves `default_program` through profiles when the name matches, otherwise passes it through verbatim (`config/config.go:49-59`); `GetProfiles()` returns defined profiles default-first, or synthesizes one from `DefaultProgram` (`config/config.go:61-82`). CLI flags override file config at startup (`-p/--program`, `-y/--autoyes` at `main.go:52-63`, `main.go:148-154`). The string travels untouched `app.Run → home.program → NewInstance(InstanceOptions{Program}) → tmux.NewTmuxSession(title, program)` (`app/app.go:27-56`, `session/instance.go:149-163` per wiki 06 cross-checked against `app/app.go:27-56` read and `session/instance.go:155`, `session/instance.go:214`), becoming the trailing command argument of `tmux new-session` (`session/tmux/tmux.go:93-102`). The picker is a cursor-over-list overlay embedded in the session-creation input (`ui/overlay/profilePicker.go:13-24`, `ui/overlay/profilePicker.go:44-70`, wired via `NewTextInputOverlayWithBranchPicker` at `ui/overlay/textInput.go:61-67`). Harnesses named anywhere: `claude`, `codex`, `gemini`, `aider`, `amp` — in the binary's short description (`main.go:29`: "Claude Code, Aider, Codex, and Amp") and README (`README.md:3`: Codex, Gemini, Aider; `README.md:82-86`: `cs -p "codex"|"aider ..."|"gemini"`; `README.md:128-129`: codex/aider profile example). But only three are named in code — `ProgramClaude`, `ProgramAider`, `ProgramGemini` (`session/tmux/tmux.go:22-25`) — and solely for substring prompt/trust detection: auto-yes matching in `HasUpdated` (`session/tmux/tmux.go:253-260`) and the trust-prompt gate in `CheckAndHandleTrustPrompt` (`session/instance.go:346-355`). Any other CLI (codex, amp, custom wrappers) launches fine but gets generic trust handling and no prompt detection. Trade-off: adding a harness is a one-line JSON edit with arbitrary flags (`session/instance.go:155`); cost is no existence validation before spawn (failure surfaces as a tmux timeout at `session/tmux/tmux.go:117-133` per wiki 03 cross-checked against `session/tmux/tmux.go:125`), no capability model, and substring-fragile prompt matching.
## What Fleet can borrow (5-8 concrete ideas)
1. **Worktree-per-worker isolation.** One branch plus one disposable worktree per worker under a controlled directory, created from pinned `HEAD`, eliminates shared-checkout conflicts without any locking protocol; Fleet maps this directly to one worktree per coder worker. `session/git/worktree.go:49-78`
2. **tmux capture-pane observability.** Polling worker state via `tmux capture-pane -p -e -J` (plus `-S/-E` scrollback windows) plus SHA-256 (Secure Hash Algorithm) change hashing gives Fleet passive, agent-agnostic progress monitoring with zero worker cooperation. `session/tmux/tmux.go:475-496`
3. **State-file/tmux reconciliation on restart.** Persisting only started rows as JSON and re-attaching live sessions on boot — parking dead ones as resumable instead of erroring — means orchestrator restarts never lose worker identity or branch state; Fleet's bead DB (database) plus worker registry should follow the same load-and-reconcile pattern. `session/instance.go:248-263`
4. **reset/cleanup-all command.** A single operator command that wipes state rows, kills all prefixed tmux sessions, removes all worktrees/prunes metadata, and stops background daemons bounds the blast radius of stuck workers; Fleet needs the namespaced equivalent (`claudesquad_*` regex scoping at `session/tmux/tmux.go:513-524`). `main.go:80-115`
5. **Diff-before-push review gate.** Computing the diff against a pinned base commit (with intent-to-add for untracked files) and requiring confirmation before any remote write gives reviewers a cheap, uniform checkpoint; Fleet can reuse the `add -N` plus base-SHA (Secure Hash Algorithm) pattern per worker branch. `session/git/diff.go:26-52`
6. **Profile picker for harness switching.** Named `{name, program}` profiles with default-first ordering, selected in the creation overlay, make multi-model routing a config edit instead of a code change; Fleet's model/harness selector can copy the shape while adding capability metadata Claude Squad lacks. `config/config.go:61-82`
7. **Autoyes daemon pattern.** A detached same-binary process that polls persisted workers on `DaemonPollInterval` and injects Enter only when prompt substrings match — coordinated via PID (process ID) file, stopped whenever the foreground TUI runs — is the minimal safe form of auto-approval; Fleet can adopt the poll-and-inject loop with stricter prompt classification. `daemon/daemon.go:44-60`
8. **Single-key operator keymap.** A two-level map from raw key strings to named actions with one flat dispatch switch makes every worker operation exactly one keypress and keeps the full operator surface auditable in under 25 lines; Fleet's operator console benefits from the same density. `keys/keys.go:38-58`
