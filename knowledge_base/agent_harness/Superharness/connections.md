# Connections

- [[research/GasTown/summary|GasTown]] — Same-problem-different-method: Go orchestrator spawning external coder CLIs with worktree isolation and daemon supervision, but with a Dolt-backed beads ledger, tmux sessions, and refinery merge queue where Superharness uses SQLite state.db, inbox watcher, and status gates; both never call an LLM themselves.
- [[research/AgentOrchestrator/summary|Agent Orchestrator (AO) — Run Coding Agents in Parallel]] — Same-problem-different-method: local-first Go daemon owning durable SQLite state with one worktree + branch + PR per session and 27 compiled-in harnesses, versus Superharness's per-project SQLite DB with 5 harness adapters; AO derives status at read time while Superharness stores a 17-state status machine.
- [[research/ClaudeOrchestrator/summary|claude-orchestrator + orchestration-playbook]] — Same-problem-different-method: worktree-per-agent dispatch with merge gates and bounded dispatch contracts, but as portable prose discipline (SKILL.md) rather than Superharness's runtime enforcement via DAOs, watchers, and lifecycle watchdogs.
- [[fleet/worker|Fleet worker: lifecycle contract and design decisions]] — Shares-technique / applies-in-practice: fleet's Python supervisor spawns the same coder CLIs with state outside the process (beads ledger + task dir), heartbeats, leases, bounded retries, and HANDOFF resume — the same supervision problems Superharness solves with heartbeats, zombie reaping, and append-only handoffs.
- [[structured_papers/multi_agent_systems/ClaudeCodeAgentFarm/summary|Claude Code Agent Farm]] — Shares-technique: N parallel Claude Code sessions in tmux panes with health monitoring and auto-restart of stalled workers, the same supervision layer as Superharness's inbox_watch reconcilers but without a typed contract or persistent queue.
