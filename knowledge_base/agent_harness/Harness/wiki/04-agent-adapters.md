# Multi-Agent Adapters and Registry
**In one sentence:** Harness puts the Claude Code CLI (`claude.rs`), Codex CLI (`codex.rs`), OpenCode CLI (`opencode.rs`), and the direct Anthropic HTTP API (`anthropic_api.rs`) behind the single `AgentBackend` (alias `CodeAgent`/`AgentAdapter`) trait, with `registry.rs`/`builder.rs` resolving a name such as `claude|codex|opencode|anthropic-api` to a backend and `spawn_contract.rs`+`spawn_supervisor.rs` executing every CLI backend as a supervised, sandboxed child process whose JSONL output is parsed by per-agent streaming parsers.
## Key points
- The common interface is `AgentBackend: Send + Sync` (`crates/harness-core/src/agent.rs:84`), aliased as `CodeAgent` (`crates/harness-core/src/agent.rs:180`) and `AgentAdapter` (`crates/harness-core/src/agent.rs:173`); one-shot CLI backends implement `execute`/`execute_stream`, stateful protocol backends (`codex_adapter.rs`, `opencode_adapter.rs`) override `start_turn`/`interrupt`/`steer`/`respond_approval`, and all unimplemented control operations default to `Unsupported` (`crates/harness-core/src/agent.rs:109-165`).
- `AgentRegistry` (`crates/harness-agents/src/registry.rs:19`) stores `AgentDescriptor { backend, control_backend, turn_backend_factory }` per name (`crates/harness-agents/src/registry.rs:13-17`); lookup is `get(name)` (`crates/harness-agents/src/registry.rs:109`), control side-channel is `get_adapter(name)` (`crates/harness-agents/src/registry.rs:114`), fresh stateful turn backends come from `turn_execution_adapter(name)` (`crates/harness-agents/src/registry.rs:121`), and complexity-based routing is `dispatch(task)` (`crates/harness-agents/src/registry.rs:148-163`).
- `registry_from_config` (`crates/harness-agents/src/builder.rs:135`) is the single assembly point: it registers `claude` (`crates/harness-agents/src/builder.rs:142`), `codex` plus a `CodexAdapter` turn factory (`crates/harness-agents/src/builder.rs:151-163`), `opencode` plus an `OpenCodeAcpAdapter` turn factory (`crates/harness-agents/src/builder.rs:165-180`), and `anthropic-api` only when `ANTHROPIC_API_KEY` is present (`crates/harness-agents/src/builder.rs:182-190`); the configured `default_agent` string (the `--agent` selection) resolves via `resolved_default_agent_name`/`default_agent` (`crates/harness-agents/src/registry.rs:129-146`).
- Per-adapter executors are `ClaudeCodeAgent` (`crates/harness-agents/src/claude.rs:28`), `CodexAgent` (`crates/harness-agents/src/codex.rs:52`), `AnthropicApiAgent` (`crates/harness-agents/src/anthropic_api.rs:9`), and `OpenCodeAgent` plus `parse_opencode_run_line` (`crates/harness-agents/src/opencode.rs:48`); Claude carries a provider-backpressure gate, stream timeout, reasoning budget, and optional API key (`crates/harness-agents/src/claude.rs:28-40`), Codex carries CLI path, model, reasoning effort, cloud config, and stream timeout (`crates/harness-agents/src/codex.rs:52-61`).
- The spawn contract (`crates/harness-agents/src/spawn_contract.rs:200`) has two implementations, `HostSpawn` (`crates/harness-agents/src/spawn_contract.rs:208`) and `ContainerSpawn` (`crates/harness-agents/src/spawn_contract.rs:257`), selected by isolation tier in `prepare_agent_spawn` (`crates/harness-agents/src/spawn_contract.rs:436`); egress policy derives from `AgentEgressMode::resolve(permission_mode, allowlist)` (`crates/harness-agents/src/spawn_contract.rs:217`), and container spawns become `docker run --rm` with bind mounts, `--env` propagation, and proxy/canary wiring (`crates/harness-agents/src/spawn_contract.rs:294-432`).
- `spawn_agent` (`crates/harness-agents/src/spawn_supervisor.rs:45`) builds the `tokio::process::Command`, applies `apply_process_env`, validates the capability token, retries once on `ETXTBSY` (`crates/harness-agents/src/spawn_supervisor.rs:140-155`), writes a provisional run binding, and wraps the child in `ManagedChild` (`crates/harness-agents/src/lib.rs:137`), which owns process-group kill, bounded tail capture with idle-timeout zombie detection (`crates/harness-agents/src/lib.rs:242-345`), and synchronous drop-time reaping; stale Docker resources are reconciled at startup (`crates/harness-agents/src/docker_reconciliation.rs:8`).
- Streaming output is parsed per agent: Claude `--output-format stream-json` lines become `AgentEvent`s via `parse_stream_json_events` (`crates/harness-agents/src/claude_stream_json.rs:25`), Codex `exec --json` output becomes `ParsedCodexExecEvent` items via `parse_codex_item`/`parse_codex_exec_output` (`crates/harness-agents/src/codex_exec_parser.rs:77`), OpenCode `run --format json` lines become `OpenCodeRunEvent::{Text, ToolUse, StepFinish}` (`crates/harness-agents/src/opencode.rs:25-96`), stderr is classified into warn/debug with agent-internal prefix suppression (`crates/harness-agents/src/streaming.rs:240-328`), and non-streaming output is bounded tail capture with cross-chunk secret redaction (`crates/harness-agents/src/output_capture.rs:41-113`).
- Permission and prompt shaping sit above spawn: Claude maps `allowed_tools`/capability profile to `--allowedTools` scoping (`crates/harness-agents/src/claude.rs:199`), Codex maps `allowed_tools == Some([])` to deny-all and forwards `approval_policy` via `-c approval_policy=...` (`crates/harness-agents/src/codex.rs:160-196`), OpenCode merges restrictions through the inlined `OPENCODE_PERMISSION` JSON env (`crates/harness-agents/src/opencode.rs:18`), nested Claude session markers are stripped (`crates/harness-agents/src/spawn_contract.rs:45-51`), and cross-cutting guards include the provider backpressure semaphore gate (`crates/harness-agents/src/provider_backpressure.rs:50-60`), scoped GitHub tokens (`crates/harness-agents/src/scoped_token.rs:7-9`), and the Anthropic-backed compression model reusing `AnthropicApiAgent` (`crates/harness-agents/src/compress_model.rs:23-55`).

## The adapter interface
Every backend is an `AgentBackend`. The definition (`crates/harness-core/src/agent.rs:84`) declares identity (`name`, `id`, `capabilities`, `agent_contract_capabilities`, `reports_usage_cost`) plus `execute`, `execute_stream` (defaulting to `start_turn`), and the stateful control surface (`start_turn`, `interrupt`, `terminate_and_drain`, `steer`, `respond_approval`), each defaulting to `Unsupported` so one-shot CLIs implement only what they own:
```rust
pub trait AgentBackend: Send + Sync {
    fn name(&self) -> &str;
    fn id(&self) -> String {
        self.name().to_string()
    }
    fn capabilities(&self) -> Vec<Capability> {
        Vec::new()
    }
    fn agent_contract_capabilities(&self) -> AgentContractCapabilities {
        AgentContractCapabilities::default()
    }
    fn reports_usage_cost(&self) -> bool {
        false
    }
    async fn execute(&self, _req: AgentRequest) -> crate::error::Result<AgentResponse> {
        Err(crate::error::Error::Unsupported(
            "execute not supported".into(),
        ))
    }
```
`lib.rs` (`crates/harness-agents/src/lib.rs:1-20`) re-exports the adapter modules (`anthropic_api`, `builder`, `claude`, `claude_stream_json`, `codex`, `codex_adapter`, `compress_model`, `docker_reconciliation`, `opencode`, `opencode_adapter`, `output_parsing`, `provider_backpressure`, `registry`, `scoped_token`) alongside the shared `ManagedChild` process supervisor and `OutputLimits`/`BoundedOutput` capture types.
## Registry and selection
`AgentRegistry::new(default_agent)` (`crates/harness-agents/src/registry.rs:27`) seeds the configured default name; `register` preserves existing control/turn backends across hot-reload (`crates/harness-agents/src/registry.rs:44-62`); `register_adapter`/`register_turn_backend_factory` attach the live side channel and the per-turn factory, failing loudly with `AgentNotFound` on unknown names (`crates/harness-agents/src/registry.rs:68-107`). `resolved_default_agent_name` honors the configured name unless it is empty, `auto`, or unregistered, in which case it falls back to the first registered backend (`crates/harness-agents/src/registry.rs:129-141`); `dispatch` routes `Critical`/`Complex` tasks to `complexity_preferred_agents` and everything else to the default (`crates/harness-agents/src/registry.rs:148-163`). The canonical assembly:
```rust
let mut registry = AgentRegistry::new(&config.default_agent);
registry.set_complexity_preferences(config.complexity_preferred_agents.clone());
registry.register(
    "claude",
    Arc::new(claude_agent_from_config_with_gate(
        config,
        sandbox_mode,
        ProviderBackpressureGate::from_claude_config(&config.claude.provider_backpressure),
    )),
);
registry.register(
    "codex",
    Arc::new(codex_agent_from_config(config, sandbox_mode)),
);
```
(`crates/harness-agents/src/builder.rs:139-154`); codex/opencode additionally get turn factories, and `anthropic-api` is conditional on the API key (`crates/harness-agents/src/builder.rs:155-190`). `ConfiguredAgent` seals per-entry-point knobs (stream timeout, reasoning budget, provider gate, sandbox mode) so callers can execute but not reconfigure (`crates/harness-agents/src/builder.rs:29-72`).
## Spawn lifecycle
Each CLI adapter builds its argv, derives the effective sandbox mode and `SandboxSpec`, resolves the run identity, and calls `prepare_agent_spawn` (`crates/harness-agents/src/claude.rs:103-120`, `crates/harness-agents/src/codex.rs:109-120`, `crates/harness-agents/src/spawn_contract.rs:436-477`). Host tiers wrap the command via `wrap_command` with a `NetworkPolicy` derived from the egress mode (`crates/harness-agents/src/spawn_contract.rs:210-255`); container tiers canonicalize the workspace, enforce bind-source containment, and emit `docker run` with workspace/temp/output-schema mounts, plain-vs-secret env separation, and proxy env plus container canary when first-party egress applies (`crates/harness-agents/src/spawn_contract.rs:259-434`). `spawn_agent` then spawns under a process group with `kill_on_drop`, maps spawn errors per agent, records the provisional binding, and returns a `SupervisedAgentProcess` holding the `ManagedChild` (`crates/harness-agents/src/spawn_supervisor.rs:45-109`); the fingerprint in `adapter_spawn_policy_fingerprint` hashes sandbox mode, permission mode, env, and capability paths (`crates/harness-agents/src/spawn_contract.rs:60-105`), and `spawn_contract/` holds the `docker_ownership`, `egress`, `output_schema`, `review_git`, and `spawn_env` helpers.
## Streaming and output parsing
Claude streams `--output-format stream-json` JSONL (`assistant`/`tool_use`/`tool_result`/`result`/`error` mapped to `AgentEvent`, unknown types ignored for forward compatibility) with explicit failure detection on `result` events that carry exit code 0 (`crates/harness-agents/src/claude_stream_json.rs:12-80`); Codex parses `exec --json` items (`agent_message`, tool calls, usage, structured provider/permanent errors) into `ParsedCodexExecEvent` with an `UnknownItemKind` fail-closed variant (`crates/harness-agents/src/codex_exec_parser.rs:10-62`); OpenCode parses `text`/`tool_use`/`step_finish` lines including token/cost observation (`crates/harness-agents/src/opencode.rs:41-120`). Shared streaming (`crates/harness-agents/src/streaming.rs:277-355`) drains stderr with keyword plus agent-internal-prefix classification, captures a bounded stderr tail, and enriches exit errors; sentence-level sentinels (`PR_URL=`, `CREATED_ISSUE=`, `TRIAGE=`, `LGTM`, `ISSUES=`) are extracted downstream (`crates/harness-agents/src/output_parsing.rs:101-315`).
