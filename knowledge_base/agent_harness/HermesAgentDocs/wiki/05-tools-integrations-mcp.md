# Tools, Integrations, and MCP
**In one sentence:** Hermes Agent ships 60+ built-in tools grouped into enable/disable toolsets with 7 terminal backends, connects external capabilities through MCP servers and the Nous Portal subscription with its managed Tool Gateway, and covers voice, browser, vision, image generation, TTS, and web search providers.
## Key points
- Hermes organizes 60+ built-in tools into toolsets such as `web`, `terminal`, `file`, `browser`, `vision`, `image_gen`, `tts`, `memory`, `cronjob`, `code_execution`, and `delegation`, selectable per run with `hermes chat --toolsets "web,terminal"` and configured with `hermes tools`.
- The terminal tool supports 7 backends -- `local`, `docker`, `ssh`, `singularity`, `modal`, `daytona`, and `vercel_sandbox` -- with container defaults of 1 CPU, 5120 MB memory, 51200 MB disk, and persistent filesystems when `container_persistent: true`.
- Nous Portal at portal.nousresearch.com provides one OAuth login and one bill for 300+ models including Claude Sonnet 4.6, GPT-5.5 Pro, Gemini 3 Pro Preview, and DeepSeek V4 Pro, set up with `hermes setup --portal`.
- The Nous Tool Gateway routes 5 categories through managed infrastructure -- Firecrawl web search and extract, FAL image generation with 9 models, OpenAI TTS, Browser Use cloud browsers, and Modal cloud terminals -- enabled per tool with the value `nous` in config.
- MCP servers are declared under `mcp_servers` in `~/.hermes/config.yaml` as stdio servers with `command` plus `args` plus `env` or as HTTP servers with `url` plus `headers` plus `auth: oauth`, registered with the prefix `mcp_<server>_<tool>` and a runtime toolset named `mcp-<server>`.
- MCP exposure is controlled with `enabled: false`, `tools.include` whitelists, `tools.exclude` blacklists with fnmatch globs, and `tools.prompts: false` plus `tools.resources: false`, where `include` wins when both lists match.
- Voice mode works in CLI plus Telegram plus Discord, started with `/voice on` and toggled with Ctrl+B, using OpenAI TTS through the gateway or a direct TTS provider key.
- Web search defaults to Firecrawl through the gateway or a direct Firecrawl key, with self-hosted SearXNG supported as an alternative backend selected in `hermes tools` via `web.backend`.

## Toolsets and terminal backends
Hermes groups built-in tools into logical toolsets that can be enabled or disabled per platform. Common toolsets include `web`, `search`, `terminal`, `file`, `browser`, `vision`, `image_gen`, `skills`, `tts`, `todo`, `memory`, `session_search`, `cronjob`, `code_execution`, `delegation`, `clarify`, `homeassistant`, `messaging`, `spotify`, `discord`, `discord_admin`, `debugging`, and `safe`. Platform presets include `hermes-cli` and `hermes-telegram`, while each configured MCP server adds a dynamic runtime toolset named `mcp-<server>`.
Useful commands:
- `hermes chat --toolsets "web,terminal"` -- run with only specific toolsets
- `hermes tools` -- interactive per-platform tool configuration
- `hermes status` -- full system status including Tool Gateway routing
Tool result behavior worth knowing: terminal signal deaths are explained in plain language instead of bare codes, and `read_file` transcodes UTF-16 text to UTF-8 instead of refusing it, while files over 10 MB and genuinely binary files are still refused.
Terminal execution is selected in `~/.hermes/config.yaml` under `terminal.backend`, with `cwd` for working directory and `timeout` defaulting to 180 seconds. Agent shell calls run non-interactively with no TTY, so slow or interactive shell startup files can hang every command. The docs recommend an early return guard in `.bashrc` for non-interactive shells, keeping `.zshenv` minimal, and exporting needed PATH changes above the guard.
Backend notes:
- `local` -- default, runs on the agent machine for development and trusted tasks.
- `docker` -- one persistent long-lived container per Hermes process started with sleep infinity, with every terminal, file, and `execute_code` call routed through docker exec into the same container. Working directory changes, installed packages, and files under `/workspace` persist across `/new`, `/reset`, and `delegate_task` subagents until shutdown. Set image with `terminal.docker_image`, for example `python:3.11-slim`.
- `ssh` -- recommended for sandboxing the agent away from its own code, configured with `TERMINAL_SSH_HOST`, `TERMINAL_SSH_USER`, and `TERMINAL_SSH_KEY` in `~/.hermes/.env`.
- `singularity` -- HPC rootless containers, configured with a prebuilt SIF image such as `~/python.sif` built from `docker://python:3.11-slim`.
- `modal` -- serverless cloud execution, enabled after Modal install plus `modal setup` plus setting `terminal.backend` to `modal`. Daytona and Modal serverless workers hibernate when idle and resume on use.
- `daytona` -- persistent remote cloud sandbox workspace for development environments.
- `vercel_sandbox` -- Vercel Sandbox cloud microVM with snapshot-backed persistence, runtimes `node24`, `node22`, and `python3.13`, authenticated with `VERCEL_TOKEN`, `VERCEL_PROJECT_ID`, and `VERCEL_TEAM_ID`.
Container resources apply to `docker`, `singularity`, `modal`, `daytona`, and `vercel_sandbox`: `container_cpu`, `container_memory`, `container_disk`, and `container_persistent`. Documented defaults are 1 CPU core, 5120 MB memory, 51200 MB disk, and persistence enabled. Container security includes read-only root filesystem on Docker, dropped Linux capabilities, no privilege escalation, PID limit of 256 processes, and namespace isolation with persistent workspaces via volumes.
Background processes use `terminal` with `background=true`, which returns a `session_id`, then the `process` tool with actions `list`, `poll`, `wait`, `log`, `kill`, and `write`. PTY mode with `pty=true` supports interactive CLIs such as Codex and Claude Code. Hermes retains the newest 64 completed results for up to 7 days under `logs/process-results` in the profile home, each capped at the rolling 200000-character output tail with secret redaction always applied. Sudo on interactive sessions uses a masked password prompt cached for the session, with `SUDO_PASSWORD` in the profile `.env` as the non-interactive alternative. No egress credential-injection proxy for Docker was described in the fetched tools documentation.
## Tool Gateway and Nous Portal
Nous Portal is the recommended setup path and one subscription for models plus managed tools. Fresh installs use `hermes setup --portal`, which runs Portal OAuth, stores the refresh token at `~/.hermes/auth.json`, lets the user pick a model, sets Nous as inference provider, and turns on the Tool Gateway. Existing installs add it with `hermes model` by picking Nous Portal, keeping other providers available for mid-session switching with `/model`. Day-to-day commands are `hermes portal info` or `hermes portal status`, `hermes portal tools`, and `hermes portal open` for subscription management. Portal tokens are shared across Hermes profiles, and runtime token handling mints short-lived JWTs from the stored refresh token with automatic refresh plus a keepalive bounded by `nous.keepalive_interval_seconds` default 900.
The subscription covers 300+ frontier models billed against Nous, including Anthropic Claude Opus 4.7, Opus 4.6, Sonnet 4.6, and Haiku 4.5, OpenAI GPT-5.5, GPT-5.5 Pro, GPT-5.4 Mini, GPT-5.4 Nano, and GPT-5.3 Codex, Google Gemini 3 Pro Preview, Gemini 3 Flash Preview, Gemini 3.1 Pro Preview, and Gemini 3.1 Flash Lite Preview, DeepSeek V4 Pro, Qwen3.7-Max, Kimi K2.6, GLM-5.1, MiniMax M2.7, Grok 4.3, Nemotron-3 Super 120B-A12B, Hunyuan 3 Preview, MiMo V2.5 Pro, Step 3.5 Flash, and Hermes-4-70B plus Hermes-4-405B. Hermes 4 models are chat and reasoning models offered at discounted rates but are explicitly not recommended inside Hermes Agent because they are not tuned for rapid tool-calling loops. After setup, config uses `model.provider: nous` with `base_url: https://inference-api.nousresearch.com/v1`.
The Tool Gateway is included with paid Portal subscriptions and routes tool calls through Nous-managed infrastructure so users avoid separate Firecrawl, FAL, OpenAI, Browser Use, and Modal accounts. The five gateway backends are Firecrawl web search and extract, FAL image generation, OpenAI TTS, Browser Use headless Chromium browser automation, and Modal cloud terminal sandbox as an optional add-on. Gateway selection is per tool, not all-or-nothing: `hermes tools` offers a Nous Subscription row per category, and picking it before login runs Portal OAuth inline without changing the inference provider. Each category has one selection key: `web.backend: nous`, `image_gen.provider: nous`, `tts.provider: nous`, `stt.provider: nous`, and `browser.cloud_provider: nous`. While a category is set to `nous`, direct keys in `.env` are ignored, and a direct-provider selection without its key produces an explicit error instead of silent fallback. The older `use_gateway: true` flag is legacy and read as equivalent to `nous` but is no longer written.
## MCP setup patterns and tool filtering
MCP lets Hermes use tools that live outside Hermes, such as GitHub, databases, filesystems, browser stacks, and internal APIs, without writing a native tool first. MCP support ships with the standard install. Minimal stdio and HTTP patterns in `~/.hermes/config.yaml` under `mcp_servers` are a local command with `command` plus `args` plus optional `env`, and a remote endpoint with `url` plus optional `headers`. OAuth-hosted servers use `auth: oauth`, with automatic discovery, PKCE, token exchange, refresh, and tokens cached at `~/.hermes/mcp-tokens/<server>.json` with 0o600 permissions. First connection prints an authorize URL and waits for a loopback callback, with paste-back, SSH port forwarding, proxied `redirect_uri`, and Desktop relay options for remote hosts. Client certificates use `client_cert` plus optional `client_key`, and per-user identity headers use `identity_header` with `static` or `profile` value sources. Timeouts use `timeout`, `connect_timeout`, `idle_timeout_seconds`, and `max_lifetime_seconds`, with recycling useful for memory-heavy servers such as Playwright Chromium.
The curated catalog holds Nous-reviewed servers under `optional-mcps` in the hermes-agent repo, disabled by default. Commands are `hermes mcp` for the interactive picker, `hermes mcp catalog` for a scriptable list, `hermes mcp install <name>` to install, `hermes mcp configure <name>` to change tool selection, `hermes mcp login <server>` for OAuth, and `hermes mcp add <name> --preset <preset>` for presets such as `codex`. Install may prompt for API keys written to `~/.hermes/.env`, run bootstrap commands, and probe the server to present a tool checklist backed by manifest `tools.default_enabled` or `tools.default_excluded`. GitHub is deliberately not in the catalog because its hosted MCP needs per-client OAuth apps, while bundled GitHub skills driving the `gh` CLI are the recommended integration.
Hermes registers MCP tools with the prefix `mcp_<server>_<tool>`, for example `mcp_filesystem_read_file` and `mcp_github_create_issue`, and registers capability-aware utility wrappers `list_resources`, `read_resource`, `list_prompts`, and `get_prompt` only when the server supports them and config allows them. Tool-result handling strips invisible Unicode TAG characters in range U+E0000 to U+E007F while preserving legitimate emoji tag sequences, and passes through vendor `_meta` while dropping protocol-reserved prefixes. Filtering patterns:
- `enabled: false` -- skip the server completely without connecting
- `tools.include` -- whitelist exact names or fnmatch globs such as `*_dns_*`
- `tools.exclude` -- blacklist exact names or globs, practical for large surfaces such as Cloudflare with about 3300 endpoint tools
- `include` wins when both lists match the same tool
- `tools.resources: false` disables resource wrappers and `tools.prompts: false` disables prompt wrappers
If every tool and utility is filtered out, Hermes creates no runtime toolset for that server. Discovery happens at startup, servers can push `notifications/tools/list_changed` for dynamic refresh, and config changes reload with `/reload-mcp`. Parallel execution is opt-in per server with `supports_parallel_tool_calls: true` for safe concurrent tools. Sampling with `sampling.createMessage` and elicitation with `elicitation/create` are both enabled by default, with per-server rate limits, timeouts, and disable flags. Hermes can also act as an MCP server itself with `hermes mcp serve`, exposing 10 messaging bridge tools such as `conversations_list`, `messages_read`, `messages_send`, `events_poll`, and `events_wait`.
## Voice mode
Voice mode enables spoken conversations in CLI, Telegram, and Discord sessions. Users start it with `/voice on` and toggle push-to-talk input with Ctrl+B in supported CLI clients. Speech output uses the `text_to_speech` tool through either the Nous Tool Gateway OpenAI TTS backend or a direct TTS provider key selected in `hermes tools`. The gateway path needs no separate OpenAI key, while the bring-your-own-key path keeps existing voices such as ElevenLabs without routing through Nous.
## Browser, vision, image generation, and TTS
Browser automation uses `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, and `browser_vision`, with text plus vision support for agent-driven pages. Cloud browser sessions run through Browser Use when `browser.cloud_provider` is set to `nous`, avoiding a separate Browser Use or Browserbase account, while direct browser backends remain selectable per tool. Vision analysis uses `vision_analyze` for image and page understanding alongside browser vision primitives.
Image generation uses `image_generate` through FAL.ai, either direct with a FAL key or managed through the gateway with `image_gen.provider: nous`. The gateway exposes 9 models under one endpoint with per-call override: `fal-ai/flux-2/klein/9b` as the fast default, `fal-ai/flux-2-pro`, `fal-ai/z-image/turbo`, `fal-ai/nano-banana-pro` for Gemini 3 Pro Image, `fal-ai/gpt-image-1.5`, `fal-ai/gpt-image-2`, `fal-ai/ideogram/v3` for prompt adherence and typography, `fal-ai/recraft/v4/pro/text-to-image` for vector and graphic design styles, and `fal-ai/qwen-image`. TTS uses `text_to_speech` through OpenAI TTS voices via the gateway or a direct key, and speech-to-text selection uses `stt.provider`.
## Web search providers
Web capabilities center on `web_search` plus `web_extract`, with X post search through `x_search` gated on xAI credentials and off by default. The default managed path is Firecrawl web search and full-page extraction through the Tool Gateway with `web.backend: nous`, which removes Firecrawl signup and rate-limit management. Direct alternatives are configured per tool in `hermes tools`: Firecrawl with a direct API key, or self-hosted SearXNG for users who want their own search infrastructure. Tools explicitly pointed at another backend such as `web.backend: searxng` are never overwritten by Portal enablement prompts, while tools configured only through environment variables are offered unchecked so existing backends are preserved.
