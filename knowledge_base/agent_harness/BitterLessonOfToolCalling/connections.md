# Connections

- [[papers/CodeAsAgentHarness/summary|Code as Agent Harness]] — cited directly in this paper's Related Work (Ning et al., 2026) as the survey-level theoretical case that code is the ideal substrate for agentic reasoning because it is executable, inspectable, and stateful; this paper is the empirical, benchmarked follow-through on that theoretical claim, specifically for function/tool calling.
- [[papers/IsGrepAllYouNeed/summary|Is Grep All You Need? How Agent Harnesses Reshape Agentic Search]] — same lead author (Sen) and the same underlying question — does the interface/harness wrapping a capability matter more than the capability choice itself? — applied to a different axis (search paradigm vs. tool-calling paradigm); both papers conclude the harness/interface design dominates the headline capability comparison.
- [[papers/ModelOrHarnessFailureTaxonomy/summary|Model or Harness? An Interaction-Centric Taxonomy for Localizing Agent Failures]] — shares the same-problem-different-method relationship: this paper's central finding (PTC viability tracks model generation/capability, not the paradigm/harness choice) is essentially a concrete instance of the "is this a model failure or a harness failure?" attribution question that taxonomy paper formalizes generically.

_Also worth noting: this paper cites "Recursive Agent Harnesses (Lumer et al., 2026)" and "Chronos (Sen et al., 2026b)" as related production/harness work, but neither has a corresponding entry in this KB as of 2026-08-26 — candidates to ingest if agent-harness tool-calling design becomes a recurring research focus._
