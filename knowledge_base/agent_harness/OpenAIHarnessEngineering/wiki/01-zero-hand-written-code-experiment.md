# The Zero-Hand-Written-Code Experiment

**In one sentence:** Over five months a tiny OpenAI team shipped a real internal-beta product with zero manually-written lines of code, reaching roughly one million lines and 1,500 merged pull requests at about one-tenth the estimated hand-written time.

## Key points

- The experiment ran about five months (first commit late August 2025, post February 11, 2026) building an internal beta with daily internal users and external alpha testers that ships, deploys, breaks, and gets fixed like a normal product.
- The hard constraint was zero manually-written code: application logic, tests, CI configuration, documentation, observability, and internal tooling were all written by Codex; humans never directly contributed code.
- Scale reached roughly one million lines of code and about 1,500 opened-and-merged pull requests, driven by a team that started at three engineers and grew to seven.
- Average throughput was about 3.5 merged PRs per engineer per day, and throughput increased as the team grew rather than collapsing under coordination cost.
- The team estimates roughly 1/10th the time hand-writing would have taken, with the explicit goal of forcing investment in whatever was needed to raise engineering velocity by orders of magnitude.
- The initial scaffold (repo structure, CI, formatting, package manager, app framework, even AGENTS.md itself) was generated by Codex CLI using GPT-5 from a small set of templates, with no human-written code anchoring the system.
- The stated lesson of the constraint: the scarce resource is human time and attention, so all engineering effort goes into environments, intent specification, and feedback loops that let Codex do reliable work.

---

## The setup

### An empty repository and a deliberate constraint

The first commit landed in an empty repository in late August 2025. The scaffold came from Codex CLI running GPT-5, guided by existing templates: repository structure, CI configuration, formatting rules, package manager setup, and the application framework. Even the AGENTS.md file directing agents how to work in the repository was itself written by Codex. There was deliberately no pre-existing human-written code for the system to anchor on; the repository was shaped by the agent from the start.

The constraint (zero manually-written code) was chosen on purpose. The team wanted weeks to produce what became on the order of a million lines, and reasoned the only way to learn what an agent-first team actually needs was to forbid the escape hatch of just writing the code themselves.

### What "shipped" means here

This was not a demo or a benchmark submission. The product had hundreds of internal users including daily power users, plus external alpha testers. It deployed, broke in production, and got fixed through the same agent-driven loop as feature work. That grounding matters for every later claim: investments in tooling and process were anchored by real users, not by output volume for its own sake.

## The numbers

| Measure | Value (per the post) |
|---|---|
| Duration | ~5 months (late Aug 2025 - Feb 2026) |
| Hand-written lines | 0 |
| Total code | ~1,000,000 lines (app, infra, tooling, docs, dev utilities) |
| Pull requests | ~1,500 opened and merged |
| Team size | 3 engineers growing to 7 |
| Throughput | ~3.5 PRs per engineer per day, rising with team size |
| Estimated speedup | ~1/10th of hand-written time |

The throughput figure is the load-bearing one: 3.5 PRs per engineer per day sustained over five months is what makes every downstream decision (minimal merge gates, agent-to-agent review, garbage collection) rational rather than reckless.

## Redefining the role of the engineer

With no hands-on coding, engineering work moved up a layer to systems, scaffolding, and leverage. Early progress was slower than expected, not because Codex was incapable but because the environment was underspecified: the agent lacked the tools, abstractions, and internal structure to make progress on high-level goals.

The team's job became enabling agents to do useful work, in practice working depth-first: decompose a large goal into building blocks (design, code, review, test), prompt the agent to construct those blocks, and use them to unlock harder tasks. When something failed, the fix was almost never "try harder." Because Codex was the only implementation path, engineers asked: "what capability is missing, and how do we make it both legible and enforceable for the agent?" Each answer became permanent infrastructure, which is why capability compounded over the five months.

### The interaction model

Humans interact with the system almost entirely through prompts: an engineer describes a task, runs the agent, and lets it open a pull request. Driving a PR to completion means instructing Codex to review its own changes locally, request additional specific agent reviews locally and in the cloud, respond to human or agent feedback, and iterate until all agent reviewers are satisfied (the post notes this is effectively a Ralph Wiggum loop). Codex uses standard development tools directly (gh, local scripts, repository-embedded skills) to gather context, so humans never copy-paste context into the CLI. Humans may review pull requests but are not required to, and review effort has steadily shifted to agent-to-agent.
