# Retrieval Practice: Welcome to Learn Harness Engineering | Learn Harness Engineering
### Q1. What is the Learn Harness Engineering course, and which four references does it synthesize?
> [!tip]- Answer
> Learn Harness Engineering is a course on engineering AI coding agents that makes tools like Codex and Claude Code reliable through environment design, state management, verification, and control systems. It synthesizes four core references: OpenAI on Codex in an agent-first world, two Anthropic guides on long-running agents, and Awesome Harness Engineering. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q2. What does the claim "a harness doesn't make the model smarter" mean?
> [!tip]- Answer
> It means the harness does not improve the model's raw intelligence; instead it establishes a closed-loop working system for the model to operate in. Reliability comes from engineering that surrounding system — environment, state, verification, and controls — rather than from a smarter model. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q3. What are the four learning paths in the Get started section, and what is each for?
> [!tip]- Answer
> The four paths are Lectures (theory on why strong models still fail), Projects (hands-on practice building a reliable agentic environment from scratch), Resource Library (copy-ready templates like AGENTS.md and feature_list.json), and Frontier Harness Design Breakdowns (how Pi, Claude Code, Codex, and DeepSeek design harnesses, mapped to the course framework). Together they split learning into theory, practice, reusable resources, and real-world case studies. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q4. What are the five key concepts listed under "What you will learn"?
> [!tip]- Answer
> The five concepts are constraining agent behavior with explicit rules and boundaries, maintaining context across long-running multi-session tasks, and stopping agents from declaring victory too early. They also include verifying work with full-pipeline tests and self-reflection, plus making runtime observable and debuggable. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q5. How does the course teach verification and observability for coding agents?
> [!tip]- Answer
> Verification is taught via full-pipeline tests combined with agent self-reflection, so work is checked end to end rather than trusted on the agent's word. Observability means making runtime visible and debuggable, which pairs with verification to catch premature victory claims and silent failures. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q6. What are the three recommended next steps, and what does each one give you?
> [!tip]- Answer
> The next steps are Lecture 01 (Why Capable Agents Still Fail) for the theory behind harness engineering, Project 01 (Baseline vs Minimal Harness) as the first hands-on task walkthrough, and the Templates pack (AGENTS.md, feature_list.json, claude-progress.md) for your own projects. They map directly to the learn-theory, build-practice, and reuse-templates loop of the course. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
### Q7. (evaluation) A team new to AI coding agents can only start with one next step — Lecture 01, Project 01, or the templates pack. What should they pick and why?
> [!tip]- Answer
> They should start with Lecture 01 if their agents fail unpredictably, because understanding why capable models fail (lost context, premature victory, missing verification) prevents wasted building on a shaky mental model. They should pick Project 01 or the templates only when they already accept that diagnosis and need a concrete baseline-to-harness comparison or copy-ready files to move fast. See [[wiki/01-welcome-to-learn-harness-engineering|Welcome to Learn Harness Engineering]].
