# Connections

- [[research/ModelOrHarnessFailureTaxonomy/summary|Model or Harness Failure Taxonomy]] — same-problem-different-method: builds a 41-category taxonomy attributing agent failures to model vs. harness vs. tool vs. task-spec vs. environment, the diagnostic counterpart to Prime Agent's engineering solution for the exact same "was it the model or the scaffolding?" question.
- [[research/TheHarnessEffect/summary|The Harness Effect]] — shares-technique/same-problem: empirically isolates the harness (not the model) as the dominant driver of agent cost and latency by swapping only the orchestration layer across six models and 22 tasks; a direct quantitative complement to Prime Agent's qualitative harness-vs-model-capability argument.
- [[research/VerificationHorizon/summary|Verification Horizon]] — related-problem: argues that as models improve, grading/verifying their long-horizon work becomes the harder bottleneck than generating it — relevant to Prime Agent's own verification and resource-accounting layer, and to the unresolved question of how to verify refinement edits before they become durable.
- [[research/MetaHarness/summary|MetaHarness]] — same-problem-different-method: also frames self-improvement as an outer loop that edits the harness (not model weights) using full trajectory access, but optimizes the harness's *code* via an agentic proposer, whereas Prime Agent's Continual Harness refines typed *state* (prompts, memories, skills) at the session level — two different granularities of the same "self-improving harness" idea.
- [[structured_papers/agent_harness/UltraLongHorizonAgenticScience/summary|Ultra-Long-Horizon Agentic Science]] — applies-in-practice: ML-Master 2.0 uses hierarchical memory caching to sustain 24-hour Kaggle ML runs, a similar long-horizon persistence problem to Prime Agent's multi-day nanoGPT and Factorio runs, but via a different memory architecture rather than a full recursive-subagent harness.
- [[research/ScalingLawsAgentHarnesses/summary|Scaling Laws for Agent Harnesses]] — shares-technique: proposes Effective Feedback Compute (EFC) as a harness-level scaling coordinate that outperforms raw token/tool-call counts, complementing Prime Agent's own standardized resource-accounting layer as another way to measure harness contribution independent of the model.
