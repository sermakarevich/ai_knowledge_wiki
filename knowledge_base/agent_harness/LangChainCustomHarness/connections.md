# Connections

- [[OsmaniHarness/summary|Agent Harness Engineering]] — Same core formula stated independently: Osmani's "agent = model + harness" and this article's identical equation both put the harness, not the model, as the main lever of agent quality; Osmani's ratchet/context-rot practitioner advice is the kind of concern this article's context-management and reliability middleware groups are built to address.
- [[AmuxHarnessGuide/summary|amux.io Agent Harness Guide]] — Near-identical framing from a different vendor: amux's guides-vs-sensors split and ratchet principle cover the same territory as this article's deterministic-logic lever and policy/steering middleware, giving a second independent source for the same "harness quality determines outcomes" thesis, useful for triangulating what's genuinely common wisdom vs. vendor-specific spin.
- [[NaturalLanguageHarnesses/index|Natural-Language Agent Harnesses]] — Contrasting design point on the same problem: this article keeps harness policy as composable code (middleware objects hooking into a loop), while NLAH externalizes the same kind of policy (state, validation, recovery, stopping) into an editable natural-language document run by a shared runtime — both agree the harness is the customization surface, but disagree on whether it should live in code or in a readable document.
- [[ScalingTheHarnessInAgenticAI/summary|Scaling the Harness in Agentic AI]] — Complementary research framing: that paper argues the "office infrastructure" around the model (memory, context management, tool use, verification) is now the bottleneck and proposes measuring/improving it systematically, which is the research-side counterpart to this article's practitioner capability checklist (context overflow, memory, action/delegation, reliability, policy, cost).
- [[CodeAsAgentHarness/summary|Code as Agent Harness]] — Related but distinct emphasis: that survey treats code itself as the harness substrate (using code to keep agents grounded and verifiable), whereas this article treats middleware objects around a model-calls-tools loop as the harness substrate — both fall under the same "the scaffolding matters more than the model" thesis but disagree on what the scaffolding should be made of.
