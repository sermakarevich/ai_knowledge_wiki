**Figure 1 – technical summary**

**What it shows.** Figure 1 is not a coordinate plot; it is a box‑and‑arrow *protocol schematic* ("cost‑first measurement protocol") that depicts how context‑compression conditions are fed through a bounded agent loop and how cost is decomposed. There are therefore no data axes; the only "trends" are qualitative annotations and a dashed cost‑reduction arrow. The horizontal layout has two parts separated by a dotted vertical line: a main **agent loop** on the left and an **oracle branch** on the right.

**Structure (left, main loop).** A top row of three context conditions — *Full* (1× baseline), *Sliding* (≈5×, drop early turns), and *Summary* (≈5×, fact‑preserving digest) — all funnel into a single box, a **fixed 24‑turn interaction horizon (bounded agent loop)**. (A marginal note states the compression ratio is a sweep parameter varied in §4.2.) Inside the loop, two modes are shown as interleaved boxes: **Retrieval** (re‑query of dropped state) and **Execute** (task work), joined by a two‑way "interleaved" arrow. These map respectively to two outputs: **Tool cost** (turns + tool calls) under Retrieval, and **Task completion** (tasks finished) under Execute. A red annotation under Tool cost states the central qualitative trend: *completion can stay flat while interaction cost rises*.

**Structure (right, oracle branch).** A green box, **compressed + oracle** (a queryable task graph D* or history‑dependent state R*), feeds a **dropped state (restored)** box. A dashed green arrow labeled *retrieval cost ↓* runs from this branch back into the main loop's retrieval path, indicating that restoring the dropped state reduces retrieval cost.

**Takeaway.** The figure formalizes the paper's cost‑first measurement: missing execution‑relevant state forces *retrieval* (re‑acquisition) in place of *execution*, so the loop jointly produces completion and a tool‑level interaction cost *C = C_R + C_E* (the agent's budgeted currency, not wall‑clock or money). Because completion and cost are decoupled (completion can be flat while cost climbs), a completion‑only projection is non‑identifiable — the oracle branch illustrates the manipulated recoverability variable (restoring state drops retrieval cost, with D* and R* expected to act differently). In short, the diagram is the conceptual backbone for the argument that completion alone cannot rank strategies by interaction efficiency.
