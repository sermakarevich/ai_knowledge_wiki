**What it shows.** Figure 1 is a two‑panel schematic (not a data plot) of the paper's experimental methodology, titled *Experimental pipelines*. There are no axes or curves; the "trends" are the staged flow of information. Panel **(a)** — *skill‑vs‑procedural‑memory pipeline* — traces a path from raw Docker‑container task execution (agent run + test results) to a pool of labeled **Success Trace / Error Trace** examples (e.g., a theme flicker persisting before hydration, mismatched skeleton/final card dimensions), then to a small **trace‑composition grid** (roughly a 5‑success/0‑fail down to 0‑success/5‑fail cross of N successes + N failures), and finally to a *controlled execution* step where `skill‑creator.md` turns those traces into one reusable `SKILL.md` (repeatable process, ordered steps, failure modes, verification) usable by an agent/workflow.

Panel **(b)** — *three‑experiment skill‑retrieval evaluation* — fixes a **controlled setup**: a task description plus a candidate pool of one ground‑truth skill and *k−1* real distractors (k on the order of 5–100), with distractors built as random / similar / dissimilar and the same pool reused across settings. From this pool three parallel protocols are run: **(A) embedding‑based** deterministic ranking (encode task + skills → cosine similarity via an embedding model → top‑ranked skill; reports Hit@1 / rank gap, *no* execution); **(B) agent‑pick** selection (visible name+description list → agent reasoning → a single structured tool‑call; reports Hit@1 / wrong‑skill / refusal, *no* Docker or verifier, isolating selection); and **(C) real execution** (full `SKILL.md` loaded in a Harbor/Docker environment, agent reads the skill then acts, 5 runs/setting through a verifier; reports task success rate plus the picked skill and trajectory).

**Takeaway.** The figure encodes a *matched, contrastive* design: the same prior experience is first distilled into a standardized skill (a) and then tested for retrieval under three protocols of increasing fidelity (b). By holding the candidate pool constant and stripping away execution in (A) and (B), the methodology isolates *where* in the pipeline (ranking vs. selection vs. full execution) gains or failures arise, rather than reporting only an end‑to‑end success rate. In short, it is the experimental scaffolding that lets the paper attribute skill utility to concrete mechanisms (procedural anchoring over factual injection) instead of treating skills as a black box.
