# Skill-Use Mechanisms: A Contrastive Trajectory Analysis

**In one sentence:** The authors go beyond aggregate success rates by building a human-validated, 3-category / 12-mode taxonomy of skill-use trajectories and comparing matched task triples across raw, workflow-memory, and skill arms to expose *which behaviors* change when prior experience is injected as a workflow versus as a distilled skill.

## Key points

- A contrastive trajectory-analysis pipeline normalizes the heterogeneous benchmark outputs into a shared manifest of **8,135 trial records** (task identity, execution arm, verifier outcome, injected artifact, and a trajectory transcript when available); **7,837** of those records contain agent transcripts.
- An open-coding pass over **240 sampled trajectories** yields **238 valid unique labels**, which are then merged into a **12-mode canonical taxonomy** organized into **3 top-level Skill-use Categories (SCs)**.
- Both LLM-assisted construction stages are validated by an independent human annotator: **714 trajectory–label checks** (238 labels × 3 supporting trajectories), all confirmed, and a second-stage mapping to the 12 canonical modes achieves **95.8% exact agreement** with the LLM and **Cohen's κ = 0.952** (Table 3).
- The unit of analysis is a **paired triple**: the same task and setting run under three arms (raw execution, workflow-memory injection, skill injection). The authors construct **528 triples** — SkillsBench (**144**), TerminalBench 2.0 (**186**), Terminal-Bench-Pro (**198**) — giving **1,584 arm-level mode assignments**.
- For each triple, an LLM judge assigns each arm a taxonomy mode, records **pairwise changes between arms**, and tags whether the injected artifact acts through **procedural anchoring, knowledge injection, failure warning, no meaningful use, or counterproductive guidance**.
- **SC1 (successful procedural anchoring)**: the agent succeeds autonomously, or prior experience provides useful guidance. Skill arms shift more trajectories into SC1 than workflow memory — **326/528** skill-vs-workflow SC1 assignments vs. **294/528**.
- **SC2 (execution- and verification-layer failures)**: skill arms show fewer of these than raw and workflow memory — **124/528** (skill) vs. **197/528** (raw) and **176/528** (workflow).
- **SC3 (invocation, applicability, and boundary failures)**: guidance is present but misused, overapplied, ignored, or constrained by external limits; skill arms *increase* these — **78/528** (skill) vs. **19/528** (raw).

## The contrastive analysis pipeline

Aggregate success rates tell us only *whether* a skill helps, not *what changes* when a skill is available. To make those changes observable, the authors build a contrastive trajectory-analysis pipeline over the controlled skill-versus-workflow experiments. The pipeline begins by taking heterogeneous benchmark outputs and normalizing them into a single shared manifest of **8,135 trial records**. Each record carries the task identity, the execution arm, the verifier outcome, the injected artifact, and — when it was captured — the trajectory transcript. Of the 8,135 records, **7,837 contain agent transcripts**, which is the subset available for the qualitative, trajectory-level analysis that follows.

On top of that manifest the authors run an **open-coding pass**: a coding sweep over **240 sampled trajectories** produces a set of raw, free-form failure and success descriptions. Of these, **238 valid unique labels** are retained, and the open-ended descriptions are then merged into a **12-mode canonical taxonomy**. This taxonomy is deliberately two-tiered: it contains three coarse **Skill-use Categories (SCs)** as the top-level labels, with each SC grouping a set of fine-grained modes (twelve in total, enumerated in the paper's Table 11). The contrastive logic is what ties the taxonomy to the experimental design. The main unit of analysis is a **paired triple**, and each triple compares the *same task and setting* under three different arms — raw execution, workflow-memory injection, and skill injection. The authors construct **528 such triples**, spanning three benchmarks: **SkillsBench (144)**, **TerminalBench 2.0 (186)**, and **Terminal-Bench-Pro (198)**. Those 528 triples yield **1,584 arm-level mode assignments**.

For every triple, an LLM judge assigns a taxonomy mode to each of the three arms, explicitly records the **pairwise changes between arms**, and identifies *how* the injected artifact acts — that is, whether it operates as **procedural anchoring, knowledge injection, a failure warning, no meaningful use, or counterproductive guidance**. Because the triples are matched on task and setting, this paired design lets the authors ask not merely whether a given arm succeeds, but *which specific behavior changes* when the same prior experience is represented as direct workflow memory versus as a distilled skill. The pairing is the core methodological move: it isolates the effect of the *form* of the prior experience from the effect of the particular task.

## The three Skill-use Categories

At the coarse level, each trajectory receives exactly one **Skill-use Category (SC)**, which serves as its top-level taxonomy label. The three SCs together group the twelve fine-grained modes, and were designed to decompose the paper's central question into the complementary cases "when skills help," "why they work," and "where they fail."

**SC1 — successful procedural anchoring.** SC1 captures trajectories in which the agent either succeeds autonomously or, when prior experience is present, that experience provides useful guidance. These are the "skill helped" cases. At the group level, skill arms push more trajectories into SC1 than workflow memory arms do: **326/528** skill-arm SC1 assignments versus **294/528** for workflow memory. This is the behavioral signature of the distilled skill — more clean, guidance-consistent successes than the raw workflow memory achieves on the same tasks.

**SC2 — execution- and verification-layer failures.** SC2 bundles the failures that arise at the level of actually running and checking the work: environment setup, output formatting, service management, shell execution, algorithmic implementation, and runtime validation. Here the skill again looks best: skill arms reduce SC2 failures relative to both raw and workflow-memory arms — **124/528** for skill versus **197/528** for raw and **176/528** for workflow memory. In other words, compared with merely injecting the verbatim prior workflow, the distilled skill both increases clean successes and drops execution-layer breakage.

**SC3 — invocation, applicability, and boundary failures.** SC3 is the counterweight. It captures trajectories where guidance is *present* but ends up misused, overapplied, ignored, or blocked by external limits such as timeouts and budgets. This is where the skill's advantage can reverse: skill arms *increase* SC3 failures relative to the raw baseline — **78/528** for skill versus only **19/528** for raw. The read is that distillation can concentrate failures into the meta-layer (how and when the skill is applied and bounded) even as it reduces the execution-layer (SC2) failures. Taken together, the three SCs decompose the central question directly: skills help (SC1), they tend to reduce execution-layer failure (SC2), and they do so at a partial cost of invocation/boundary misfires (SC3).

The taxonomy is treated as a robust instrument rather than a one-off LLM opinion. The authors validate both LLM-assisted construction stages with an independent human check. In the first stage, for each of the **238 valid raw labels** a human annotator inspected **three supporting trajectories** — **714 trajectory–label checks in total** — and confirmed that the raw label was grounded in the recorded agent behavior; all labels were confirmed. In the second stage, the same annotator independently mapped all 238 raw labels to the 12 canonical modes using only the taxonomy definitions. As summarized in Table 3, the human and LLM aggregation assignments agree at **95.8% exact agreement** with **Cohen's κ = 0.952**, providing direct evidence that the taxonomy is stable beyond the judgments of a single LLM.

## Figure: Taxonomy of Skill-Use Modes

![Taxonomy of skill-use categories and modes](images/02-fig2-taxonomy-page3.png)

Figure 2 presents the taxonomy as a three-panel stacked-bar chart that compares the *composition* of trajectory-level success/failure labels across the three experimental arms — **Raw**, **Workflow Memory**, and **Skill** — for each of six source-trajectory mixtures (5s0f down to 0s5f, varying the success/failure ratio while holding the total at 5). Each bar is roughly normalized to about 100 trajectories, so the panels differ in *composition* rather than in total count. The stack segments are colored by Skill-use Category: green segments for **SC1 guided success** (skill-, workflow-, and autonomous-guided variants), blue segments for **SC2 execution and verification** failures (logic, verify-only, format/schema, infrastructure, background-service, shell-corruption), and red/orange segments for **SC3 invocation and budget** issues (timeout/budget, misapplied guidance, capability/safety).

The per-arm trend matches the numbers in the prose. The **Raw** bars show roughly half success (green) with a thick blue execution/verification band and a thin red top — many execution-layer failures. **Workflow Memory** keeps a large blue band and a visibly thicker red top (more timeout/budget failures), reflecting retained verbose exploration and drift. **Skill** has the most prominent green (skill-guided success) base and a comparatively thinner blue execution-failure band, with moderate red — i.e., fewer execution-layer failures and more guided successes. The takeaway is that skills primarily reduce execution-layer (SC2) failures and shift outcomes toward guided success (SC1), whereas workflow memory preserves useful procedural evidence but at the cost of extra process noise and more timeout/budget (SC3) failures — so the label mix is arm-dependent, not just a function of the underlying success/failure mixture of the source trajectories. (Exact per-mode percentages are reported in the paper's Appendix Table 11.)
