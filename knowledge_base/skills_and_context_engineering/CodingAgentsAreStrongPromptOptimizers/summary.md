# Coding Agents are Strong Prompt Optimizers

**Paper:** [Coding Agents are Strong Prompt Optimizers (Singh et al., 2026)](https://arxiv.org/pdf/2609.26261)

## Human Readable TL;DR

Imagine trying to coach a soccer team by watching one player for five minutes after every game and shouting a new rule, versus sitting down once with the full season's stat sheets and game tapes to write a proper playbook. Today's prompt optimizers do the former: they tweak the instructions, run a few fresh games to check the score, and repeat, which is expensive and easily fooled by a lucky or unlucky batch. This paper does the latter: it hands a complete pile of past game recordings to an off-the-shelf coding assistant, which crunches the numbers with real code, spots the patterns that only show up at scale, and writes a short rulebook that the team simply reads before playing. That one-time, offline rewrite beats the fiddly trial-and-error loop on most tests while costing about as much as a cup of coffee.

## TL;DR

Coding-Agent Skill Distillation (CASD) replaces iterative search-based prompt optimization with a single offline pass in which an unmodified coding agent (Claude Sonnet 5 / Claude Code) analyzes a frozen corpus of agent rollouts and writes a skill markdown file that is used directly as the optimized system prompt, requiring no optimization loop, validation gate, environment interaction, or held-out validation set. The agent works explore-first and statistics-guided, writing and executing analysis code to compute corpus-wide reward rates, tool-use histograms, duplicate-call counts, and failure-mode breakdowns before drilling into the flagged episodes and distilling evidence-grounded behavioral rules. Under matched data access across ALFWorld, tau-2 retail and telecom, and SpreadsheetBench-Verified, CASD lifts the unoptimized baseline by 16.6 points on average versus 10.9 for GEPA and 5.3 for validation-gated SkillOpt, winning on three of four benchmarks at roughly $1.60 per prompt, about 22x cheaper than SkillOpt, and it still leads on two of four benchmarks even when baselines get extra validation data and unlimited environment access that CASD never uses.

## Problem & Motivation

Large language model agents are highly sensitive to their system prompts, so a growing literature treats the prompt as a learnable artifact: propose an edit, evaluate it with fresh environment rollouts, keep it only if a validation score improves, and repeat, with reflective variants such as GEPA strengthening proposals by having a language model reflect over sampled trajectories. The paper argues this search paradigm carries two structural costs that motivate a different design. First, every candidate revision must be validated through fresh interaction, keeping the environment, user simulator, and grader in the loop while cost grows with the number of edits. Second, each revision is informed by only a small minibatch of trajectories, so patterns that are visible only at corpus scale, such as a tool invoked 284 times with 123 exact duplicates or an entire task category failing 24 of 24 attempts, are essentially undiscoverable from any single reflection step, while small validation batches further invite gate overfitting where edits that happen to please a handful of episodes are kept.

CASD matters because it reframes the bottleneck as reflection scope rather than search budget. If the optimizer can run code over the entire rollout pool instead of reading a few episodes in context, counting becomes exact the way program-aided prompting is exact, corpus size enters through the interpreter rather than the context window, and the resulting prompt is grounded in measured frequencies and absences rather than minibatch anecdotes, all in one cheap offline step that works even where no simulator, grader, or validation split exists.

## Main Original Ideas

1. **Coding-Agent Skill Distillation (CASD) as a single offline pass** — The full recipe is to give an off-the-shelf, unmodified coding agent access to the frozen rollout corpus D and the initial prompt p0 under one short natural-language instruction asking it to analyze the trajectories and distill a skill markdown file capturing the behavioral rules that would make a future agent more accurate and more token- and step-efficient, and then to use that file directly as the optimized prompt p*. The agent sets its own methodology with no prescribed pipeline or metric, and the process terminates when it writes the skill, formalized as p* = CASD(D, p0) with no new trajectories collected and no environment touched.

2. **Corpus-scale statistical reflection via executable analysis code** — What replaces the iterative loop is a characteristic workflow observed across 24 runs and 816 tool calls: brief upfront exploration of corpus layout, then alternating statistics computation and targeted episode inspection (median 5 mode switches, up to 16), then terminal skill writing into a 5–8 KB file. Every run computes reward and length statistics, nearly all compute termination, failure-mode, and tool-use breakdowns, most break down by task category, and a third count duplicated invocations, so that quantitative findings such as 16 of 50 episodes fabricating an identity-lookup argument or get_details_by_id being duplicated 123 of 284 times direct the reading and end up cited as evidence in the final rules.

3. **A unified bias–variance view of prompt optimization** — All optimizers are cast as maximizing the same expected task reward J(p) through updates of the form pt+1 = Π[pt ⊕ ρ(pt, φt)], differing only in the feedback φt. Search feedback combines a sampled rollout batch with a Monte Carlo validation score whose variance shrinks only with more rollouts, while CASD feedback pairs deterministic corpus statistics Φ(D) with the representative episodes they flag, eliminating minibatch sampling variance once the corpus exists at the price of fixed-corpus bias whenever the frozen pool misses important behaviors. The consequence is complementary operating regimes: offline distillation wins on effectiveness and cost under limited budgets where variance reduction matters most, while iterative search with its lower asymptotic bias is expected to dominate once abundant interaction is available.

## Key Findings

Under the headline limited-data regime where every optimizer sees only the same static pool, CASD is best on ALFWorld (83.3% versus 74.0% for GEPA), retail (40.0% versus 39.2%), and telecom (39.2% versus 17.5%), and second on SpreadsheetBench-Verified (51.3% versus 60.7% for GEPA), for a mean gain of 16.6 points over baseline against 10.9 for GEPA and 5.3 for SkillOpt, with telecom providing the sharpest separation. The advantage survives generosity toward the baselines: when GEPA and SkillOpt additionally receive a separate held-out validation set plus unlimited environment access for candidate rollouts that CASD never uses, CASD still leads on two of four benchmarks, and a pass costs about $1.60 with no rollout bill since the corpus is a byproduct, totaling far below GEPA ($8.4) and roughly 22x below SkillOpt ($142.5) across the four benchmarks.

The paper explains the win through three scope effects supported by concrete cases. Rules become statistical rather than anecdotal, as with the telecom skill's top rule against fabricated lookup arguments seen in 32% of episodes, which no single minibatch reliably surfaces and GEPA never addresses. Efficiency rules emerge from cross-episode joins, such as the duplicate-call finding that is a one-liner in pandas but invisible to context-window reflection. And the absence of an acceptance gate avoids overfitting to small validation pools, which is blamed for GEPA's telecom collapse to 17.5 and SkillOpt's retail variance reaching SD 10.1, while CASD's skill-to-skill variance stays small. Figure 4 makes the absence argument vivid on a single telecom ticket requiring two independent fixes: the device fault is visible in any failed episode and all methods encode it, but the billing fault appears only as a corpus-level absence because make_payment is never invoked anywhere in the pool, so only CASD writes the billing rule and only CASD solves the episode. Finally, a reasoning ablation shows that much of test-time thinking is crystallizable policy: no-think plus the CASD skill exceeds think-mode accuracy outright on ALFWorld (83.3 versus 71.3) and retail (40.0 versus 35.0) and recovers 78% and 55% of the no-think-to-think gap on telecom and SSB while emitting zero reasoning tokens at 2.9–4.5x lower per-episode output, and distilling from failure-rich no-think rollouts lands within a few points of distilling from expensive think rollouts with no consistent winner.

## Suggestions & Future Directions

The paper's own framing suggests treating offline corpus-scale reflection as the default first step of prompt optimization and reserving iterative search for final gains when additional interaction is inexpensive, since the two occupy complementary regimes rather than optimizing different objectives. Open directions include testing sensitivity to distiller capability beyond the single studied pair of GPT-5.4-mini as target and Claude Sonnet 5 as optimizer, reconciling the variance accounting between skill-to-skill and seed variance, and handling very small or failure-free corpora that leave nothing to distill given that CASD inherits the corpus and cannot invent behaviors absent from logged rollouts. The residual no-think-to-think gaps on telecom and SSB point to a portion of thinking that is instance-specific deduction rather than reusable policy, which no static prompt recovers and which future work could target, alongside managing the deployment cost of verbose optimized prompts, noting for example that SkillOpt's telecom prompt induces substantially more test-time prompt tokens than GEPA's.
