# Connections

- [[DemystifyingAgentSkills/summary|Demystifying Agent Skills: Why They Work-Until They Don't]] (arXiv 2608.14036) — Same core topic (why Agent Skills help or hurt), with a complementary rather than contradictory finding: Jiang et al. attribute Skill gains mostly to procedural anchoring rather than knowledge injection, and separately show retrieval precision collapsing as the Skill pool grows. This paper's length-matched/content-misalignment split and its retry-lock-in mechanism give a concrete causal account for cases where that anchoring backfires — read together, the two papers cover "why Skills usually help a little" and "why and when they instead hurt."
- [[AgentSkillsCanBeHarmful/summary|Agent Skills Can Be Harmful: An Empirical Study of Skill-Induced Failures in LLM Agents]] (arXiv 2608.11888) — Directly corroborating: an independent contrastive-testing study on SkillsBench/SWE-Skills-Bench that confirms 307 concrete cases of Skill-induced functional failures and efficiency regressions, building failure taxonomies. This paper adds the missing piece that study doesn't isolate — a length-matched control separating pure prompt-length cost from genuine content harm — plus a WebDev-specific, chain-position-aware view.
- [[BeyondDomainsWebSkills/summary|Beyond Domains: Reusing Web Skills via Transferable Interaction Patterns]] (arXiv 2606.17645) — Same WebDev-agent setting but a different Skill paradigm (browsing/interaction-pattern skills for WebArena/Mind2Web, not coding-agent SKILL.md files) and an opposite framing: SkillMigrator treats skill reuse as a pure efficiency win (fewer LLM calls at matched accuracy), which this paper's findings complicate — reuse that helps action-count efficiency in a browsing agent does not imply reuse helps *correctness* in a coding agent, where this paper shows content and length can actively degrade Pass@2.
- [[skills_and_context_engineering/skills_and_context_engineering|Skills & Context Engineering (category index)]] — Home category for this paper; several entries there (e.g. SkillRetrievalAugmentation's finding that need-aware skill loading, not retrieval quality, is the bottleneck) share this paper's central thesis that a Skill's value depends on selective, contextual deployment rather than blanket injection.
